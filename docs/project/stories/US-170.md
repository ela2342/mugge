## US-170: Pi 4 config hardening parity

**As** the owner keeping the Pi 4 configuration as the US-164 baseline,
**I want** the Pi 4 `mugge` config to get the same network allowlist and configuration revision as the Pi 5,
**so that** the Pi 4 image is never weaker than the Pi 5 one if it is ever used again.

**Status:** draft (PO, 2026-10-24, from worker-1)
**Priority:** blocks any amps-on Pi 4 use (security)
**Depends on:** US-163
**Related:** US-163 (AC1a pi4-noop stays as written: this story deliberately changes the Pi 4 drvPath), US-000a, F-037

### Acceptance criteria

- [ ] AC1: The Pi 4 config gets the same 8080/5900 ip saddr allowlist as the Pi 5: fails closed when empty, IPv6 covered.
- [ ] AC2: `system.configurationRevision` is set, and `nixos-version --configuration-revision` reports it.
- [ ] AC3: The Pi 4 toplevel builds; the nft ruleset is verified with eval/build checks (no Pi 4 hardware is available).
- [ ] AC4: Any drvPath pin added for US-163 AC1a is removed here at the latest.
