- **US-174b Offline filter generation, closed loop against the room
  simulator.** The first slice (below). No Pi, mic, amps or
  PipeWire.
- **US-174b2 = US-067** (PipeWire headless simulator): run the
  generated WAVs through the real filter-chain convolver in an
  isolated PipeWire, to catch loader and format issues before any
  Pi. Optional. After 174b and after worker-2's lane, because it
  touches local-demo and the PipeWire config. US-067 keeps its ID as a
  linked child story (PO).
- **US-174b-sim Position-dependent room simulator** (architect,
  2026-10-25): after slice 1, a position-dependent modal sum in
  `mock/room_simulator.py`. It unlocks the off-position criterion
  (AC4) and spatial averaging.
- **US-174c Measurement on the Pi 5** (UMIK-1 + signal-gen through the
  D-063 gate). Plays sweeps through the amps, so it is gated by the
  FULL amps-on list, US-173's H and F-341 AC3 (no signal-gen
  measurement session before it), D-070, and the AE's measurement
  safety rules (S-010, attenuation budget). Prerequisite: the UMIK-1
  calibration file for serial 7161942, re-fetched from miniDSP (the
  copy at `/home/ela/7161942.txt` was on the unreachable Pi 4) and
  kept in the repo or the deploy. AE: magnitude-only, sensitivity
  -1.378 dB; the owner may have a copy, otherwise a team member
  downloads it from miniDSP by serial (no owner needed); verify the
  serial in the file header. H (the amp level cap) also applies, so
  a sweep can't exceed 7 W per sat even with a wrong gain.
- **US-174d Deploy and verification** (load the filters, re-measure in
  the real room, AE acceptance). After 174c. The re-measurement is
  the real gate: the corrected MEASURED response at the listening
  position must have a maximum positive deviation <=
  closed_loop.MEASURED_MAX_POSITIVE_DEVIATION_DB (initially 3.0 dB,
  the same value as the simulated MAX_POSITIVE_DEVIATION_DB), with
  the same 1/6-octave smoothing and bands as AC3 (sub 30-200 Hz and
  sats 250-500 Hz per channel, system 30-500 Hz summed). A
  re-measurement whose SNR fails the measurement-time SNR check
  (backlog item; threshold AE-set there) is INVALID (repeat it),
  never a pass. A failure blocks the deploy: the new filters
  are not loaded, the previously deployed filters stay, and the run
  reports per channel. The tolerance is the AE's (2026-10-25); any
  change to the measured constant needs AE review, and it never
  changes in the same PR as a correction-algorithm change. The two
  constants are separate so that real data can't silently loosen
  the simulated gate, or the reverse (AE).
- **US-174e One-button venue workflow** (design principle 6). After
  worker-2's web-UI lane.

### US-174b: first slice (architect; thresholds AE)

The owner's real room dimensions replace the generic home-lab

Precondition (AE, 2026-10-25): the LR4 crossover fix F-374 lands
before AC3-AC5 are judged. Otherwise the correction "fixes" the
+5.4 dB crossover bump and hides the defect. F-374 is its own PR
(worker-5, branch `fix/F-374-lr-crossover` off `b0666c02`), merged

Slice 1 also includes (architect, 2026-10-25): a pure pipeline
function that `runner.py` delegates to; the level-normalization fix
in `correction.py` (worker-4 found that it has no level reference:
the cut depth follows the measurement level 1:1, so a +12 dB mode
gets about a 29 dB cut); the speaker response (speaker_sim) in
simulate_measurement. After F-374 lands, `runner.py:200` switches
off the old crossover alignment (this lane).

- [ ] AC1: One CLI run (`runner.py --mock`) writes the WAV set the
  venue profile and `deploy.py` expect: combined_left_hp,
  combined_right_hp, combined_sub1_lp, plus dirac for the spare, HP
  and IEM channels. Each is 16,384 taps, 48 kHz, float32, with the
  names in `export.CHANNEL_FILENAMES`.
- [ ] AC2: The verify gates fail loudly (values AE, 2026-10-25):
  - D-009 absolute: combined FIR |H| <= -0.5 dB at every frequency
    (cut-only, F-299 bound).
  - Slice 1 is cut-only, with NO relative dip-fill (AE refinement,
    2026-10-25; was: dip-fill sub <= +6 dB from 30-200 Hz, sats
    <= +3 dB). The per-bin cut is at most the measured excess over
    the target and at most 18 dB. This cap is required: if the
    frozen correction API blocks the kwarg, it goes to the AE and
    the architect; it is not silently dropped (AE).
  - Level reference: the per-channel median, 1/6-octave smoothed,
    over 400 Hz-4 kHz for the sats and 30-150 Hz for the sub (AE).
  - Level invariance: the room IR scaled x0.1, x1 and x10 gives the
    same filter within 0.1 dB (AE).
  - Cut accuracy: within +/-2 dB of each injected mode's excess (AE).
  - Venue closed-loop residual gate (simulated scenarios):
    closed_loop.max_positive_deviation_db of the 1/6-oct smoothed
    corrected response vs target <= 3.0 dB (AE value). Architect,
    AE agrees, PO condition met (2026-10-25); was: "the verify
    tolerance default goes from 8 dB to 3 dB".
    - The limit is the named constant MAX_POSITIVE_DEVIATION_DB in
      closed_loop.py, checked through
      closed_loop.passes_residual_gate (built on
      closed_loop.max_positive_deviation_db). 174d revisits only
      its own MEASURED_MAX_POSITIVE_DEVIATION_DB on real data,
      never this constant (AE). Enforced by tests, not a runtime
      gate; no shipped code enforces it (QE T5). The closed_loop.py
      comment on the constant is the AE's exact text ("...this
      value is not changed by 174d. Changing or loosening it needs
      AE review.").
    - verify_target_deviation is a filter-only sanity check (a
      filter WAV against its own passband average); its default is
      unchanged at 8.0 dB (QE T5).
    - The tests run the same chain as the gate: 1/6-octave
      smoothing, then max_positive_deviation_db (QE T1).
    - Teeth test: a deterministic one-line degradation of the
      correction gives a residual in (3, 8] dB and fails
      passes_residual_gate (QE T1).
      The window bounds come from MAX_POSITIVE_DEVIATION_DB and
      verify_target_deviation's default, not literals (AE).
    - Three asserts, each with its band: subs 30-200 Hz, sats
      250-500 Hz, system 30-500 Hz; values reported to 2 decimals
      (QE T2, T4).
    - Gate API (Architect APPROVED, fits option (A); AE): two
      layers in closed_loop. deviation_within_limit(dev_db, *,
      limit=MAX_POSITIVE_DEVIATION_DB) is the scalar predicate;
      passes_residual_gate(response_db, target_db, *,
      limit=MAX_POSITIVE_DEVIATION_DB) returns False on any
      non-finite input, checked before smoothing. limit is
      keyword-only and for tests only. The venue and teeth asserts
      use passes_residual_gate; no second `<=` anywhere.
      max_positive_deviation_db raises ValueError on NaN/+inf/-inf
      input; it never returns NaN. The gates never raise: a shape
      mismatch, an empty input, any non-finite value, or a
      non-finite or negative limit all return False (AE, Architect
      joint line). Tests: the gates return False on NaN/+inf/-inf
      with no exception; the metric raises on NaN/+inf/-inf; the
      venue and teeth deviations are asserted finite (np.isfinite)
      before they are gated.
    - Boundary (AE): +3.00 dB passes, +3.01 dB fails, NaN/+inf/-inf
      and a NaN limit fail — via closed_loop.deviation_within_limit
      / passes_residual_gate (QE, Architect).
    - Mutations (QE T3): (a) the constant -> 8 must go red
      (required); (b) the constant -> 3.2 goes red, or the test
      states its margin (optional); (c) np.max -> np.mean in the
      deviation must go red (required); (d) tests import the
      constant only: a grep shows zero copies of the value in
      tests/.
    - Test counts are reported against 1268 / 76 (QE T6).
  - Below-target regions stay unchanged within 0.5 dB (cut-only; see
    AC3) (AE).
  - Nulls narrower than 1/3 octave or deeper than 10 dB are not
    corrected.
  - Minimum phase: the energy of (h - minphase(|H|)) is <= -40 dB
    relative to the energy of h. NOT "energy before the main peak":
    a correct min-phase lowpass fails that test (AE).
  - Causality and wrap-around: the energy in the last 5% of taps is
    <= -60 dB.
  - Format.
- [ ] AC3: Closed loop per scenario: target flat (the profile's
  target_curve) on the SUMMED sat+sub response at the listening
  position, 1/6-octave smoothed. 30-500 Hz: one-sided residual
  (AE refinement, 2026-10-25; was: X = +/-3 dB): positive deviation
  <= +3 dB; below the target the response stays unchanged within
  0.5 dB (cut-only). Bands (AE): per channel, sub 30-200 Hz and sats
  250-500 Hz (above the CHN-50P box knee, with speaker_sim in slice
  1); the system band is the summed 30-500 Hz. Metric: the maximum
  positive deviation, 1/6 octave, <= +3 dB. 500 Hz-16 kHz: +/-4 dB
  at 1/3 octave, only if the simulator models that band; otherwise
  not checked (AE).
- [ ] AC4: Off-position robustness: a filter made at position A,
  evaluated at simulated positions B and C (same smoothing and
  band), has a corrected RMS deviation <= uncorrected + 1 dB (Y),
  and no 1/3-octave band more than 3 dB worse than uncorrected (AE).
  Guards against over-correction. DEFERRED, not waived (AE,
  2026-10-25): the simulator applies the same modes at every
  position, so this AC (and spatial averaging) is tested in
  US-174b-sim, not slice 1. Positions (AE): B = +0.5 m lateral,
  C = +1.0 m depth; Y unchanged.
- [ ] AC5: Transient fidelity (AE; "1-2 ms at 200 Hz" is not
  achievable, ideal LR4 at 200 Hz has ~2.3 ms below 200 Hz; the
  architect accepts the AE's 3.5 ms budget as binding):
  - summed group delay <= 3.5 ms from 50-300 Hz and <= 1 ms above
    500 Hz, excluding +/-1/6 octave around each corrected room mode;
  - sat-sub phase difference at 200 Hz at the listening position
    <= 30 degrees (needs the simulator distances and delay_ms);
  - at corrected modes, modal decay is not longer than uncorrected.
- [ ] AC6: Time alignment: the estimated sub delay is within 1
  sample of the ground truth, the geometric direct path; this is
  stricter than +/-0.2 ms, and worker-4 tests both (AE, 2026-10-25).
- [ ] AC6a: Noise robustness (AE, 2026-10-25): the simulated
  measurement adds pink noise with a fixed seed. At -60 dB re the
  recording peak it gates: no extra cuts below 30 Hz compared with
  the noise-free run (+/-1 dB). At -40 dB it is report-only.
- [ ] AC7: Channel identity (US-098 P1): no cross-contamination
  between channels.
- [ ] AC8: The tests run in the existing `test-room-correction` check
  and `nix run .#test-room-sim-e2e`, with no `flake.nix` change. A
  missing import FAILS, not skips (F-362 lesson).
