## US-159: GraphManager Gate Module — Single Owner of All Gain Writes

**As** the engineer running a gig with the amps on,
**I want** one GraphManager gate module that owns every gain (Mult) write, ramps every increase, and refuses unsafe operations,
**so that** no venue switch, unlatch, restart, UI action or stray client can put an unramped, unfiltered or over-ceiling signal into the speakers.

**Status:** draft. Design agreed by architect, audio-engineer and UX (2026-10-24). PO reviewed 2026-10-24 (changes applied). Owner to select (worker spawning, O-8).

### Gate module (GraphManager)

Sole owner of all Mult writes. Every other write site is removed
(`main.rs` 579/677/752/804/829/1042 and `registry.rs:504`), and the
web UI ones go through GM. The only non-GM writers are the three web-ui
callers of `pw_helpers.set_mult` (architect, verified): `config_routes.py:203`
(F-344), `audio_mute.py:87/124` (F-320-F) and `thermal_limiter.py:437`
(F-345). See D1-D3 and L1-L4 below.

- [ ] G1. States: Closed / Opening{target, generation} / Open. Decreases are applied immediately, within the <21 ms watchdog budget.
- [ ] G2. One slew limiter governs every increase (open, set_gain while Open, any future trim). Per tick: `applied = min(target, max(target*10^(-60/20), applied*10^(R*dt/20)))`, R = 30 dB/s (full open ~2 s), dt is measured wall-clock time, cap +3 dB per tick, tick interval = max(1 quantum period, 10 ms). Same relative dB curve on every channel; channels with target 0 stay at 0. Generation check on every tick. *(The 30 dB/s curve amends D-063's 3 s cosine; owner decision O-27. AE's minimum: rate-limited on wall-clock time, per-tick cap, generation check, full open >= 2 s.)*
- [ ] G3. Target validation before any write: finite, 0 <= Mult <= 1.0, and <= the per-speaker ceiling (G9). Any failing channel rejects the whole operation; no partial writes.
- [ ] G4. `open()` refuses, with a reason string, unless the graph is healthy: convolver present, all 8 gain params present, link audit clean (no foreign USBStreamer links), watchdog not latched.
- [ ] G5. At startup GM actively writes 0.0 to all 8 channels and enters Closed; it never trusts the conf or previous state. If the convolver is not present yet, it writes on node appearance, before any USBStreamer link is created. *(Note: this story is selectable with G5 = zero on start, the AE and architect recommendation (PO). If the owner later chooses "adopt" under O-12, that is a new story, with G3 validation and the G4 health check, falling back to zero; the gate never reads Closed while any Mult is above 0.)*
- [ ] G5a. GM creates no USBStreamer links until it has read back Mult == 0.0 on all 8 channels from the node.
- [ ] G6. `watchdog_unlatch` / CLEAR WATCHDOG clears the latch only and never restores gain. It refuses while the trip cause persists.
- [ ] G7. `set_venue` returns an error unless the gate is Closed, and mutates nothing on error. Venue persistence happens only after validation succeeds.
- [ ] G8. `set_venue` rejects a venue whose coefficients differ from those loaded, compared by content hash, not filename. GM hashes the conf-referenced files when the convolver node appears; any later on-disk change counts as a mismatch.
- [ ] G8a. On a coefficient hash mismatch, GM refuses `open()` and `set_venue` until the convolver is reloaded with the gate Closed. An on-disk change while Open shows a visible warning only (no forced close). Policy: coefficient files are written only via deploy, followed by that reload. The load-time record (here and in G8b (a)) is taken at a GM-confirmed reload, not at node appearance (G8c R-f, architect).
- [ ] G8b. Coefficient content validation, runtime (final text agreed by AE and architect, 2026-10-24). Runs alongside the G8 hash. Scope is per channel n, driven by the speaker identity S(n) bound to that channel in the active speaker profile, not by venue name. If no speaker identity resolves for a channel, refuse (fail closed, not a skip).
  - (i) Every channel: max_f |H_n(f)| <= S(n).max_boost_db + 0.1 dB, otherwise refuse. The +0.1 dB is a numerical tolerance for the runtime check only (Python/Rust agreement <= 0.05 dB per T9 fixtures). It is deliberately not the D-009 generator target (cut-only with -0.5 dB margin), and it must not be loosened without AE review, because the G9 ceilings assume |H| <= 0 dB with < 1 dB thermal margin for the CHN-50P. *("T9 fixtures" in the quoted sentence refers to this story's G8b test, numbered T11 here.)*
  - (ii) Any channel whose speaker declares `mandatory_hpf_hz` = F: |H| <= -3 dB at F and <= -24 dB over [DC, F/2], otherwise refuse with "no driver protection on ch N". The same check applies to the sub 42 Hz subsonic floor where defined. Ch 5-8 (HP/IEM) declare no `mandatory_hpf_hz`, so a Dirac passes there; a Dirac passes (i) at 0 dB.
  - (a) Off the PipeWire main loop (architect: a WAV read or FFT stall there delays registry/link events and the <21 ms watchdog response). Validation runs on a worker thread when the convolver node appears and at `set_venue`, cached per content hash. `open()` only re-hashes (G8a) and reads the cache; a cache miss refuses with "validation pending" and starts the computation, never blocks. Validate what PW actually loaded (AE): record content hash, mtime and size at a GM-confirmed reload (G8a, G8c R-f); if the on-disk hash no longer matches in `open()`, refuse with "coefficients changed on disk since load; reload required". One shared load-time record serves G8, G8a and G8b.
  - (b) (i) uses >= 4x zero-padding (matches the F-262 condition 2 shared |H| helper). (ii) uses a direct DTFT on a grid of <= 0.5 Hz spacing over [DC, F/2] plus the exact point F; no bin snapping (F-299).
  - (c) The WAV check compares rate and channel count against the conf; the expected tap count comes from the conf/profile, not a hard-coded 16384 (F-331).
  - (d) One rule, two languages: the T11 fixture WAVs also run through the Python room-correction verify path, agreeing within 0.05 dB.
  - First boot (AE ruling, architect agrees): no exemption for passthrough by venue name. G8b enforces D-031 point 3 and D-055 point 3, which `foh-passthrough.yml` already violates (F-271; safety.md §10 Rule 2). Until F-271 ships HPF-only protection WAVs for ch 1-4, first-boot `open()` is refused with "no driver protection on ch 1-4 (F-271)". Because the gate is all-or-nothing (G3), that also silences ch 5-8. Owner questions: O-30.

It is cleared by one confirmed reload while Closed (G8b on the files, trigger all 8, all counters +1, files unchanged); this costs one main-loop stall per start. After a PW restart a counter at 0 is a new baseline, never a mismatch. This replaces "G8a hash at node appearance" and removes the startup race of files written while PW starts. Same instance: GM records the convolver's `object.serial` (monotonic, never reused, unlike node IDs) with the baseline counters; a different serial at read-back means the node was recreated -> ContentUnknown, never confirmed.

RF1: any non-zero Mult while ReloadFailed escalates to CloseFailed (A1). RF1 also holds with D3 detection active (architect). RF3: a partial reload (some counters moved, others not) is ReloadFailed and the UI shows "N of 8 reloaded". RF4: reload while Open stays refused unless the owner rules otherwise (O-33).

  - R-h, re-arm value (architect, with AD): GM reads each convolver's current Reload value from PW just before triggering and writes current+1; never a value held only in memory (stale after a GM or PW restart or an external write, giving the F-346 false success). (a) Read and write per node under the same `object.serial`; a serial change between them fails that channel (ReloadFailed, ContentUnknown). (b) Confirmation is still the read-only ReloadCount going +1 on all 8; the Reload input proves nothing. (c) A failed Reload read means no write and ReloadFailed for that channel.
  - Boot (AE): with R-f the confirmed reload is boot-critical; the UI shows a distinct "filter content unverified: reload required" or "reload failed, N of 8" state. G8b validates the files before the trigger, and the files are frozen (re-checked unchanged) until the trigger.
  - R-g1, close preempts (architect, with AD): open_gate, reload and set_mode serialize through one mutation lock (refuse if held, never queue; R-g3, AD). close_gate (including watchdog, integrity and standby closes) bypasses it: bump the gate epoch, write Mult 0 to every discovered gain at once, then read back. Close latency is bounded by the PW main loop, so a patched reload's FFT build can delay a close (and D3 re-zeroing) by up to the FFT time; the patch must build the FFT off the main loop (F-346 AC14). The epoch also guards the final transition (AD, architect): the ramp sets gate_open=true and emits GateOpened (`main.rs:808` on) only if the epoch is unchanged since it started; otherwise the open returns aborted and the state stays Closed (else the indicator reads OPEN with every gain at 0.0, the inverse of F-320).
  - R-g3, refuse, never queue: open_gate during a reload or set_mode is refused; set_mode during a reload is refused ("reload in progress"); reload during set_mode is refused ("mode change in progress"). The operator retries; nothing completes later on its own. A reload ends confirmed, ReloadFailed or timed out (= ReloadFailed, "N of 8").

  - R-i, automatic content verification (architect; AE accepts with N1/N2, architect agrees): every entry into ContentUnknown (GM start, PW restart, convolver node reappearance, `object.serial` change) starts exactly one GM-initiated reload attempt, only when all preconditions hold: gate confirmed Closed (G11 read-back, no watchdog latch, not Closing, not CloseFailed, not ReloadFailed; AE N2), convolver present and the expected set matches (R-g4), G8b passed on the current files, no set_mode in progress (R-g3). A pending precondition (validation running, node incomplete) is awaited, then the attempt runs once, never blocking the main loop (G8b (a)). GM bounds the whole VERIFYING phase (G8b plus reload) with a timeout; on expiry it becomes ReloadFailed ("verification timed out") or a G8b refusal, never an indefinite pending state, and GM exposes the phase ("validating" / "reloading k of 8"). Confirmed: content known, gate stays Closed. Failure: ReloadFailed "k of 8" with the reason. No automatic retry loop (each reload stalls the main loop until F-346 AC14) and none without AE review; the operator retries via RETRY FILTER RELOAD (U8), the only operator-triggered reload besides the deploy path (R-a). The reload never opens the gate (G4). Any close, watchdog or integrity event during the reload preempts it (R-g1). No new venue-setup step in the normal path (DOC3).
  - R-i N1, non-finite coefficients (AE; architect mappings): Mult 0 does not mask non-finite output (0 x NaN = NaN; architect: steady Closed with Mult and Add exactly 0 memsets the output, but a latched NaN comes out at open, F-349). (a) G8b rejects any non-finite sample with an f32 bit-pattern check (F-349 AC5; not isfinite) over every tap of every channel, before the |H| analysis, shared by the Python and Rust paths (G8b (d)). (b) The swap happens only under the data-loop lock, so the RT thread sees the old or the new convolver, never a torn one; the unlocked fallback is removed (F-346 AC10), a precondition for every reload path, R-i included. (c) The swap resets convolver state: the new instance starts with zeroed overlap and tail, and the old one is freed after the swap, off the RT thread (F-346 AC15). The broader non-finite input gap is F-349.

### Sole Mult writer (architect D1-D3, 2026-10-24; with G11 in the same increment)
