## US-159: GraphManager Gate Module — Single Owner of All Gain Writes

**As** the engineer running a gig with the amps on,
**I want** one GraphManager gate module that owns every gain (Mult) write, ramps every increase, and refuses unsafe operations,
**so that** no venue switch, unlatch, restart, UI action or stray client can put an unramped, unfiltered or over-ceiling signal into the speakers.

### Gate module (GraphManager)

Sole owner of all Mult writes. Every other write site is removed
(`main.rs` 579/677/752/804/829/1042 and `registry.rs:504`).

- [ ] G1. States: Closed / Opening{target, generation} / Open. Decreases are applied immediately, within the <21 ms watchdog budget.
- [ ] G2. One slew limiter governs every increase (open, set_gain while Open, any future trim). Per tick: `applied = min(target, max(target*10^(-60/20), applied*10^(R*dt/20)))`, R = 30 dB/s (full open ~2 s), dt is measured wall-clock time, cap +3 dB per tick, tick interval = max(1 quantum period, 10 ms). Same relative dB curve on every channel; channels with target 0 stay at 0. Generation check on every tick. *(The 30 dB/s curve amends D-063's 3 s cosine; owner decision O-27. AE's minimum: rate-limited on wall-clock time, per-tick cap, generation check, full open >= 2 s.)*
- [ ] G3. Target validation before any write: finite, 0 <= Mult <= 1.0, and <= the per-speaker ceiling (G9). Any failing channel rejects the whole operation; no partial writes.
- [ ] G4. `open()` refuses, with a reason string, unless the graph is healthy: convolver present, all 8 gain params present, link audit clean (no foreign USBStreamer links), watchdog not latched.
- [ ] G5. At startup GM actively writes 0.0 to all 8 channels and enters Closed; it never trusts the conf or previous state. If the convolver is not present yet, it writes on node appearance, before any USBStreamer link is created. *(Note: this story is selectable with G5 = zero on start, the AE and architect recommendation (PO). If the owner later chooses "adopt" under O-12, that is a new story, with G3 validation and the G4 health check, falling back to zero; the gate never reads Closed while any Mult is above 0.)*
- [ ] G5a. GM creates no USBStreamer links until it has read back Mult == 0.0 on all 8 channels from the node.
- [ ] G6. `watchdog_unlatch` / CLEAR WATCHDOG clears the latch only and never restores gain. It refuses while the trip cause persists.
- [ ] G7. `set_venue` returns an error unless the gate is Closed, and mutates nothing on error. Venue persistence happens only after validation succeeds.
- [ ] G8. `set_venue` rejects a venue whose coefficients differ from those loaded, compared by content hash, not filename. GM hashes the conf-referenced files when the convolver node appears; any later on-disk change counts as a mismatch.
- [ ] G8a. On a coefficient hash mismatch, GM refuses `open()` and `set_venue` until the convolver is reloaded with the gate Closed. An on-disk change while Open shows a visible warning only (no forced close). Policy: coefficient files are written only via deploy, followed by that reload.
- [ ] G8b. Coefficient content validation, runtime (final text agreed by AE and architect, 2026-10-24). Runs alongside the G8 hash. Scope is per channel n, driven by the speaker identity S(n) bound to that channel in the active speaker profile, not by venue name. If no speaker identity resolves for a channel, refuse (fail closed, not a skip).
  - (i) Every channel: max_f |H_n(f)| <= S(n).max_boost_db + 0.1 dB, otherwise refuse. The +0.1 dB is a numerical tolerance for the runtime check only (Python/Rust agreement <= 0.05 dB per T9 fixtures). It is deliberately not the D-009 generator target (cut-only with -0.5 dB margin), and it must not be loosened without AE review, because the G9 ceilings assume |H| <= 0 dB with < 1 dB thermal margin for the CHN-50P. *("T9 fixtures" in the quoted sentence refers to this story's G8b test, numbered T11 here.)*
  - (ii) Any channel whose speaker declares `mandatory_hpf_hz` = F: |H| <= -3 dB at F and <= -24 dB over [DC, F/2], otherwise refuse with "no driver protection on ch N". The same check applies to the sub 42 Hz subsonic floor where defined. Ch 5-8 (HP/IEM) declare no `mandatory_hpf_hz`, so a Dirac passes there; a Dirac passes (i) at 0 dB.
  - (a) Off the PipeWire main loop (architect: a WAV read or FFT stall there delays registry/link events and the <21 ms watchdog response). Validation runs on a worker thread when the convolver node appears and at `set_venue`, cached per content hash. `open()` only re-hashes (G8a) and reads the cache; a cache miss refuses with "validation pending" and starts the computation, never blocks. Validate what PW actually loaded (AE): record content hash, mtime and size when the convolver node appears; if the on-disk hash no longer matches in `open()`, refuse with "coefficients changed on disk since load; reload required". One shared load-time record serves G8, G8a and G8b.
  - (b) (i) uses >= 4x zero-padding (matches the F-262 condition 2 shared |H| helper). (ii) uses a direct DTFT on a grid of <= 0.5 Hz spacing over [DC, F/2] plus the exact point F; no bin snapping (F-299).
  - (c) The WAV check compares rate and channel count against the conf; the expected tap count comes from the conf/profile, not a hard-coded 16384 (F-331).
  - (d) One rule, two languages: the T11 fixture WAVs also run through the Python room-correction verify path, agreeing within 0.05 dB.
  - First boot (AE ruling, architect agrees): no exemption for passthrough by venue name. G8b enforces D-031 point 3 and D-055 point 3, which `foh-passthrough.yml` already violates (F-271; safety.md §10 Rule 2). Until F-271 ships HPF-only protection WAVs for ch 1-4, first-boot `open()` is refused with "no driver protection on ch 1-4 (F-271)". Because the gate is all-or-nothing (G3), that also silences ch 5-8. Owner questions: O-30.
  - Tested by T11. Part of the AE veto-lift conditions (core story if split, O-29). Related: F-271, US-113, US-124.
- [ ] G9. Per-speaker static ceilings live in the speaker profile (dB re amp full scale, converted to Mult). Until the chain is calibrated, assume Mult 1.0 = 450 W. CHN-50P: <= 0.112 (-19 dB). UMII18-22 (120 L): 1.0. Applied to every Mult write; `set_venue` rejects any profile above its ceiling. Chain-calibration measurement: US-161 (validates A35). Dynamic limiter: US-162, after a BM-2 CPU check. Assumption: the ceilings are valid only if FIR peak gain is <= 0 dB (D-029 max_boost 0); G8b enforces this (AE). Summed inputs (AE, after an AD caveat): for a channel fed by N correlated summed inputs, the ceiling applies to effective output, Mult_max = ceiling / N (-6 dB for the L+R subs). Output is bounded at Mult 1.0 regardless (USBStreamer clips at 0 dBFS). Today's rigs are unaffected (CHN-50P is mains-only), but G9 implements the rule generally.
- [ ] G10. D-063's `audio_enabled` in `active.yml` (F-320 G): implemented as specified, or D-063 amended to match the in-memory design (architect).
- [ ] G11. Confirmed close (architect, with AE A1-A4; fixes F-339). Every close path (RPC, watchdog, `set_venue` pre-close, MUTE): (a) bump the generation and enter Closing{deadline}; (b) immediately write 0.0 to all 8 Mults; (c) read back from PipeWire with a real param query, never GM's cache: exactly 8 `gain_*:Mult` == 0.0 within max(100 ms, 4 quanta), and report the measured value; (d) confirmed -> Closed/Ok; otherwise -> CloseFailed with an RPC error and reason, an error log and a GateCloseFailed event, and GM keeps retrying the zero write. CloseFailed counts as Closed for every refusal; (e) GetGate and /ws/system expose Closing and CloseFailed distinctly.
  - A1. CloseFailed destroys ALL links into the USBStreamer playback node (every port) and blocks reconciler-created links. Destruction is confirmed via link-removed events; if a link survives, GM stays in CloseFailed and escalates the error.
  - A3. The only exit from CloseFailed: convolver present, confirmed read-back, then link recreation (as G5a), into Closed, never Open. A re-appearing convolver gets an active zero write plus read-back.
  - A4. CloseFailed is a distinct state; `open()` refuses it (G4). UX reconciles the wording (U6).

### WirePlumber default-sink bypass (F-318) — both required

- [ ] B1. Prevention: no PipeWire client can select or auto-link to USBStreamer playback as a default sink. Verified by T6. *(Task: investigate making it non-selectable altogether, not a regular Audio/Sink or via PW permissions, which is stronger than priority 0.)*
- [ ] B2. Enforcement: GM destroys any non-GM link to the USBStreamer playback node, event-driven on registry link-added (not polling), and logs it, with the gate open or closed. Extend and verify the existing event-driven `link_audit.rs` rather than adding a second auditor (architect). Requirements (AE):
  - Bound: from the link-creation registry event to `destroy_global` complete, <= 1 graph cycle (21.3 ms at quantum 1024, 5.3 ms at 256). Hard fail above 2 cycles. T6 asserts it.
  - The bound is mitigation, not safety. B1 is the primary control; interim Rule 9 stays until B1 is verified on the Pi (F-318).
  - Fail closed: a link to the USBStreamer playback node whose source or port cannot be resolved is a violation, or is re-audited until resolved within the bound. Today `audit_links_for` in `link_audit.rs` does `None => continue` (called from `run_reconcile`, `registry.rs:578`).
  - Protect every input port on the USBStreamer playback node, not just `playback_AUX{n}`.
  - If split (O-29), these go into US-159b B2/T6.

### Web UI (UX)

- [ ] U1. Venue Apply with the gate Open: the button becomes "CLOSE GATE & LOAD VENUE" (warning style) with a confirm dialog. The browser closes the gate, waits for GM's authoritative Closed state (not a client flag), then calls set_venue. The gate is never re-opened automatically. On GM rejection: inline error, re-fetch state, keep the dropdown selection. If close succeeds but set_venue fails: "Gate closed, venue NOT changed (still <old>)". The label is driven by the /ws/system gate state. The gain display refreshes after a switch (F-274).
- [ ] U2. CLEAR WATCHDOG control on the gate panel, disabled with the cause as visible text while the cause persists. The trip cause is visible text, not a tooltip.
- [ ] U3. OPEN GATE refusal: GM's reason shown inline after the confirm dialog, never looking like success. The button is pre-disabled with blocker text when /ws/system health already shows a blocker.
- [ ] U4. Status bar and gate banner states (UX): CLOSED (amber); OPENING… (amber, the ~2 s ramp); OPEN/OK (green); CLOSING… (amber, transient); CLOSE FAILED (red, "retrying", U6); MUTED (red, watchdog latched). Never green except OPEN. State comes from GM's /ws/system state, not a client timer. During OPENING, CLOSE GATE acts immediately (G1) and OPEN GATE is disabled; if GM rejects or aborts the ramp, the UI shows CLOSED with the reason (PO). The gate banner shows the close reason (boot / manual / watchdog / venue switch / GM restart). If the owner picks "adopt" under O-12, a GM restart that adopts an open gate shows a visible warning in the status bar or banner (e.g. "GraphManager restarted — gains adopted from running graph; verify levels"), covered in T9 (UX).
- [ ] U5. Web UI MUTE/UNMUTE (F-320 F) goes through the gate: MUTE = close gate; UNMUTE removed or replaced by Open Gate with confirmation and ramp. Replaces US-160.
- [ ] U6. CloseFailed (G11): red "CLOSE FAILED — gains not confirmed zero. Amps off." (architect; AE alternative: "NOT CONFIRMED SILENT — turn amps off"; UX picks the wording). The indicator shows ERROR/UNKNOWN, never green or CLOSED. OPEN GATE disabled, CLOSE GATE enabled.
- [ ] U7. CLOSE GATE is always enabled, in every gate state including CLOSED: closing is always safe (F-338, UX).

### Tests

Each test states its environment: local-demo real PW stack, or Pi Gate 2 (QE to assign; PO).

- [ ] T1. Real stack (pw-cli enum-params): a watchdog close during Opening gives Mult == 0 on all 8 channels, and it stays 0 for at least 10 further ticks. Manual close and watchdog close: Mult == 0 on all 8 within 21 ms, measured (G1). CloseGate with the convolver node missing returns an error and does not report Closed (F-339).
- [ ] T2. Ramp, for both open() and a gain increase while Open (set_gain): monotonic, rate <= 30 dB/s measured on wall-clock time, cap respected under an injected stalled tick, stale generation is a no-op.
- [ ] T3. set_venue while not Closed: error, venue and gains unchanged. Coefficient hash mismatch: error.
- [ ] T4. open() refused for each unhealthy condition in G4. Unlatch never changes Mult.
- [ ] T5. GM restart while Open: Mult is 0 on all 8 after restart, state Closed, and no USBStreamer link exists before the read-back (G5a).
- [ ] T6. F-318 amps-off Pi test (CM CHANGE session), real stack under DJ load (Mixxx, quantum 1024): pw-play to the default sink delivers zero frames to the USBStreamer ports; a forced direct pw-link is destroyed within the B2 bound (<= 1 cycle, hard fail above 2), at least 100 trials, reporting p50, p99 and max. Includes an ordering case (link created before its source/port resolves: fail-closed per B2) and a link to a non-AUX input port of the playback node.
- [ ] T7. Unit tests for every ceiling and validation rejection in G3/G9, including summed-channel ceiling = profile ceiling - 6 dB.
- [ ] T8. Gate-authority invariant (F-320, F-298): after unlatch, GM restart and MUTE/UNMUTE, `Closed ⇒ all 8 Mult confirmed == 0 by read-back (G11); any Mult > 0 ⇒ Opening/Open` per pw-dump (architect: the equality form is false for Open with zero targets and for the first Opening tick).
- [ ] T9. Browser E2E against local-demo, one test per U item (UX + QE). Each test asserts what the operator sees AND cross-checks real state independently in PipeWire (pw-dump Mult values and USBStreamer links), never via GM `get_state` (anti-tautology). Faults are triggered through real conditions, not mocks. Requires F-312 REQUIRE_STACK; must not skip when GM is not connected.
  - U1: with the gate Open the Apply label reads "CLOSE GATE & LOAD VENUE". After confirming, the banner shows CLOSED and pw-dump shows all 8 Mult == 0 before the new venue is pending. Partial failure via a real coefficient-hash mismatch (G8): "venue NOT changed" text visible, venue and Mult unchanged.
  - U2: trip the watchdog with a real gain-integrity violation (external pw-cli Mult write). CLEAR WATCHDOG disabled, cause shown as visible text (not a tooltip). Clearing after the cause is gone leaves Mult at 0.
  - U3: each G4 blocker shown inline after the confirm dialog, no success styling, Mult stays 0. The button is pre-disabled when /ws/system shows a blocker.
  - U4: status bar colour and text for each visible state (CLOSED, OPENING…, OPEN/OK, CLOSING…, CLOSE FAILED, MUTED); never green while the gate is closed per pw-dump. During the ramp: amber "OPENING…" from GM state, CLOSE acts immediately (Mult == 0 per pw-dump), OPEN disabled; an aborted ramp shows CLOSED with the reason. Banner reason correct for boot, manual, watchdog, venue switch and GM restart (plus the adopt warning if O-12 picks adopt).
  - U5: browser MUTE leaves all 8 Mult == 0 and the gate Closed. UNMUTE is gone (or is Open Gate with confirm and ramp).
  - U6: close with the convolver absent or renamed: red CLOSE FAILED text, indicator never green or CLOSED, OPEN disabled, CLOSE enabled.
  - U7: with the indicator CLOSED and a Mult above 0 (external pw-cli write), CLOSE GATE is enabled and pressing it leaves all 8 Mult == 0.
  - Mutation evidence per item (e.g. leave the gate open on venue apply, restore gains on unlatch): the test must fail.
- [ ] T10. Confirmed close (G11; architect + AE), real stack: a healthy close shows all 8 Mult == 0 per pw-dump before Ok. Close with the convolver absent or renamed: RPC error, CloseFailed, UI red error. Cases: (i) watchdog trip with no convolver -> CloseFailed and all USBStreamer playback links destroyed; (ii) injected non-zero read-back -> CloseFailed and links destroyed; (iii) recovery only after a confirmed read-back, with no links before it; (iv) a WP or stray-client re-link during CloseFailed is destroyed.
- [ ] T11. Coefficient validation (G8b; AE + architect): a Dirac on a CHN-50P channel -> `open()` refused ("no driver protection on ch N"); a +3 dB boost FIR -> refused; a FIR with a +0.3 dB peak -> refused; a correct 200 Hz crossover -> accepted; a Dirac on ch 5-8 -> accepted; a channel with no resolvable speaker identity -> refused; an on-disk change after load -> refused ("reload required"); a cache miss -> "validation pending", no block.
