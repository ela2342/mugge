## US-159: GraphManager Gate Module — Single Owner of All Gain Writes

**As** the engineer running a gig with the amps on,
**I want** one GraphManager gate module that owns every gain (Mult) write, ramps every increase, and refuses unsafe operations,
**so that** no venue switch, unlatch, restart, UI action or stray client can put an unramped, unfiltered or over-ceiling signal into the speakers.

**Status:** draft. Design agreed by architect, audio-engineer and UX (2026-10-24). PO reviewed 2026-10-24 (changes applied). G11/U6/T10 (architect, AE A1-A4), G8b/T11 (AE thresholds) and the B2 bound (AE) added 2026-10-24. PO recommends a split into core / 159b / 159c (owner decision O-29). Owner to select (worker spawning, O-8).

### Gate module (GraphManager)

Sole owner of all Mult writes. Every other write site is removed
(`main.rs` 579/677/752/804/829/1042 and `registry.rs:504`), and the
web UI ones go through GM. The only non-GM writers are the three web-ui
callers of `pw_helpers.set_mult` (architect, verified): `config_routes.py:203`
(F-344), `audio_mute.py:87/124` (F-320-F) and `thermal_limiter.py:437`
(F-345). See D1-D3 and L1-L4 below.

- [ ] G1. States: Closed / Opening{target, generation} / Open. Decreases are applied immediately, within the <21 ms watchdog budget.
- [ ] G2. One slew limiter governs every increase (open, set_gain while Open, any future trim). Per tick: `applied = min(target, max(target*10^(-60/20), applied*10^(R*dt/20)))`, R = 30 dB/s (full open ~2 s), dt is measured wall-clock time, cap +3 dB per tick, tick interval = max(1 quantum period, 10 ms). Same relative dB curve on every channel; channels with target 0 stay at 0. Generation check on every tick. *(The 30 dB/s curve amends D-063's 3 s cosine; owner decision O-27. AE's minimum: rate-limited on wall-clock time, per-tick cap, generation check, full open >= 2 s.)*
- [ ] G3. Target validation before any write: finite, 0 <= Mult <= 1.0, and <= the per-speaker ceiling (G9). Any failing channel rejects the whole operation; no partial writes.
- [ ] G4. `open()` refuses, with a reason string, unless the graph is healthy: convolver present, all 8 gain params present, link audit clean (no foreign USBStreamer links), watchdog not latched.
- [ ] G5. At startup GM actively writes 0.0 to all 8 channels and enters Closed; it never trusts the conf or previous state. If the convolver is not present yet, it writes on node appearance, before any USBStreamer link is created. *(Note: this story is selectable with G5 = zero on start, the AE and architect recommendation (PO). If the owner later chooses "adopt" under O-12, that is a new story, with G3 validation and the G4 health check, falling back to zero; the gate never reads Closed while any Mult is above 0.)*
- [ ] G5a. GM creates no USBStreamer links until it has read back Mult == 0.0 on all 8 channels from the node.
- [ ] G6. `watchdog_unlatch` / CLEAR WATCHDOG clears the latch only and never restores gain. It refuses while the trip cause persists.
- [ ] G7. `set_venue` returns an error unless the gate is Closed, and mutates nothing on error. Venue persistence happens only after validation succeeds.
- [ ] G8. `set_venue` rejects a venue whose coefficients differ from those loaded, compared by content hash, not filename. GM hashes the conf-referenced files when the convolver node appears; any later on-disk change counts as a mismatch.
- [ ] G8a. On a coefficient hash mismatch, GM refuses `open()` and `set_venue` until the convolver is reloaded with the gate Closed. An on-disk change while Open shows a visible warning only (no forced close). Policy: coefficient files are written only via deploy, followed by that reload. The load-time record (here and in G8b (a)) is taken at a GM-confirmed reload, not at node appearance (G8c R-f, architect).
- [ ] G8b. Coefficient content validation, runtime (final text agreed by AE and architect, 2026-10-24). Runs alongside the G8 hash. Scope is per channel n, driven by the speaker identity S(n) bound to that channel in the active speaker profile, not by venue name. If no speaker identity resolves for a channel, refuse (fail closed, not a skip).
  - (i) Every channel: max_f |H_n(f)| <= S(n).max_boost_db + 0.1 dB, otherwise refuse. The +0.1 dB is a numerical tolerance for the runtime check only (Python/Rust agreement <= 0.05 dB per T9 fixtures). It is deliberately not the D-009 generator target (cut-only with -0.5 dB margin), and it must not be loosened without AE review, because the G9 ceilings assume |H| <= 0 dB with < 1 dB thermal margin for the CHN-50P. *("T9 fixtures" in the quoted sentence refers to this story's G8b test, numbered T11 here.)*
  - (ii) Any channel whose speaker declares `mandatory_hpf_hz` = F: |H| <= -3 dB at F and <= -24 dB over [DC, F/2], otherwise refuse with "no driver protection on ch N". The same check applies to the sub 42 Hz subsonic floor where defined. Ch 5-8 (HP/IEM) declare no `mandatory_hpf_hz`, so a Dirac passes there; a Dirac passes (i) at 0 dB.
  - (a) Off the PipeWire main loop (architect: a WAV read or FFT stall there delays registry/link events and the <21 ms watchdog response). Validation runs on a worker thread when the convolver node appears and at `set_venue`, cached per content hash. `open()` only re-hashes (G8a) and reads the cache; a cache miss refuses with "validation pending" and starts the computation, never blocks. Validate what PW actually loaded (AE): record content hash, mtime and size when the convolver node appears; if the on-disk hash no longer matches in `open()`, refuse with "coefficients changed on disk since load; reload required". One shared load-time record serves G8, G8a and G8b.
  - (b) (i) uses >= 4x zero-padding (matches the F-262 condition 2 shared |H| helper). (ii) uses a direct DTFT on a grid of <= 0.5 Hz spacing over [DC, F/2] plus the exact point F; no bin snapping (F-299).
  - (c) The WAV check compares rate and channel count against the conf; the expected tap count comes from the conf/profile, not a hard-coded 16384 (F-331).
  - (d) One rule, two languages: the T11 fixture WAVs also run through the Python room-correction verify path, agreeing within 0.05 dB.
  - First boot (AE ruling, architect agrees): no exemption for passthrough by venue name. G8b enforces D-031 point 3 and D-055 point 3, which `foh-passthrough.yml` already violates (F-271; safety.md §10 Rule 2). Until F-271 ships HPF-only protection WAVs for ch 1-4, first-boot `open()` is refused with "no driver protection on ch 1-4 (F-271)". Because the gate is all-or-nothing (G3), that also silences ch 5-8. Owner questions: O-30.
  - Tested by T11. Part of the AE veto-lift conditions (core story if split, O-29). Related: F-271, US-113, US-124.
- [ ] G8c. Coefficient reload (F-346; architect ruling R-a to R-e, amended 2026-10-24, plus R-f, R-h and R-g1 to R-g4; AE conditions RF1-RF4; with US-090/097/112/127 and F-321; patch changes in F-346 AC10-AC12).
  - R-a: reload is a GM-owned RPC; `POST /reload-pw` and the web UI deploy path call GM, never pw-cli.
  - R-b: allowed only when the gate is confirmed Closed (G11 read-back), as G7. Reload while Open is not permitted, regardless of G8b outcome or programme material, until the patch provides a synchronized, crossfaded all-channel swap (architect, AD: hard discontinuity per swap, 8 swaps in different cycles; owner decision O-33).
  - R-c (amended): GM cannot read back what PW loaded, so it uses the patch's `ReloadCount` notify control. Sequence: (1) hash, mtime and size of all 8 files, then G8b on that content, refuse on failure; (2) record every `ReloadCount`; (3) trigger all 8 with prefixed names (`conv_<ch>:Reload`, value: the current Reload value read from PW, +1; R-h); (4) wait, with a timeout, until all 8 counters have incremented by exactly 1; (5) re-check hash, mtime and size unchanged; (6) only then update the G8a hash. A counter that does not move, or a file changed in between, is a failed reload. A PW restart sets ContentUnknown (R-f), which only a confirmed reload clears, so with R-f `open()` needs the prefixed per-convolver Reload and the ReloadCount patch (F-346 AC10-AC12; architect confirmed). Sequencing: R-f ships together with the patch or after it, never before (alone, the system could never open). The "PW restart via G8a" fallback ends when R-f lands; interim rule 9 is pre-fix only.
  - R-d: prefixed names for all 8 channels; anything short of all 8 confirmed is ReloadFailed.
  - R-e: GM updates its G8a hash only after a confirmed reload.
  - R-f (architect): filter content counts as known only after a GM-confirmed all-8 reload on the current node instance. GM start, PW restart and convolver node reappearance set ContentUnknown; `open()` is refused while ContentUnknown. It is cleared by one confirmed reload while Closed (G8b on the files, trigger all 8, all counters +1, files unchanged); this costs one main-loop stall per start. After a PW restart a counter at 0 is a new baseline, never a mismatch. This replaces "G8a hash at node appearance" and removes the startup race of files written while PW starts. Same instance: GM records the convolver's `object.serial` (monotonic, never reused, unlike node IDs) with the baseline counters; a different serial at read-back means the node was recreated -> ContentUnknown, never confirmed.
  - ReloadFailed (architect; AE accepts on RF1-RF4): open_gate refused until a confirmed reload or a PW restart; the UI shows which channels failed; no link destruction while the gate is confirmed Closed. RF1: any non-zero Mult while ReloadFailed escalates to CloseFailed (A1). RF2 (refined by R-f): exit only via a confirmed reload on the current node instance, directly or after a PW restart; a GM or PW restart sets ContentUnknown. RF1 also holds with D3 detection active (architect). RF3: a partial reload (some counters moved, others not) is ReloadFailed and the UI shows "N of 8 reloaded". RF4: reload while Open stays refused unless the owner rules otherwise (O-33).
  - The main-loop stall (8 x 16k-tap FFT builds in `control_changed`) is measured under DJ load and added to the L4 latency budget.
  - R-h, re-arm value (architect, with AD): GM reads each convolver's current Reload value from PW just before triggering and writes current+1; never a value held only in memory (stale after a GM or PW restart or an external write, giving the F-346 false success). (a) Read and write per node under the same `object.serial`; a serial change between them fails that channel (ReloadFailed, ContentUnknown). (b) Confirmation is still the read-only ReloadCount going +1 on all 8; the Reload input proves nothing. (c) A failed Reload read means no write and ReloadFailed for that channel.
  - Boot (AE): with R-f the confirmed reload is boot-critical; the UI shows a distinct "filter content unverified: reload required" or "reload failed, N of 8" state. G8b validates the files before the trigger, and the files are frozen (re-checked unchanged) until the trigger.
  - R-g1, close preempts (architect, with AD): open_gate, reload and set_mode serialize through one mutation queue. close_gate (including watchdog, integrity and standby closes) bypasses it: bump the gate epoch, write Mult 0 to every discovered gain at once, then read back. Close latency is bounded by the PW main loop, so a patched reload's FFT build can delay a close (and D3 re-zeroing) by up to the FFT time; the patch must build the FFT off the main loop (F-346 AC14). Until then the bound is documented and the L4 stall measurement is mandatory. D3 detection stays active during a reload (RF1).
  - R-g2, ramp epoch: every gain-raising step (open ramp, G2 slew) carries the epoch it started under and re-checks it immediately before each write; on a mismatch it aborts without writing. Required once the ramp becomes temporal (F-315 fix); today's 30 steps run back to back with no timer (`main.rs:797-806`). The epoch also guards the final transition (AD, architect): the ramp sets gate_open=true and emits GateOpened (`main.rs:808` on) only if the epoch is unchanged since it started; otherwise the open returns aborted and the state stays Closed (else the indicator reads OPEN with every gain at 0.0, the inverse of F-320).
  - R-g3, refuse, never queue: open_gate during a reload or set_mode is refused; set_mode during a reload is refused ("reload in progress"); reload during set_mode is refused ("mode change in progress"). The operator retries; nothing completes later on its own. A reload ends confirmed, ReloadFailed or timed out (= ReloadFailed, "N of 8").
  - R-g4, expected set: the 8 fixed per-output names (`GAIN_PARAM_NAMES`, one source); the profile's channel map decides only each channel's content (FIR or Dirac, ceiling, UI role label; on 3-way ch 5-6 are speakers, ch 7-8 HP, no IEM). GM compares the discovered set with these 8. Reload: any mismatch -> ReloadFailed, ContentUnknown, shown as "k of 8 expected", never "k of k found". Close and open: G13.
  - Tested by T22-T33.

- [ ] G12. Gain integrity MissingNodes (`gain_integrity.rs:91`, `main.rs:1063`) becomes a loud fail-closed state, and the > 1.0 check still runs over the gains present. G11 read-back covers every discovered gain. D3 external-write detection iterates the discovered set.

  - A3. The only exit from CloseFailed: convolver present, confirmed read-back, then link recreation (as G5a), into Closed, never Open. A re-appearing convolver gets an active zero write plus read-back.

### Sole Mult writer (architect D1-D3, 2026-10-24; with G11 in the same increment)

Shipping G11 without D3 would make "confirmed Closed" untrue as soon as the web UI writes (architect).

- [ ] D1. GM is the only process that sets Mult; every web-ui write becomes a GM RPC. Config `set_gain` -> GM `set_channel_gain` (updates the venue's pending gains when Closed; when Open, goes through G3/G9 and the G2 slew limiter). MUTE -> GM `close_gate` (MUTE is the gate; UNMUTE as a gain restore is removed; recovery is `open_gate` under G4; resolves F-320-F). The thermal limiter sends GM `set_limit_factor(channel, f)`, 0 <= f <= 1, and never writes Mult. `pw_helpers.set_mult` is deleted.
- [ ] D2. Limiter can only reduce: GM computes effective = min(venue_gain x f, G9 ceiling), and effective = 0 while Closed whatever f is. No cached `current_mult` anywhere (this also removes the stale convolver node ID cache, `thermal_limiter.py:427-435`).
- [ ] D3. External-write detection, required (web-ui, GM and any shell all run as `ela`, so D1 cannot be enforced at a process boundary). GM subscribes to param-change events on the convolver node; the 30 s gain_integrity poll stays as a backstop, and its > 1.0 check stays as-is. Closed: any Mult != 0.0 -> re-zero -> CloseFailed (A1: destroy USBStreamer links, block relinks). Open: any Mult not matching GM's own commanded values (L3) -> zero immediately, close the gate, log the external write.
- [ ] L1. (AE; architect) One slew limiter for every raise: any rise in effective (factor recovery, venue gain, open) goes through G2 (30 dB/s); decreases apply immediately; the G9 ceiling still applies.
- [ ] L2. (AE) On a stale limiter GM holds the last factor and never reverts to 1.0; the factor survives Close -> Open. R1 (architect): after a GM restart GM does not assume f = 1.0; `open_gate` for a channel with a thermal profile is refused ("limiter not reporting") until a fresh limiter update arrives (extends G4). Mid-show heartbeat loss: hold the last factor plus a visible UI alarm "thermal limiter not reporting". What follows the hold is the owner's call (O-31; AE recommends a 60 s bounded hold, then a -6 dB cap).
- [ ] L3. (AE) A mismatch while Open zeroes immediately, with GM's own write echoes recognized. R2 (architect): an observed value is GM's own if it is within tolerance of any value GM commanded in the last N ticks (N covers the measured event lag), each tagged with the GM generation; anything else is external.
- [ ] L4. (AE) Stray write to re-zero latency measured over >= 100 Pi trials, p50/p99/max, hard fail above the bound. R3 (architect): measured end to end, from the external pw-cli return to GM's zero write confirmed by the next param event, under DJ load (quantum 1024, Mixxx). Detection is mitigation only: the interim amps-off rule stays until the web-ui writers are removed (D1), not merely detected (D3).
