## US-159: GraphManager Gate Module — Single Owner of All Gain Writes

**As** the engineer running a gig with the amps on,
**I want** one GraphManager gate module that owns every gain (Mult) write, ramps every increase, and refuses unsafe operations,
**so that** no venue switch, unlatch, restart, UI action or stray client can put an unramped, unfiltered or over-ceiling signal into the speakers.

**Status:** draft. Design agreed by architect, audio-engineer and UX (2026-10-24). PO to review; owner to select (worker spawning, O-8).
**Priority:** critical (fixes F-314; AE veto on gate/venue/first-boot PRs lifts only when this lands)
**UX tier:** A (the worker sends the approach to UX, AE and architect before writing code)
**Fixes:** F-314, F-315, F-320 (D/E/F/G), F-318, F-321, F-322
**Depends on:** F-298 Part A (AE merge condition for any gate/venue/first-boot PR); owner decision O-12 (GM restart behaviour, see note under G5)

### Gate module (GraphManager)

Sole owner of all Mult writes. Every other write site is removed
(`main.rs` 579/677/752/804/829/1042 and `registry.rs:504`).

- [ ] G1. States: Closed / Opening{target, generation} / Open. Decreases are applied immediately, within the <21 ms watchdog budget.
- [ ] G2. One slew limiter governs every increase (open, set_gain while Open, any future trim). Per tick: `applied = min(target, max(target*10^(-60/20), applied*10^(R*dt/20)))`, R = 30 dB/s (full open ~2 s), dt is measured wall-clock time, cap +3 dB per tick, tick interval = max(1 quantum period, 10 ms). Same relative dB curve on every channel; channels with target 0 stay at 0. Generation check on every tick. *(The 30 dB/s curve amends D-063's 3 s cosine; owner decision O-27. AE's minimum: rate-limited on wall-clock time, per-tick cap, generation check, full open >= 2 s.)*
- [ ] G3. Target validation before any write: finite, 0 <= Mult <= 1.0, and <= the per-speaker ceiling (G9). Any failing channel rejects the whole operation; no partial writes.
- [ ] G4. `open()` refuses, with a reason string, unless the graph is healthy: convolver present, all 8 gain params present, link audit clean (no foreign USBStreamer links), watchdog not latched.
- [ ] G5. At startup GM actively writes 0.0 to all 8 channels and enters Closed; it never trusts the conf or previous state. If the convolver is not present yet, it writes on node appearance, before any USBStreamer link is created. *(Note: this settles F-320 E as "zero on start", the AE and architect recommendation. "Adopt" stays an owner option under O-12, only with G3 validation and the G4 health check, falling back to zero; the gate never reads Closed while any Mult is above 0.)*
- [ ] G5a. GM creates no USBStreamer links until it has read back Mult == 0.0 on all 8 channels from the node.
- [ ] G6. `watchdog_unlatch` / CLEAR WATCHDOG clears the latch only and never restores gain. It refuses while the trip cause persists.
- [ ] G7. `set_venue` returns an error unless the gate is Closed, and mutates nothing on error. Venue persistence happens only after validation succeeds.
- [ ] G8. `set_venue` rejects a venue whose coefficients differ from those loaded, compared by content hash, not filename. GM hashes the conf-referenced files when the convolver node appears; any later on-disk change counts as a mismatch.
- [ ] G8a. On a coefficient hash mismatch, GM refuses `open()` and `set_venue` until the convolver is reloaded with the gate Closed. An on-disk change while Open shows a visible warning only (no forced close). Policy: coefficient files are written only via deploy, followed by that reload.
- [ ] G9. Per-speaker static ceilings live in the speaker profile (dB re amp full scale, converted to Mult). Until the chain is calibrated, assume Mult 1.0 = 450 W. CHN-50P: <= 0.112 (-19 dB). UMII18-22 (120 L): 1.0. Applied to every Mult write; `set_venue` rejects any profile above its ceiling. Chain-calibration measurement: AE follow-up. Dynamic limiter: later story, after a BM-2 CPU check. Summed inputs (AE, after an AD caveat): for a channel fed by N correlated summed inputs, the ceiling applies to effective output, Mult_max = ceiling / N (-6 dB for the L+R subs). Output is bounded at Mult 1.0 regardless (USBStreamer clips at 0 dBFS). Today's rigs are unaffected (CHN-50P is mains-only), but G9 implements the rule generally.
- [ ] G10. D-063's `audio_enabled` in `active.yml` (F-320 G): implemented as specified, or D-063 amended to match the in-memory design (architect).

### WirePlumber default-sink bypass (F-318) — both required

- [ ] B1. Prevention: the USBStreamer is never the default sink. Investigate making it non-selectable for clients altogether (not a regular Audio/Sink, or via PW permissions), which is stronger than priority 0.
- [ ] B2. Enforcement: GM destroys any non-GM link to USBStreamer playback, event-driven on registry link-added (not polling), and logs it, with the gate open or closed. The measured worst-case time from creation to destruction is reported. Extend and verify the existing event-driven `link_audit.rs` rather than adding a second auditor (architect).

### Web UI (UX)

- [ ] U1. Venue Apply with the gate Open: the button becomes "CLOSE GATE & LOAD VENUE" (warning style) with a confirm dialog. The browser closes the gate, waits for GM's authoritative Closed state (not a client flag), then calls set_venue. The gate is never re-opened automatically. On GM rejection: inline error, re-fetch state, keep the dropdown selection. If close succeeds but set_venue fails: "Gate closed, venue NOT changed (still <old>)". The label is driven by the /ws/system gate state. The gain display refreshes after a switch (F-274).
- [ ] U2. CLEAR WATCHDOG control on the gate panel, disabled with the cause as visible text while the cause persists. The trip cause is visible text, not a tooltip.
- [ ] U3. OPEN GATE refusal: GM's reason shown inline after the confirm dialog, never looking like success. The button is pre-disabled with blocker text when /ws/system health already shows a blocker.
- [ ] U4. Status bar: MUTED (red) -> CLOSED (amber) -> OK (green); never green while the gate is closed. The gate banner shows the close reason (boot / manual / watchdog / venue switch / GM restart). If the owner picks "adopt" under O-12, a GM restart that adopts an open gate shows a visible warning in the status bar or banner (e.g. "GraphManager restarted — gains adopted from running graph; verify levels"), covered in T9 (UX).
- [ ] U5. Web UI MUTE/UNMUTE (F-320 F) goes through the gate: MUTE = close gate; UNMUTE removed or replaced by Open Gate with confirmation and ramp.

### Tests

- [ ] T1. Real stack (pw-cli enum-params): a watchdog close during Opening gives Mult == 0 on all 8 channels, and it stays 0 for at least 10 further ticks.
- [ ] T2. Ramp, for both open() and a gain increase while Open (set_gain): monotonic, rate <= 30 dB/s measured on wall-clock time, cap respected under an injected stalled tick, stale generation is a no-op.
- [ ] T3. set_venue while not Closed: error, venue and gains unchanged. Coefficient hash mismatch: error.
- [ ] T4. open() refused for each unhealthy condition in G4. Unlatch never changes Mult.
- [ ] T5. GM restart while Open: Mult is 0 on all 8 after restart, state Closed, and no USBStreamer link exists before the read-back (G5a).
- [ ] T6. F-318 amps-off Pi test (CM CHANGE session): pw-play to the default sink delivers zero frames to the USBStreamer ports; a forced direct pw-link is destroyed within the measured bound.
- [ ] T7. Unit tests for every ceiling and validation rejection in G3/G9, including summed-channel ceiling = profile ceiling - 6 dB.
- [ ] T8. Gate-authority invariant (F-320, F-298): after unlatch, GM restart and MUTE/UNMUTE, `Closed ⇒ all 8 Mult == 0; any Mult > 0 ⇒ Opening/Open` per pw-dump (architect: the equality form is false for Open with zero targets and for the first Opening tick).
- [ ] T9. Browser E2E against local-demo, one test per U item (UX + QE). Each test asserts what the operator sees AND cross-checks real state independently in PipeWire (pw-dump Mult values and USBStreamer links), never via GM `get_state` (anti-tautology). Faults are triggered through real conditions, not mocks. Requires F-312 REQUIRE_STACK; must not skip when GM is not connected.
  - U1: with the gate Open the Apply label reads "CLOSE GATE & LOAD VENUE". After confirming, the banner shows CLOSED and pw-dump shows all 8 Mult == 0 before the new venue is pending. Partial failure via a real coefficient-hash mismatch (G8): "venue NOT changed" text visible, venue and Mult unchanged.
  - U2: trip the watchdog with a real gain-integrity violation (external pw-cli Mult write). CLEAR WATCHDOG disabled, cause shown as visible text (not a tooltip). Clearing after the cause is gone leaves Mult at 0.
  - U3: each G4 blocker shown inline after the confirm dialog, no success styling, Mult stays 0. The button is pre-disabled when /ws/system shows a blocker.
  - U4: status bar colour and text across MUTED, CLOSED and OK; never green while the gate is closed per pw-dump. Banner reason correct for boot, manual, watchdog, venue switch and GM restart (plus the adopt warning if O-12 picks adopt).
  - U5: browser MUTE leaves all 8 Mult == 0 and the gate Closed. UNMUTE is gone (or is Open Gate with confirm and ramp).
  - Mutation evidence per item (e.g. leave the gate open on venue apply, restore gains on unlatch): the test must fail.
