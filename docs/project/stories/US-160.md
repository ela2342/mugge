### Acceptance Criteria

- [ ] AC1: No web UI control can raise Mult outside the documented interim procedure.
- [ ] AC2: The operator still has a documented, visible path to restore audio: Close Gate, then pre-flight #10, then Open Gate. No gain-restore control (UX).
- [ ] AC3: A browser test covers AC1 and AC2, cross-checking Mult in PipeWire.
- [ ] AC4: US-159 U5 replaces this when it lands.

Mode changes and restore paths (F-359)

- [ ] AC5 (G-a): a plain `set_mode` is refused unless the gate is confirmed Closed: Closed after a G11 read-back, all 8 Mult exactly 0.0. CloseFailed, unknown and every unconfirmed state count as NOT Closed for every refusal here: `set_mode`, measurement/TF entry and close_first's switch step (AD M5(a), PO). The refusal returns reason code `gate_not_closed` (G14 style) and changes no link. Once US-159 brings a real ramp, Opening and Closing are refused too (architect B2). After a successful `set_mode` the gate stays Closed; reopening needs pre-flight #10 and an explicit OpenGate. `set_mode(standby)` follows the same rule: main's standby close (`graph-manager main.rs:568-581`) emits GateClosed without a read-back and gets the G11 read-back (architect B3, AE).
- [ ] AC6 (G-b): `set_mode(target, close_first=true)` runs close, ramp complete, G11 read-back and switch as one GM command and ends Closed. Concurrent GM commands are refused or queued. On CloseFailed: no switch, an error and the AC15 banner. It is an explicit caller opt-in for the restore paths and does not weaken AC5 for a plain `set_mode` (AE N8).
- [ ] AC7 (gate lock; AD M5(b)): while a `set_mode` or relink is in progress the gate is locked: OpenGate is refused with reason code `mode_change_in_progress` until the new link set has been read back and has settled. Then OpenGate is accepted again, with its normal checks.
- [ ] AC8 (other link paths; AD M5(c)): the architect lists every other GM path that changes links (the reconciler, GM restart/adopt (O-12), `set_venue`, any others) and states for each whether the same invariant gates it. An ungated path gets this rule in US-160 or a named follow-up defect. "Not listed" does not pass review.
- [ ] AC9 (entry; R3): starting a measurement or TF run is refused unless the gate is confirmed Closed, never auto-closed; its panel shows "Measurement not started — gate is open. Close the gate first." Then `set_mode`, read-back, and an explicit operator OpenGate with the S-012 confirmation, the signal-gen cap at -20 dBFS and a ramp (the stimulus needs the gate Open, `routing.rs:649-679`).
- [ ] AC10 (exit, every path; R1, R2, AE A1 and M1): (1) a standalone CloseGate before signal-gen stops; (2) signal-gen stops, whatever the outcome of step 1; (3) `set_mode(previous, close_first=true)`; (4) "restored" only on GM confirmation (`get_mode` read-back) plus the G11 read-back. The gate stays Closed; no automatic reopen. On success: "Restored to <mode>. Gate CLOSED: open when ready (pre-flight #10)." If step 1 or 3 fails: no switch, the AC15 banner, and "still in measurement mode: restore failed" with a retry (AE texts).
- [ ] AC11 (R4): TF `/stop` and the measurement session never report "restored" without the AC10 confirmation; otherwise a visible alarm with GM's reason code and the actual mode. The `except: pass` at `session.py:489-494` and TF's unconditional `restored_mode` (`transfer_function_mode.py:205-247`) go (UX).
- [ ] AC12 (R5): every exit path is covered: normal end, abort, error, and the enter-failure rollback at `session.py:490-496` (UX found these paths: `session.py:477-494, 1509-1520`).
- [ ] AC13 (UI error): the refusal appears inline in the open mode dropdown (role="alert"; not a tooltip, toast or outline-only), mapped from the reason code with no string matching: "MODE NOT CHANGED — gate is open. Close the gate, then switch. Still in <mode> mode." In Closing it reads "wait for the gate to close". It stays until the dropdown closes or the gate reads Closed. The badge keeps showing the real mode from /ws/system. (UX: today `statusbar.js:519-551` shows only a 1.5 s red outline.)
- [ ] AC14 (UI pre-emption; UX): mode options are greyed out while the gate is not confirmed Closed (Open, Opening, Closing, CloseFailed or unknown, so it fails closed), with one visible line, "Close the gate to change mode." AC5's refusal stays authoritative. No combined "close & switch" button before US-159 U1.
- [ ] AC15 (CloseFailed banner; PO, AE, UX): one text, shared with US-159 U6 and US-171: "CLOSE FAILED — NOT CONFIRMED SILENT. All amps off (incl. HP/IEM), headphones off, IEMs out." A context line follows ("Mode not changed." or "Measurement ended; mode not restored."), and a failed restore also shows the RESTORE_FAILED state. "Signal generator stopped" is added only when GM or signal-gen confirms it. The banner wraps onto as many lines as it needs. It is never truncated or ellipsized, and its actions are never hidden behind a tooltip or "more" toggle. The "All amps off" short form is allowed only on a surface that physically can't wrap; none exists in the current UI.
