## US-157: Mechanical Test Anti-Pattern Lint in test-unit

**As** the team relying on CI as the quality gate,
**I want** a mechanical check that flags test code which can swallow failures,
**so that** safety assertions cannot silently turn into skips or passes
(see F-298, F-301).

**Status:** draft (architect ruling 2026-10-24; AC reworded by PO, AC2/AC3 confirmed by architect and QE, 2026-10-24). Owner to confirm.
**Priority:** High
**Depends on:** F-298, F-301, F-303–F-311 (fix or exempt each site); docs freeze lift (AC8)
**Blocks:** none
**Related:** F-298, F-301, F-303–F-311, F-272, testing-process.md Sec 4.2

### Acceptance Criteria

1. An AST lint runs as part of `nix run .#test-unit` and **fails the run**
   (non-zero exit) on any unexempted finding. It scans **all** Python test
   code in the repo (tests/unit, tests/integration, tests/e2e,
   tests/service-integration, room-correction tests, and any other
   `test_*.py` / `conftest.py`).
2. It flags any `except` handler that catches `AssertionError`, `Exception`,
   `BaseException`, or is a bare `except:` (including inside a tuple), whose
   `try` body contains `assert`, Playwright `expect(...)`, or a call to a
   pytest assertion helper, **unless the handler re-raises
   unconditionally**. Unconditional means a bare `raise` (or `raise X from
   e`) as a top-level statement of the handler body, reached on every path;
   a raise nested in `if`/`try`, or preceded by a possible early
   `return`/`continue`, does not count. Re-raising pytest's Skipped/XFailed
   (e.g. `raise pytest.skip.Exception`) does not count.
   `contextlib.suppress(...)` whose arguments include `Exception`,
   `BaseException` or `AssertionError`, around such statements, is flagged
   the same way.
3. It flags any `pytest.skip(...)`, `pytest.xfail(...)` or
   `pytest.importorskip(...)` call inside an `except` handler.
   `pytest.fail(...)` in a handler is not flagged. Module-level
   `importorskip` outside a handler is out of scope (F-311 X1).
4. An exemption needs a marker comment on the `except` line, in the exact
   form `# lint-allow: <rule-id> F-NNN`. The lint checks that
   `docs/project/defects/F-NNN.md` exists. Each run prints every active
   exemption (file:line, rule, defect).
5. Findings are reported as `file:line: <rule-id> <message>`.
6. The lint's own tests use a fixture file with one positive example per
   flagged pattern (including the nested-raise case) and negative cases
   (unconditional re-raise, narrow exception, `pytest.fail`, module-level
   importorskip), a valid exemption, and an exemption naming a
   non-existent defect (must fail). Mutation evidence: the lint catches
   every positive and none of the negatives.
7. At merge, `nix run .#test-unit` passes on the PR branch with zero
   unexempted findings. Every exemption references an **open** defect from
   F-298/F-301/F-303–F-311 (or a newly filed one).
8. testing-process.md Sec 4.2 documents the anti-pattern (technical-writer).
   **Depends on:** docs freeze lift.
