## US-157: Mechanical Test Anti-Pattern Lint in test-unit

**As** the team relying on CI as the quality gate,
**I want** a mechanical check that flags test code which can swallow failures,
**so that** safety assertions cannot silently turn into skips or passes
(see F-298, F-301).

**Status:** draft (architect ruling 2026-10-24; PO to review AC wording)
**Priority:** High
**Related:** F-298, F-301, F-303–F-311, testing-process.md Sec 4.2

### Acceptance Criteria

1. An AST lint runs as part of `nix run .#test-unit`.
2. It flags any `except` (bare, `Exception` or `BaseException`) whose `try`
   body contains `assert` or `expect()`.
3. It flags any `pytest.skip` inside an `except` handler.
4. An exemption needs a marker comment that names a defect ID.
5. The lint has its own tests (positive and negative cases).
6. It lands after the F-298/F-301/F-303–F-310 fixes, or with tracked
   exemptions for the sites that remain.
7. testing-process.md Sec 4.2 documents the anti-pattern (TW, after the
   docs freeze).
8. QE is a mandatory reviewer.
