## D-065: Remove WirePlumber 90-no-auto-link.conf (2026-04-19)

**Status:** RECONSTRUCTED — owner confirmation required

> **Reconstructed record (PM, 2026-10-24).** Commit `991ff456` and a comment
> in `nix/nixos/audio/wireplumber.nix` reference D-065, but no decision
> record was written. The text below is taken from that comment. Decisions
> are binding only when owner-made. The owner must confirm that this
> decision was taken, or else replace this record.

**Context:** `90-no-auto-link.conf` set `policy.standard=disabled` to stop
WirePlumber auto-linking (D-043). This was too broad. It disabled all WP
format negotiation, so nodes were not activated and ports were not created
(F-292).

**Decision:** Remove `90-no-auto-link.conf`. Anti-bypass relies on the two
remaining layers: `node.autoconnect=false` and GraphManager reconciler
cleanup.

**Rationale:** Per the code comment, the two remaining layers are sufficient.

**Impact:** Amends D-043 (WP retained, linking disabled). WirePlumber
standard policy is active again. Security/audio-safety implications of
removing one anti-bypass layer are not recorded. Audio-engineer and
security-specialist review needed.

**Security retroactive review (2026-10-24): HIGH finding, pending evidence**
(F-318). `node.autoconnect=false` does not stop WP standard policy from
linking non-JACK streams to the default sink (likely the USBStreamer), leaving
GM `link_audit` as the only, after-the-fact layer, absent while GM restarts.
D-065 cannot be accepted until F-318 is resolved.

**Joint AE + security position (2026-10-24):** HIGH, rising to CRITICAL if
the Pi test confirms the USBStreamer is the default sink. Acceptance needs a
non-reactive layer, not just `link_audit`. AE veto applies. See F-318.

**Related (2026-10-24):** F-334 — local-demo still sets
`policy.standard = disabled`, so it does not reflect this decision.
