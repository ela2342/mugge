## D-069: Pi 5 platform baseline under NixOS (2026-10-25)

**Status:** PROPOSED (architect, 2026-10-25). Owner confirmation is
given by owner acceptance of PR #50 (US-163); no separate ask.

**Context:** Since 2026-10-24 the deployment target is a Raspberry Pi 5
(the Pi 4B at .185 is unreachable). US-163 bootstrapped it from
Raspbian to NixOS. AC21 asked which platform decisions made on the
Pi 4 still hold on the Pi 5, and recorded the new ones the Pi 5 needs.

**Decision:**
1. **D-013 (PREEMPT_RT) holds on the Pi 5.** AC13 PASS. AC3 PASS:
   `uname -v` reports PREEMPT_RT, the kernel has
   `CONFIG_PREEMPT_RT=y`, and PAGESIZE is 4096. On 6.12, PREEMPT_RT
   is mainline, so `/sys/kernel/realtime` (an attribute of the old
   out-of-tree RT patch) is expected to be absent and is not a
   criterion.
2. **D-022 (hardware V3D GL) is not confirmed on the Pi 5.** There is
   no DRM device: the DT nodes are disabled (F-367). This is deferred
   to US-172 as a known deviation; it does not block US-163. On the
   Pi 4, D-022 is unchanged and unverified (US-170).
3. **Board split.** Board-specific code lives in `nix/nixos/boards/pi4`
   and `nix/nixos/boards/pi5`. Shared modules never branch on the
   board; they read facts from `mugge.board.*`
   (`nix/nixos/boards/options.nix`). Configurations: `mugge` and
   `mugge-deploy` (Pi 4), `mugge-pi5-bootstrap` and
   `mugge-pi5-deploy` (Pi 5). The Pi 4 drvPath stays identical apart
   from `05-rt-direct.conf` (AC1a).
4. **Direct firmware boot on the Pi 5, no U-Boot.** The firmware reads
   `config.txt` on the FAT partition, which points at the generation
   to boot. Rollback means moving that pointer back to an older
   generation (card reader or tryboot). The FAT partition always
   keeps at least 2 complete generations (F-369 fix: the keep set is
   {new, previous, booted, highest other complete generation};
   pruning only deletes and runs with a pinned PATH).
5. **Deploy verb.** From the Mac, run the darwin nixpkgs
   `nixos-rebuild-ng` package (binary name `nixos-rebuild` in nixpkgs
   26.11) with `--no-reexec`:
   `boot --flake .#mugge-pi5-deploy --target-host ela@192.168.178.89
   --sudo`, then announce and do a reboot. Not `switch`. The Mac
   daemon offloads aarch64 builds to its linux-builder VM.
6. **Target identity.** The canonical address is the DHCP-pinned
   192.168.178.89. `mugge.lab.andreas.org` is an alias only, because
   it resolves only via the LAN DNS. The host is identified by its
   ED25519 host key (SHA256:a5kILUyr...) plus MAC 88:a2:9e:8c:8d:4e,
   never by accept-new.
7. **CPU governor.** `performance` is the production default on both
   boards (`nix/nixos/rt-tuning.nix`, F-291). Load runs check it
   read-only and never pin it.

**Rationale:** Direct firmware boot is the Pi 5's native boot path and
avoids maintaining U-Boot for a board where it adds nothing. The
remaining risk is the vfat power-loss window, which the 2-generation
rule bounds (F-370 narrows it further). The board split keeps the
Pi 4 build bit-identical, so the Pi 4 stays a known-good fallback.
D-022 cannot be tested without a DRM device, so it stays an explicit
open item instead of an assumed carry-over.

**Impact:**
- `docs/architecture/rt-audio-stack.md` and CLAUDE.md "Pi Hardware
  State" described the Pi 4. Done in #50 (TW; CLAUDE.md is the
  owner's file): rt-audio-stack.md has "Pi 5 Kernel and Boot
  (US-163)" and "Pi 5: Root Cause and Direct RT Path (F-358)";
  CLAUDE.md has "Pi 5 State (verified 2026-10-25)".
- The Pi 5 has passive cooling only (metal case). Load runs follow
  the thermal rule (WARN at 75 C, STOP at 80 C, invalid if throttled
  or undervolted). Sustained DJ load likely needs a fan (flight-case
  TODO).
- F-370 (skip identical rewrites of `config.txt`/MAP.txt): P2, not
  blocking.
