## D-067: Documentation-only PRs are exempt from the Rule 13 CI requirement (2026-10-24)

**Status:** ACCEPTED (owner, first-hand to team-lead, 2026-10-24)

**Context:** O-22 ruled that a CI paths-filter skip is not green, so
T1-T3 had to actually run on every PR head. Since F-335 breaks T1 on
main, docs-only PRs (#41, #46, #47) could not meet Rule 13 at all, and
F-357 showed that the skip had been counted as green since 2026-04-20.
The CM asked whether a docs-only PR whose test jobs are skipped counts
as CI green.

**Decision:** Owner, verbatim: "documentation-only PRs are exempt".
Docs-only PRs do not need T1-T3 to actually run. This supersedes O-22
for docs-only PRs.

**Unchanged:** every other Rule 13 requirement: all 7 approvals at the
current head, and owner acceptance on the PR. The ruling accepts no
PR. PRs that touch code, Nix, CI or config files still need T1-T3 to
actually run and pass at the head (F-357).

**Open scope questions** (CM to the owner via team-lead, 2026-10-24;
proposed answers, pending):
1. Docs-only means only `*.md` under `docs/`, `.claude/memories/` or
   the repo root; any `configs/*.yml` makes a PR not docs-only.
   Added for the owner: does `.claude/team/protocol/*.md` count
   (architect A7)? AE: any `configs/` file, including
   `configs/pipewire/*.conf`, makes a PR not docs-only.
2. A failed (not skipped) job still blocks.
3. A stacked PR with no CI run at all is covered. This differs from
   security's interpretation below ("provided the workflow completes
   with no failures"); the owner's answer to Q3 decides which applies
   (security).

Security's interpretation (2026-10-24): a paths-filter skip is
acceptable for docs-only PRs whose scope the reviewer has verified,
provided the workflow completes with no failures. CM's working
classification: #41, #46 and #47 are docs-only; #44 and #45 are not
(`configs/*.yml`).

Classification is mechanical and per head (AD M1): the CM records
`git diff --name-only` against the merge base at every approved head
and re-classifies whenever the head moves; a stacked PR is classified
on its cumulative diff against main at merge time. A CI skip is never
evidence of docs-only: the filter (`ci.yml:69-81`) is an allowlist of
`src/**`, `nix/**`, `configs/**`, `scripts/**`, `flake.nix`,
`flake.lock`, `.github/**` and `tests/**` (QE N3), so for example
`.claude/settings.json`, `.claude/hooks/**` and `.mcp.json` skip
T1-T3 although they are not docs-only under Q1 (AD).

**Consequences:**
- CLAUDE.md Rule 13 ("CI must be green: T1 + T2 + T3 required before
  merge") and the protocol copy in `.claude/team/protocol/` need the
  exemption; CLAUDE.md is the owner's file, so the edit goes through a
  PR for owner acceptance (TW). `testing-process.md` too, if it
  restates the rule.
- F-357 is rescoped to non-docs-only PRs.
- F-330 (which paths trigger the tests) decides what CI treats as
  docs-only, so it must match the answer to question 1.
