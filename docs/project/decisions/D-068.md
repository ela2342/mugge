## D-068: US-163 local test suites run after the install, not as a pre-erase gate (2026-10-24)

**Status:** ACCEPTED (owner, process override, 2026-10-24; relayed by
team-lead via the CM)

**Context:** US-163 AC22 and test T57 required the local suites
(`nix run .#test-all`, `nix run .#test-e2e`) to pass at the exact
install SHA before the SD card was erased. With CI broken by F-335,
T57 ran on the Pi 5 under Raspbian (`.88`) as CM-T57-88-1, under the
AC22 exception, and was slow and partial.

**Decision:** Owner, verbatim: "I don't think these tests even make
sense to run before the installation." Then, choosing between the
options: "Drop gate, test after install."
- T57 is no longer a pre-erase gate. CM-T57-88-1 was stopped; the
  evidence collected so far is kept.
- The suites run after the install, on the installed NixOS or in the
  Mac linux-builder VM, as part of the US-163 PR's Rule 13 review.
- AC22 and T57 in US-163 are amended to match.

**Unchanged:** Rule 13. All 7 approvals, green CI at the PR head
(T1-T3) and owner acceptance are still required before the US-163 PR
merges. Local evidence does not replace CI.

**Consequences:**
- QE's post-install test plan (P1-P3) replaces the pre-install T57
  run; P1-P3 complete is QE's precondition for its Rule 13 approval.
- The AC22 test-e2e exception for Raspbian `.88` lapsed with the
  wipe; it was never a general rule.
- Owner standing preference (2026-10-24): code suites are not a
  pre-install gate; they run after the install and before the PR
  merges.

**Related:** US-163 (AC22, T57), D-067, F-335, F-365, Rule 13.
