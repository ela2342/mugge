## F-298: D-063 gate-closed E2E test cannot fail — gate-open regression would show green

**Severity:** high (test defect guarding a safety contract; no known safety defect)
**Status:** open
**Found in:** `src/web-ui/tests/e2e/test_gate_closed_e2e.py` (l.51-69 `demo_page` fixture, l.124-137 assert inside `except Exception: pytest.skip`)
**Affects:** D-063 (universal audio gate), US-113 acceptance, US-151, testing-process.md Sec 4.5
**Related:** F-313 (orphaned conf test contradicting D-063), F-314 and F-315 (gate behaviour defects), F-318
**Found by:** quality-engineer (skip audit H1, 2026-10-24); expanded by audio-engineer and architect

### Description

1. `assert not gate_open` sits inside `try ... except Exception: pytest.skip(...)`.
   AssertionError is an Exception, so a real D-063 violation reports SKIPPED.
2. The `demo_page` fixture closes the gate before every test and swallows
   errors from that call. A stack that boots with the gate open would pass
   all four tests.
3. Only the flag and UI text are checked, never the gain nodes or the output
   levels.
4. Wrong tier: the test uses urllib with no browser call, yet sits in `e2e/`.

### Merge condition (audio-engineer, enforced by QE in Rule 13)

**Part A must be merged before the next PR that touches gate, venue-load
or first-boot logic.** PR #22 (US-113) was already merged on 2026-04-06,
so US-113 cannot be accepted until Part A passes on main.

### Acceptance criteria — Part A (highest priority, no stimulus needed)

- **A1.** The `try` covers only `urlopen`. An HTTP or connection error calls
  `pytest.fail`. No assert may sit inside a `try` and no skip is allowed. A
  missing `/api/v1/venue/gate/status` endpoint is itself a D-063 contract
  failure.
- **A2.** `demo_page` stops swallowing errors from its gate pre-close. The
  pre-close is kept only for the UI-element tests.
- **A3 (revised).** Boot-state tests on fresh isolated instances (US-131
  instance-ID isolation, a dedicated fixture, independent of test order and
  `-k`), one for each GM boot path: (a) empty state dir, so the default
  venue `foh-passthrough` auto-loads; (b) a persisted venue; (c) a
  persisted venue that is missing, which falls back to no venue. Each
  asserts `gate_open=false` through BOTH the API and the browser gate
  banner. Boot completion is detected via GM RPC `get_venue` returning
  the expected venue + `has_pending_gains`. Sleeps are never allowed.
- **A4.** Regression evidence (raw output): the test FAILS when the API
  reports `gate_open=true`; the boot-state test FAILS against a stack
  deliberately started with the gate open; plus the green run.
- **A5.** Sweep `test_venue_gate_e2e.py`, `test_config_tab_e2e.py` and
  `test_measurement.py` for the same except/skip and pre-close patterns.
  Fix them or report them as findings.
- **A6 (final).** On each of the three boot paths:
  (i) ALL 8 gain controls read `Mult=0.0`: `gain_left_hp`,
  `gain_right_hp`, `gain_sub1_lp`, `gain_sub2_lp`, and the hp_l/hp_r/iem_l/iem_r
  gains for ch 5-8 (an IEM channel open at boot is a hearing-safety issue).
  (ii) The expected set comes from PipeWire's actual state (pw-dump of the
  filter-chain node), never from GM's gate list. The count is
  cross-checked against the `label = linear` entries in the deployed
  `30-filter-chain-convolver.conf` (8 today). A mismatch, or fewer than 8
  controls found, fails the test.
  (iii) No bypass (revised by architect + AE): asserted at boot AND in
  every mode (standby, DJ, live, measurement), after `await_settled`.
  Scoped by port direction to USBStreamer **playback input** ports only
  (monitor/capture links such as level-bridge are excluded). Every such
  link must originate from the filter-chain output. Links are observed
  independently via pw-dump/pw-link, never through GM's `link_audit` or
  `get_state`.
  Regression evidence: a failing run with one gain control (e.g. `iem_l`)
  non-zero at boot, and a failing run with a stray stream linked to a
  USBStreamer playback port (the WirePlumber/JACK auto-connect case, cf.
  F-318).
- **A7 (static config test; AE merge condition).** Mult=0 at boot comes from
  the filter-chain `.conf` defaults, which PW loads before GM starts, so the
  E2E boot test alone only proves the local-demo conf. Both
  `configs/pipewire/30-filter-chain-convolver.conf` (production) and
  `configs/local-demo/convolver.conf` must have exactly 8 `linear` nodes,
  each with Mult == 0.0 exactly, Add == 0.0 exactly (a non-zero Add sends
  DC through a closed gate), and Mult <= 1.0. Node names must match
  `GAIN_PARAM_NAMES` in `src/graph-manager/src/watchdog.rs:81`.
  Provenance: the test proves mechanically (by parsing
  `nix/nixos/audio/pipewire.nix`, or a nix eval check) that the parsed
  file is the one the image ships (`pipewire.nix:35`). If config
  generation ever replaces copying, the test fails loudly. Runs in
  test-unit or test-all. It replaces the orphaned
  `configs/pipewire/tests/test_filter_chain_config.py` (F-313).
  Mutation evidence: Mult=0.5, Add=0.01, a renamed node, and removing one
  `gain_X:Out` output must each fail it. A7 also absorbs the valid
  assertions of the orphaned conf test (see F-313 for the mapping AC).
- **Fixture review.** The shared fresh-instance fixture (A3, also used by
  the F-313 GM-SIGKILL port) needs QE and architect review before anything
  builds on it.
- **Gate authority invariant (F-320).** After watchdog unlatch, GM restart
  and web-UI MUTE/UNMUTE, assert `gate_open == (any Mult > 0)` (pw-dump).
  Tracked on F-320; it reuses this test infrastructure.

### Acceptance criteria — Part B (follow-up, depends on F-296; does not block merges)

- **B1.** On a fresh boot with the gate closed and the F-296 stimulus at the
  input, the output-side level-bridge meters show silence below a
  threshold that the AE sets.
- **B2.** Regression evidence: the test FAILS when the gate flag reads closed
  but a gain node is non-zero.
