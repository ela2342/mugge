## F-407: Venue gate E2E reports a gate-indicator timeout as a skip, not a failure

**Severity:** unrated (P-level pending, PM)
**Status:** open. Found by the `-rs` skip summary added in PR #64 (F-362)
**Found in:** `src/web-ui/tests/e2e/test_venue_gate_e2e.py:165` and `:180` (`TestGateControls::test_gate_open_close_via_api_reflected_in_browser`), CI run 40333713247 at `f715538e` (2026-10-26)
**Affects:** CI evidence that the browser reflects gate open/close (UX/E2E); gate indicator in the web UI
**Related:** F-362, F-405 (same pattern in `test_gate_closed_e2e.py:137`), F-402, F-406, D-063
**Found by:** quality-engineer (PR #64 skip review)

### Description

The test opens the gate through the API and waits up to 10 s for
`#gate-indicator` to show OPEN, then closes it and waits for CLOSED.
Each step is wrapped in `except Exception: pytest.skip(...)`:

- `:165` skips with "Could not open gate via API" if the venue select or
  gate-open POST fails;
- `:180` skips with "Gate indicator did not update to OPEN — local-demo
  may not propagate gate events via WebSocket" if the indicator times out;
- the CLOSED wait (`:198-201`) has the same skip.

In CI run 40333713247 the `:180` skip fired. The browser reflecting gate
changes is what this test checks, so a timeout is the failure the test
exists to catch (quality-engineer). Reported as a skip, CI stays green
and gives no evidence either way.

### Acceptance criteria

Proposed by the technical writer from the QE's PR #64 ruling; the QE
confirms or amends them.

1. The indicator timeouts (OPEN and CLOSED) are FAILs, or a strict
   xfail that cites this F-ID while the cause is open.
2. The API step at `:165` fails on an API error instead of skipping.
   It may skip only for a named environment limit.
3. Root-cause why the OPEN state does not reach the browser in the CI
   local-demo stack (missing WebSocket `gate_opened` event, or UI not
   updating), and fix it.
4. The `-rs` output of the E2E step shows no skip for this test, and the
   test PASSED.
