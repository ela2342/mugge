## F-342: GM does not enforce D-054 `mode_constraints` / channel budget on `set_mode`

**Severity:** medium (audio-engineer, agreeing with advocatus-diaboli): a credible hearing-injury path, but it needs a 3-way profile, Live mode and an IEM pack on outputs 7-8, and no current gig uses 3-way. **Re-rate to High** as soon as any 3-way profile is used at a gig or rehearsal, or a 3-way profile and an IEM are in use together (AE).
**Status:** open — confirmed by architect (read-only, main); needs a worker (O-8). Architect's pre-3-way-gig condition, doc side: met by #45 HP/IEM Rule 3 and its gaps row once #45 merges (AE, architect); the code fix is still required.
**Found in:** GM `handle_set_mode` (`src/graph-manager/src/rpc.rs:536-597`) only parses the mode string and forwards it; `SetMode` (`src/graph-manager/src/main.rs:528-549`) sets `current_mode`, the quantum and reconciles. No profile, constraint or budget check; "mode_constraints" does not appear in `src/graph-manager`. The only references are in `src/web-ui/app/speaker_routes.py` (schema validation l.299-306, advisory check-mode l.717, l.800), and nothing in the set_mode path calls them (`mode_manager.py:263`).
**Affects:** D-054, Live mode on 3-way profiles, singer IEM (ch 7-8)
**Related:** D-054, D-063, US-159 (same refusal pattern as G7), O-10, O-11, F-160 (restore flow bypasses the web UI), F-340 (AC6), PR #44 (AD L2)
**Found by:** advocatus-diaboli (2026-10-24, answering #44 L2); confirmed by architect

### Description

On 3-way layouts GM intentionally omits the IEM links: `routing.rs:602-616`
(Live) creates the Reaper IEM -> convolver links only if
`num_speaker_channels + 4 <= 8`, and skips them silently (no log). This is
D-054's channel budget; `configs/speakers/profiles/workshop-c3d-elf-3way.yml`
(:23, :92-95) says "no IEM channels — live vocal mode blocked" and declares
`mode_constraints: [dj, standby]`.

Nothing enforces that block. Live mode on a 3-way profile is accepted; GM
builds Live routing with the HP links on convolver/USBStreamer ch 7-8
(`routing.rs:586-600`), the singer-IEM outputs in the standard channel map,
and drops the IEM links. If an IEM transmitter is cabled to outputs 7-8,
the singer gets the engineer's HP feed at HP gain (no limiter, O-11). The
web-UI check is advisory and is bypassed by any direct RPC client,
including the F-160 restore and measurement flows.

Mechanism (AE): HP and IEM are both unity, so there is no gain step at the
switch. The hazard is control and destination mismatch: when the engineer
raises "their headphones" (HP send or fader, monitored loud), they raise
the singer's IEM, with no limiter and full scale reachable, and no
feedback that it is the singer's ears; the singer's real IEM mix is
silently dropped. On 3-way, DJ mode also puts HP on AUX6/7 by design, so
an IEM connected to outputs 7-8 on a 3-way rig gets the HP feed even
outside Live.

Scope limit (AD): enforcing the mode constraints prevents Live on 3-way;
it does not protect an IEM cabled on outputs 7-8 in 3-way DJ mode (DJ is
an allowed 3-way mode and puts HP on convolver ch 7-8 by design,
`routing.rs:492-507`). That case needs the AE's interim rule (no IEM on
7-8 with a 3-way rig) and, longer term, the O-11 limiter.

Interim rule (AE; status.md interim rule 8 = safety.md §10 HP/IEM Rule 3,
PR #45 `af0c6c93`): "With a 3-way speaker profile active: no Live mode, and
nothing connected to ADA8200 outputs 7-8 except engineer headphones."

### Acceptance criteria (architect)

1. The refusal is in GraphManager's set_mode, not only the web UI (a web-UI
   check is bypassed by any other RPC client). GM (`handle_set_mode` or the
   PW-thread `SetMode` handler) refuses any
   mode not in the active profile's `mode_constraints`: `RpcResult::Error`
   with a reason string, and nothing mutated (no `current_mode` change, no
   quantum change, no reconcile).
2. Profiles without `mode_constraints`: GM derives the allowed modes from
   the channel budget (`num_speaker_channels + 4 <= 8` for Live, as
   `speaker_routes.py` already does for the advisory check) and refuses
   accordingly (AD, architect); IEM links are
   never silently omitted (see AC6).
3. `set_venue` or a profile switch never leaves GM in a mode the new
   profile disallows: the switch is refused (architect's preference,
   consistent with US-159 G7) rather than forcing standby.
4. The web UI shows GM's refusal reason.
5. Tests: `set_mode(live)` on `workshop-c3d-elf-3way` gives an RPC error,
   creates no links and leaves the quantum unchanged; `set_mode(dj)` on
   the same profile is accepted; a 3-way profile with no `mode_constraints`
   also refuses `set_mode(live)` (AD). In Live, no link from an HP source
   lands on AUX6/7 (AE). Links are checked with `pw-link`, not GM state
   (QE). Enforcing `mode_constraints` alone does not close the 3-way DJ
   exposure on outputs 7-8 (AD); that stays covered by safety.md §10
   HP/IEM Rule 3 until AC7/AC8 land.
6. (AE) Dropping the IEM links (`routing.rs:606-616`) becomes a loud error
   in any mode where IEM links are expected; no silent degradation.
7. (AE) GM refuses any mode, profile or venue combination that would put a
   non-IEM feed onto the IEM outputs while Live is requested.
8. (AD) With a 3-way layout active, GM logs which physical outputs carry
   HP, in every mode.

Design note (architect): GM has no view of `mode_constraints` today, only
the routing table. The constraint list reaches GM through the same channel
as the profile/venue load: a small schema addition, no new authority.
