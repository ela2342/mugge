## F-333: T3 (SD image build) not part of PR CI — no PR can meet "T1+T2+T3 green"

**Severity:** high (process; Rule 13 gate unmeetable through CI)
**Status:** open — owner decision O-26
**Found in:** `.github/workflows/ci.yml:18-19` (image build moved out), `.github/workflows/release.yml:14-15` (assumes T3 green on the PR)
**Affects:** Rule 13 (T1+T2+T3 required before merge), every PR since the change
**Related:** F-330 (paths filter), F-329 (no durable evidence); owner ruling O-22 (a skip is not green)
**Found by:** quality-engineer (2026-10-24)

### Description

The SD image build (T3) was moved from PR CI to the tag-triggered
`release.yml`. `release.yml` assumes T3 already passed on the PR, but PR CI
never runs it. Under the O-22 ruling (a skip is not green), no PR has met
"T1+T2+T3 green" through CI since that change.

### Options (owner decision O-26)

- (a) Manual T3 dispatch per PR.
- (b) T3 back in PR CI for PRs touching `nix/`, `flake.*` or `configs/`.
- (c) Reword Rule 13 so T3 is a release gate, not a PR gate.

QE recommends (b), with (a) as the interim.

### Acceptance criteria

1. The chosen option is implemented, and CLAUDE.md Rule 13 and
   testing-process.md match it.
2. One PR (or dispatch) shows T3 actually running green on its head.
