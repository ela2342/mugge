## F-326: Invalid GITHUB_TOKEN in environment blocks all gh/PR operations

**Severity:** medium (tooling; blocks Rule 13 PR flow and PR-state verification)
**Status:** open — owner action
**Found in:** owner shell environment (`GITHUB_TOKEN`)
**Affects:** PR opening for `chore/tracking-resync`, `docs/doc-drift-repo-path`, `chore/remove-broken-playwright-mcp`, `docs/safety-d063-gate`; verifying states of PRs #2–#35; CI-log evidence for US-142–149, F-256, F-272
**Found by:** change-manager (2026-10-24)

### Description

GitHub rejects the `GITHUB_TOKEN` environment variable with `401 Bad
credentials`. gh uses that variable before any stored credentials, so the
owner's `gh auth login` had no effect. A stored gh login exists for
`andreasdotorg`, the account the earlier PRs came from, but the bad token
overrides it. Change-manager did not use it because it is a different
identity.

### Owner options

(a) Remove or refresh the stale `GITHUB_TOKEN` in the shell profile, then
restart the session. (b) Authorize gh/git without `GITHUB_TOKEN`, i.e.
acting as `andreasdotorg`. (c) Push over SSH as `ela2342`; PRs are then
opened in the browser or with a valid token. Pushing to `ela2342/mugge`
still needs checking once a route works.
