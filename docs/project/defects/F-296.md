## F-296: Tests that need audio stimulus have no stimulus source in local-demo

**Severity:** medium
**Status:** open
**Found in:** `src/web-ui/tests/service-integration/test_mute_e2e.py:89`, `src/web-ui/tests/service-integration/test_tf_backend_integration.py:165`, `src/web-ui/tests/e2e/test_transfer_function.py:136`
**Affects:** xfail budget (testing-process.md Sec 9.2), F-270 (misattributed)
**Found by:** quality-engineer + architect (xfail audit, 2026-10-24)

### Description

The three tests above are xfailed with reason text citing F-270. F-270 was
resolved in PR #21 with a different root cause (missing capture-usb
pcm-bridge). The actual cause of these failures is that no audio stimulus is
present in local-demo, so there is nothing to measure.

### Fix (agreed by QE and architect)

- Opt-in pytest fixture that drives signal-gen via its real RPC at a
  conservative level, with teardown. Not a stimulus that is on by default.
- Replace the sleep-based wait in `test_mute_e2e` with polling.
- Repoint the three xfail markers to F-296, then remove them once the
  fixture lands. Deterministic xfails must be `strict=True` meanwhile.

### Sequencing (2026-10-24)

Moved ahead of the F-262 diagnosis: F-298 Part B (silent output meters
with the gate closed) depends on this fixture.
