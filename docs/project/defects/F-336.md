## F-336: Real-Pi browser tests unusable — wizard T4 ignores PI_AUDIO_URL; monitor suite always skipped in CI

**Severity:** medium (technical-writer; QE to confirm). Test gap before owner UAT; no safety impact.
**Status:** open
**Found in:** `src/web-ui/tests/integration/test_measurement_wizard.py` (always uses the session-scoped mock server via the conftest `page` fixture); `src/web-ui/tests/conftest.py:338` (`pi_url` fixture, used only by `test_monitor_e2e.py`)
**Affects:** test-strategy.md §5.4, §6, §6.2 ("T4 real, before owner UAT"); measurement wizard acceptance
**Related:** F-312 (no central REQUIRE_STACK guard; the monitor-suite skip is the same pattern)
**Found by:** technical-writer (test-strategy drift review, 2026-10-24); widened by quality-engineer

### Description

test-strategy.md says T4 UX acceptance runs against the real Pi with
`PI_AUDIO_URL=https://192.168.178.185:8080 pytest tests/integration/test_measurement_wizard.py`.
The wizard tests always use the mock server, so setting `PI_AUDIO_URL`
just runs the mock tests again. The "T4 real, before owner UAT" step in
the test matrix cannot be executed.

The reverse also holds (QE): `test_monitor_e2e.py` sits in
`tests/integration/` and runs in CI through `test-integration-browser`,
but every test in it skips whenever `PI_AUDIO_URL` is unset
(`conftest.py:338-342`), which is always the case in CI. A permanently
skipped suite inside a CI target.

### Acceptance criteria

1. With `PI_AUDIO_URL` set, the wizard tests run against that URL (or the
   test strategy is changed to name a different real-Pi T4 route, QE).
2. Without it, the tests still run against local-demo or the mock, and the
   run states which target it used.
3. test-strategy.md placeholders (branch `docs/test-strategy-drift`)
   reference F-336.
4. `test_monitor_e2e.py` either runs against local-demo in CI or moves out
   of the CI target into an explicit real-Pi run; it never skips silently
   inside a CI target (F-312).
