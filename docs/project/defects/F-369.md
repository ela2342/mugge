## F-369: Pi 5 FAT keep set collapses to one generation after a no-op deploy

**Severity:** high (quality-engineer finding; PO ruling 2026-10-25)
**Status:** resolved in US-163: fixed in `96b4246c` + `b9e8974e` (story/US-163); AC18b, AC18c and T54b PASS at CM-DEP-.89-3. Open for the PR review: the CI log shows pi5-prune-gens "13/13 cases passed" (QE)
**Found in:** `nix/nixos/boards/pi5/bootloader.nix` (generation prune step)
**Affects:** US-163 AC2a (operator rollback to an earlier generation via the one-line SD edit), T54
**Related:** US-163 (AC2a, AC18a-c, T54, T54b), F-370, D-069
**Found by:** quality-engineer (US-163 AC18a, 2026-10-25)

### Description

The bootloader hook kept the generation set {new, prev, booted} on
the FAT. After a repeat or no-op deploy those three are the same
generation, so the prune left only one. After AC18a only `nkifli3r`
was on the FAT and `x83m7bir` survived in the store only, so the AC2a
one-line SD rollback had no second generation to point at.

PO: AC2a means at least 2 complete generations on the FAT, always, as
soon as 2 have ever existed. It protects operator rollback to an
earlier generation, not only recovery from a failed new boot: a
generation that boots can still prove bad later (audio, Mixxx, at a
gig).

### Fix

The keep set becomes {new, prev, booted, alt}, where alt is the
highest-numbered `system-*-link` id other than new whose
`gens/<id>/.complete` exists. Keep only, never recreate (architect).
The MAP.txt write moved into the prune-gens script, with the MAP
format and location unchanged. The pointer write, boot selection and
FAT layout are byte-for-byte unchanged.

An offline check, `nix/checks/pi5-prune-gens.nix` (pure bash
runCommand, no VM), runs the hook's exact script on fake `gens/`
directories and profile links: 13/13 cases, including the no-op
collapse, an unbooted pointer, an unlinked booted generation,
idempotence and empty prev/booted. CI builds
`checks.x86_64-linux.pi5-prune-gens`. Pi 4 drvPaths unchanged;
board-guard (107/107) asserts the hook calls the tested store path.

Reviews: architect APPROVE `96b4246c` and `b9e8974e`; QE ACCEPTED
both (test adequacy).

### Acceptance criteria

1. At least 2 complete generations stay on the FAT after any deploy,
   including a no-op, once 2 have existed; the booted one is among
   them. Done (AC18c PASS).
2. Rollback to the other generation and back works (T54b PASS).
3. The offline check runs in CI and the log shows "13/13 cases
   passed" (open, PR review).
