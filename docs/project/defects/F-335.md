## F-335: CI T1 fails on main before any test runs — test-all cannot cd into src/web-ui in the flake source

**Severity:** critical (quality-engineer: blocks every merge). Architect and team-lead: high. Same impact either way.
**Status:** open — probable cause found; needs a worker (O-8)
**Found in:** `nix run .#test-all` in CI (cd into `<flake source store path>/src/web-ui`: "No such file or directory")
**Affects:** Rule 13 (CI green), O-22, every PR including #41-#43, the QE Gate 1 evidence run (F-256, F-272, US-142..153)
**Related:** F-329 (no durable CI evidence), F-330 (paths filter skips tests), F-333 (T3 not in PR CI); O-22
**Found by:** change-manager and quality-engineer (dispatched T1 runs for O-22, 2026-10-24)

### Description

`test-all` fails before any test runs: it cannot cd into `src/web-ui` in
the flake source store path. Dispatched runs 40099078614 (PR #42) and
40099080404 (PR #43) are main plus docs-only changes (`c34f7da7`), so the
defect is on main. Logs: `/tmp/mugge-ci-logs/dispatch-*` (dev machine).

Root cause (architect + QE, 2026-10-24): `flake.nix` uses
`${toString ./.}` at 29 sites (test apps l.398-714, including `REPO_DIR` /
`LOCAL_DEMO_REPO_DIR`). `toString` drops string context, so the test-app
derivations have no dependency on the flake source store path. Older Nix
copied the whole flake source into the store eagerly during eval, so the
path existed by accident. Nix 2.35.0 introduced lazy copying of flake
sources (upstream release notes rl-2.35), and CI drifted to 2.35.4 because
`cachix/install-nix-action@v31` is unpinned. The path is never realised:
in run 40099078614 its hash appears only in the cd error line. Also affects
T2 (`test-e2e.sh:132` via `LOCAL_DEMO_REPO_DIR`) and any developer machine
on Nix >= 2.35. Not a repo regression: a latent flake bug exposed by
environment drift. Probable, not confirmed: not reproduced on an older Nix (optional confirmation:
dispatch with Nix pinned to a pre-2.35 version).

Fix (architect): `${self}` at all 29 sites, plus pinning AND logging the
Nix version in `ci.yml` (both install steps, l.101 and l.131) and
`release.yml:83`. Pinning alone is not acceptable.

Security note (security-specialist): pin `cachix/install-nix-action` to a
full commit SHA, not a version tag (a floating `@v31` tag is how this
drift happened, and a tag can be moved), and pin the Nix version
explicitly. The fix PR touches CI workflows: security reviews it.

### Impact

- No PR can get a green T1, so all merges are blocked, #41-#43 included.
- CI on main is unverified since an unknown point.
- The Gate 1 evidence run (F-256, F-272, US-142..153) is blocked.
- Under the old skip rule, docs PRs would have kept merging "green" while
  main's tests could not run at all (F-330). This is the case O-22 guards.

### Acceptance criteria

1. All 29 `${toString ./.}` sites replaced with `${self}`.
2. No `toString ./.` remains outside the `cleanSourceWith` filter lines
   (`flake.nix` 175-178, 752-755).
3. Nix version pinned AND logged (`nix --version` in the CI log) in
   `ci.yml` (both install steps) and `release.yml`; `install-nix-action`
   pinned to a full commit SHA.
4. Dispatched T1 and T2 green on main, with every `test-*` step run and
   pytest summaries shown. The E2E stack actually started (T2 dispatched
   with `run_e2e`, stack-up logs shown).
5. Each Rust crate actually compiles and runs a non-zero number of tests
   (the source filters are a lazy-trees risk; fall back to `lib.fileset`
   if they select nothing).
