## F-347: Config tab shows phantom -60 dB sliders and hides the real gains under a generated N-way convolver config

**Severity:** medium (audio-engineer). Static evidence only, not reproduced at runtime. A not-found gain falls back to 0.001, which shows as non-zero: that fails toward "looks live", so step 9 keeps the amps off rather than giving false comfort; Apply is banned by Rule 11; #10 is authoritative. The harm is that the operator can't see the real gains (AE). The underlying gate defect is F-348.
**Status:** open — confirmed by quality-engineer (code read); needs a worker (O-8)

### Description

`config.js` iterates a fixed list, `GAIN_NODES`, which holds the 8 2-way
names. The line `info = gains[name] || {}` gives a name the backend didn't
return mult 0.001 (-60 dB), and `found` evaluates to true. So the slider is
enabled, with no missing styling.

The GET endpoint returns the `gain_*` params the convolver actually has.
Profile activation writes the generated config to the production file
`30-filter-chain-convolver.conf`. `channel_suffix` maps only `sat_left`,
`sat_right`, `sub1` and `sub2`; unknown keys pass through unchanged. The
3-way workshop profile uses `sub_left`, `sub_right`, `mid_left`,
`mid_right`, `hf_left` and `hf_right`. Its gains would therefore be named
`gain_sub_left` and so on, and the UI never displays them.

The operator sees plausible "-60 dB" rows that don't exist and none of the
real channels, so a non-zero real gain would be invisible. Apply would POST
the 2-way names; the effect on missing nodes is unverified.

An open question for the architect, not numbered yet: under a generated
3-way config, does GM `close_gate` (`main.rs:824`) find and zero the
generated gain names? If it zeroes by fixed name, the D-063 gate is not
effective for N-way.

### Acceptance criteria

1. The UI renders the `gain_*` names the backend returns, not a fixed list.
2. A name that isn't returned renders as missing or disabled, never as an
   enabled -60 dB slider. The 0.001 fallback is removed.
3. A browser E2E test against a generated 3-way config asserts the
   displayed names and values against pw-dump (independent oracle).
4. Mutation evidence: restoring the fixed list makes test 3 fail.
