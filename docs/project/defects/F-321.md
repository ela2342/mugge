## F-321: Venue `coefficients` field is not enforced at runtime — all venues share the last-deployed WAVs (dirac on a fresh image)

**Severity:** high, affects all venues (audio-engineer)
**Status:** open
**Found in:** GM (the `coefficients` field is read only in a test, `venue.rs:927`); PW conf hardcodes `/etc/pi4audio/coeffs/combined_*.wav`; `nix/nixos/audio/pipewire.nix:95-98` seeds those files as dirac copies
**Affects:** US-155, US-113, D-031, D-055, US-127 (D-053 runtime coefficient switching)
**Related:** F-271 (protection WAVs missing for ch 1-4; architect/AE to decide whether this is the same root cause), F-314, F-322
**Found by:** audio-engineer (US-155 retroactive review, 2026-10-24); product-owner raised the shared-filename risk in US-155 AC4

### Description

`production.yml` and `markaudio-ultimax-200hz.yml` use the same filenames
for different crossover designs. The "200 Hz crossover" exists only if
someone generated and copied the WAVs by hand, and whatever was deployed
last applies to every venue. A fresh image applies dirac (no crossover) to
every channel.

Example from the CHN-50P (Xmax 3.5 mm, Bl 2.71, Re 3.4, K_total ≈ 2 kN/m):
full-band input reaches Xmax at about 8.6 V peak, roughly -17 dB re amp
full scale. That is safe at the venue's -60 dB. With a dirac placeholder,
any mains gain above about -17 dB over-excurses the driver.

### Fix direction (AE)

Per-venue coefficient sets applied on venue load, and/or GM refusing to
open the gate when a channel with `mandatory_hpf_hz` or a crossover role is
loaded with an identity (dirac) or mismatched WAV. Verify by hash or
sidecar metadata.

### Interim operator rule

Rule 4: don't run the CHN-50P rig until its 200 Hz filter files are
verified on the Pi.
