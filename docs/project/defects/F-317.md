## F-317: RT throttle disabled (sched_rt_runtime_us=-1) with no configured watchdog backstop

**Severity:** medium (availability; security-specialist). Fix before the next gig. **Blocks the next release image** (architect + security, 2026-10-24).
**Status:** open
**Found in:** `nix/nixos/rt-tuning.nix` (commit `991ff456`, F-291 fix)
**Affects:** F-291, D-013, remote recovery during a gig
**Related:** F-325 (watchdog not configured; promoted from the CLAUDE.md TODO), F-291, F-295
**Found by:** security-specialist (retroactive review of `991ff456`, 2026-10-24)

### Description

The code comment's reasoning is wrong. On PREEMPT_RT, IRQ handlers run as
FIFO-50 threads, below PipeWire (88) and GM (80). A runaway RT thread with
no throttle starves its core's IRQ threads, kworkers, sshd and the web UI,
so remote recovery is impossible during a gig. The "watchdog backstop" the
comment relies on is not configured: `nix/` has no
`systemd.watchdog.runtimeTime` or equivalent, only the kernel driver.

### Asks

1. Evidence that the 95% throttle actually caused the F-291 xruns (a thread
   using >95% of a core is already over budget).
2. Consider `990000` instead of `-1`.
3. Configure the hardware watchdog for real, and test it.

Not a retroactive veto.

### Architect analysis (2026-10-24), security concurs

1. The `rt-tuning.nix` rationale has PREEMPT_RT semantics backwards: a
   runaway FIFO-88 task does starve IRQ threads (FIFO 50) and all
   SCHED_OTHER work, including sshd.
2. The watchdog failed on 2 of 11 lockups, is not configured at all (F-325),
   and a watchdog reboot causes a USBStreamer transient.
3. The F-291 diagnosis is suspect: healthy PW cannot reach the 95%
   throttle, so some RT thread was burning a core. The F-295 Mixxx RT change
   landed in the same commit (`991ff456`) and may be the cause. If so, the
   fix is CPU placement, not unlimited RT.

**Recommendation (architect, security):** revert `sched_rt_runtime_us` to
950000 (or a bounded relaxation such as 980000) until F-291's root cause is
found. Severity stays MEDIUM.

### Acceptance criteria

1. The misleading `rt-tuning.nix` comment is corrected.
2. The hardware watchdog is configured and tested (F-325).
3. Root-cause evidence for F-291 from a CM OBSERVE session.
4. `sched_rt_runtime_us` reverted to default or a bounded value, unless (3)
   justifies otherwise with AE + security sign-off.

### Audio-engineer note (2026-10-24)

The hardware watchdog is not a speaker-safety backstop: a watchdog reboot
resets USB, which is the documented USBStreamer transient, with the amps
on. It is still worth configuring for availability, since the gate is
closed on boot. The owner decides that tradeoff (O-24), and safety.md must
document the transient (technical-writer).
