## F-317: RT throttle disabled (sched_rt_runtime_us=-1) with no configured watchdog backstop

**Severity:** medium (availability; security-specialist). Fix before the next gig.
**Status:** open
**Found in:** `nix/nixos/rt-tuning.nix` (commit `991ff456`, F-291 fix)
**Affects:** F-291, D-013, remote recovery during a gig
**Related:** CLAUDE.md watchdog TODO (BCM2835 watchdog failed 2 of 11 lockups)
**Found by:** security-specialist (retroactive review of `991ff456`, 2026-10-24)

### Description

The code comment's reasoning is wrong. On PREEMPT_RT, IRQ handlers run as
FIFO-50 threads, below PipeWire (88) and GM (80). A runaway RT thread with
no throttle starves its core's IRQ threads, kworkers, sshd and the web UI,
so remote recovery is impossible during a gig. The "watchdog backstop" the
comment relies on is not configured: `nix/` has no
`systemd.watchdog.runtimeTime` or equivalent, only the kernel driver.

### Asks

1. Evidence that the 95% throttle actually caused the F-291 xruns (a thread
   using >95% of a core is already over budget).
2. Consider `990000` instead of `-1`.
3. Configure the hardware watchdog for real, and test it.

Not a retroactive veto.
