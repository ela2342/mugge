## F-403: Session IR is computed against the session's own sweep, not the one signal-gen plays

**Severity:** High (audio correctness, core room-correction path; fails closed, no speaker or ear hazard)
**Status:** open. F-262 (PR #66) keeps the browser E2E xfail and points it here (f8a014c7 R3). R4 ruled (audio-engineer 2218daf5): Sub1 is a room-sim fixture fix (B1); the mock-room Left under-correction is a separate defect, new F-number via the PM (B2)
**Found in:** `src/web-ui/app/measurement/session.py:785-787` and `:829-834` at `e7afdb36` (the sweep loop builds its own `generate_log_sweep` array and deconvolves against it; the comment at :834 notes "F-403 S2 will deconvolve against the played array"). Found by worker-4 during F-262 c8 (ruling request 0e25d355)
**Affects:** closed-loop verification of measured corrections, mainly the subwoofer channels; the browser measurement E2E test
**Related:** F-262 / PR #66; audio-engineer rulings f8a014c7 (R1, R3, R4, R5), a8386f4b (F2, F4), f277e402 (C1-C3), b74d437e (severity) and 2218daf5 (R4 branches); QE c8 answers abfd33d7 (Q1, Q2)
**Writer:** technical-writer (CM and PM allocation, per abfd33d7 Q2; f8a014c7 R4 as read in f277e402 item 2 allows it)
**Owner:** S2 investigation and fix: PM and QE allocate it (f8a014c7 R4)

### Severity ruling (audio-engineer, b74d437e, verbatim)

Reasons:
- Production code, not only a test: src/web-ui/app/measurement/session.py:829-834 builds the impulse response against the session's own
  sweep array, not the array signal-gen plays. The correction filter is built from that IR. That the two arrays differ is a code fact;
  only how big the effect is remains a hypothesis (offline model).
- It blocks the core priority (owner, 2026-10-26: room correction before safety edges). The browser session ends in ERROR on Sub1, and
  with the session-sweep reference no measured sub correction is trustworthy.
- Not Critical: it fails safe. The F-262 closed-loop gate refuses the filter (no filter, never a wrong filter). The correction is
  cut-only and trimmed by D-009, so a wrong IR cannot raise any gain.
Re-rating: if S2 (played-sweep reference) shows the mismatch changes no result beyond 0.5 dB on real hardware, the AE drops it to Medium.
The near-limit residual (R4 data) is separate. If the cap is not reached, it becomes its own F-number, as R4 says.

### Cause

**VERIFIED** (code fact, audio engineer b74d437e): the session computes
the impulse response against its own sweep array, while signal-gen
plays a different one, and the correction filter is built from that IR.

**HYPOTHESIS** (offline model only): how big the effect is. Against the
played sweep (S2), Sub1 passes in the model. This has not been verified
in local-demo or on real hardware.

S2 alone does not close F-403. With S2, Sub1 passes by 0.01-0.03 dB and
the mock-room Left by 0.03 dB. Local-demo runs through the real PipeWire
graph with run-to-run timing and noise variation, so a 0.03 dB margin
cannot meet 10 consecutive passes (f8a014c7 R4). Offline home_lab Sub1
corrects to +0.91 dB, so about +2.97 dB in local-demo is not normal
correction quality and needs its own explanation (R4 data, below).

Also tracked here (a8386f4b F4): about 0.65-0.76 s of extra path latency
is real. A constant post-roll (`post_roll_s=2.0`, F-262) is not its fix.

### R4 branch ruling (audio-engineer, 2218daf5, verbatim)

Alignment: no defect. Onset = played_onset in every case, and SNR is 48-65 dB. Alignment is ruled out as the cause in both branches.

B1 Sub1 (local-demo model): CAP BRANCH, a test fixture issue.
   - The sim mode at 42.4 Hz is +21 dB. The cut is capped at 18 dB, which leaves 21 - 18 = +3 dB. The pipeline works as designed.
   - Fix in the local-demo room sim (scripts/generate-room-sim-ir.py), never in MAX_CUT_DB or MAX_POSITIVE_DEVIATION_DB (f8a014c7 R1).
     The deepest mode inside the gated band must be at most 15 dB over target, so the cap is not reached and a fully corrected mode
     leaves room for the R5 0.5 dB margin.
   - Product note (PM backlog, AE, not F-262): a real room with a mode more than 21 dB over target fails the closed-loop gate, so the
     channel gets no filter. That is the fail-safe direction and correct for now. A future "partial correction" verdict is a design
     question, not a defect.
B2 Mock-room Left: NO-CAP BRANCH, a correction defect suspected. New F-number via the PM.
   - The room is +3.95 dB over target at 272.6 Hz (1/6-oct, the gate's view), but the FIR cuts only 0.71 dB there. The cap is far away
     and alignment is clean, so the correction under-corrects a 4 dB peak and lands 0.03 dB inside the gate limit.
   - Suggested title: "Correction under-corrects near the closed-loop band edge (mock-room Left, 272.6 Hz: room +3.95 dB, FIR -0.71 dB)".
   - Severity: Medium (audio correctness; fails closed, no hazard). The investigation compares the correction's own smoothing and
     windowing view with the closed-loop 1/6-oct view at 250-300 Hz. If the two disagree by design, the AE rules which view is right
     before any code change.
   - Fixed: the 3.0 dB limit, the 18 dB cap and the 1/6-oct gate smoothing are not changed to make this pass.
Effect on F-262:
   - The browser xfail stays (f8a014c7 R3).
   - Its removal later needs S2 + B1 fixture fix + B2 resolved, and then the R5 10-run AC.
   - The API test (Left, session sweep, +1.92 dB) is not affected by this ruling.

The B2 defect has no F-number yet (PM). The B1 product note is a PM
backlog item, not part of F-403.

### Fixed constraints

`MAX_POSITIVE_DEVIATION_DB` stays 3.0 dB and `MAX_CUT_DB` stays 18.0 dB
(f8a014c7 R1). No test, xfail or local-demo path may use a looser limit

### Acceptance criteria

1. R4: done. The data is collected (41c33bbb) and the audio engineer
   has ruled (2218daf5).
2. A test plan for the S2 fix. It includes at least one deterministic
   unit or integration test that does not depend on local-demo, fails
   today, and proves the IR reference is the played sweep.
3. When S2 lands (the session reference is the played sweep), the 30 dB
   SNR floor is reinstated on the session-reference IR as well
   (a8386f4b F2).
4. B1: the local-demo room sim (`scripts/generate-room-sim-ir.py`) is
   fixed so that the deepest mode inside the gated band is at most 15 dB
   over target. `MAX_CUT_DB` and `MAX_POSITIVE_DEVIATION_DB` are not
   changed (2218daf5 B1).
5. B2: the separate under-correction defect (PM F-number) is resolved.
6. The browser xfail is removed only after S2, B1 and B2 are done
   (2218daf5), and the f8a014c7 R5 10-run AC then passes for the browser
   test at the head that removes it, under the QE's abfd33d7 Q1 rules
   and the audio engineer's f277e402 conditions:
   - 10 CI runs at that one head, each with its checkout sha equal to
     the head. The CM keeps a dispatch ledger (run id and conclusion, in
     order).
   - No drops, no cancellations to hide a result, and no reruns. A red
     run ends the series: the xfail goes back, and the result is a
     finding. A run that fails before the local-demo stack's first
     step is logged and ruled void by the QE, never silently left out.
   - Every run shows the browser test PASSED, and prints one
     `F-262-AC ch=… max=… band=…` line per measured channel. A run with
     a missing line is void.
   - A missing closed-loop value (`None`, from an early FAIL path) counts
     as a run FAIL, never as a skip (f277e402 C1).
   - The pass assert uses the unrounded value, or `closed_loop_pass`
     together with the value, so rounding to 0.01 dB never turns
     3.004 dB into a pass (f277e402 C2).
   - Every channel is at or below 3.0 dB in all 10 runs, and the worst
     run is at or below 2.5 dB (margin at least 0.5 dB). A 10/10 pass
     with a margin under 0.5 dB counts as UNSTABLE, which is a finding
     (f277e402 C3).
   - Evidence for the PR: the ledger, the frozen per-run AC lines, and
     min/max/spread per channel, which the QE recomputes.
