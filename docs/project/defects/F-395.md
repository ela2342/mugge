## F-395: Gains readback is blind on a suspended filter-chain node, so the gains check gives a false PASS

**Severity:** P1 (audio-engineer)
**Status:** open. ACs (a) and (b) implemented and selftested in the Gate-2 r7 sandbox build (gate2.py, worker-3), not yet merged; AC (c) list complete and annotated (2026-10-26); AC (d) waits for the Pi step 1 OBSERVE
**Found in:** Gate-2 r6b sandbox, case (ii-c) (2026-10-26); the gains readers `pw-cli enum-params` and `pw-dump`
**Affects:** every gains check that proves "muted" from a readback: safety.md check 10 (Gains at boot), D-070 rows 14-15, gate2.py, past gains PASS records
**Related:** D-063, D-070 (rows 14-15), F-396, F-397, US-176, F-373
**Found by:** Gate-2 r6b sandbox run; rated by audio-engineer (owner) and architect (co-owner), joint r6b ruling and Addenda 1-2 (2026-10-26)

### Description

On a suspended node, the gain readers return 0, not the stored value.
In Gate-2 r6b (ii-c), a conf default of 0.25 read `0.000000` while the
node was suspended, in all 4 stacks, yet the audio proved that 0.25
was applied. `0.000000` is the PASS value of the gains check (D-063),
so the false PASS is in the dangerous direction: a "0" reading does
not prove "muted" for a suspended node.

Other r6b results: a set made while the node is suspended applies after
the resume (ii-a); boot 0, then resume, is silent (ii-b). Live readback
is proven in the sandbox for nodes that are idle or running.

### Acceptance criteria

- (a) gate2.py counts a reading only when the filter-chain node and
  its output node are idle or running, from the same pw-dump snapshot.
  The state is taken immediately before and after the enum-params read;
  both must be idle or running, and a change between them counts as
  NOT VERIFIABLE. NOT VERIFIABLE is reported as FAIL (exit 2 at step 0,
  nothing played; exit 3 STOP at cleanup) with the reason "gains not verifiable: <node> state <before>/<after>", and is
  never exit 0 and never retried into a PASS. enum-params stays the only PASS source
  (B1).
- (b) selftest mutations, each with a reason check: a never-run
  suspended node with conf Mult 0 and with conf Mult 0.25 is NOT
  VERIFIABLE; a node that has run (idle) with Mult 0 is PASS and with
  runtime Mult 0.5 is FAIL; a state change between the two reads is
  NOT VERIFIABLE; the existing set-param probe on the suspended node is
  NOT VERIFIABLE. Sandbox evidence: Gate-2 r7, G1-G5 PASS, G2 logs the
  old reader as blind ("values alone pass").
- (c) every past gains PASS recorded without the node state is marked
  NOT VERIFIABLE (not FAIL: the conf defaults were 0 at the time). The
  QE's list has 13 entries: 8 in `docs/lab-notes/US-163-pi5-bootstrap.md`,
  4 in `docs/project/stories/US-163.md` (AC14, AC16b/AC17-B, AC17, AC19)
  and the F-373 interim recovery procedure. Each carries an append-only
  dated line. They are re-run under the new rule at the next Pi gains
  check: one read per context, node state logged before and after,
  after boot, after a PipeWire restart, after a cold power cycle, after
  a WirePlumber restart, and after the F-373 recovery if it differs
  from a plain PipeWire restart. A context where the OBSERVE shows the
  chain suspended or never run waits for US-176 or F-396 and is not a
  FAIL meanwhile. The read-only check after the owner's US-172c
  recovery power cycle counts as the cold-power-cycle read and as the
  step 1 OBSERVE "right after boot", if it is the first session on the
  graph after boot (AE ruling 2026-10-26).
- (d) Pi step 1 OBSERVE of the node states (at idle and right after
  boot), then the amended P-a.

Interim rule (Addendum 1 B, as amended by the joint r7 exit-code
ruling): fail closed, no wake mode. Gate-2 exit codes 2 and 3 include
NOT VERIFIABLE. If the Pi
chain is suspended or never run at boot, Gate-2 cannot pass until the
canary (US-176) or the no-suspend fix (F-396) lands.

Interim safety text: D-070 rows 14-15 and safety.md check 10 (F-318
docs batch, AE wording).
