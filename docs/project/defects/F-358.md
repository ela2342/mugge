## F-358: Three fixes recorded in #40's original records are missing on main (F-291 RT fix, F-295 period-num, D-065 convolver always-process)

**Severity:** medium (architect, AE); high if US-163 AC13 finds the PipeWire data-loop thread not at FIFO/88 after a cold boot. Security: low, medium for a gig-capable image (with passwordless sudo, NoNewPrivileges is the only barrier between a compromised PipeWire and root)
**Status:** open — rated 2026-10-24 (static reads only, nothing run). Item 1: measure first (US-163 AC13), then a separate port PR. Item 2: deferred to US-164. Item 3: rejected for now. Blocks any gig-capable or release image (security), alongside F-317
**Found in:** `nix/nixos/audio/pipewire.nix:58` (F-291 fix), `configs/pipewire/21-usbstreamer-playback.conf:23` (`period-num = 4`), `configs/pipewire/30-filter-chain-convolver.conf` (no `node.always-process`)
**Affects:** PipeWire RT scheduling (D-013), DJ-mode ERR rate, convolver suspend during mode transitions; US-163 AC13, AC20; US-164
**Related:** F-291, F-292, F-293, F-295, D-065, F-317, F-349, US-163, US-164; #40 (`sprint/session-16` @ `c1832030`, owner-held)
**Found by:** project-manager (2026-10-24), from CM's #40 exports

### Description

#40 holds the original records of F-291, F-292, F-295 and D-065. Each
describes a fix that main does not have:

1. F-291 (#40): main's fix (clearing the PW unit's hardening so FIFO/88
   applies) is called wrong; it "appeared to work only because
   `daemon-reload` was run". The session 16 fix keeps NoNewPrivileges,
   adds a PAM nice limit for `ela` and sets mod.rt `nice.level=0`.
2. F-295 (#40): `period-num` 4 -> 5 in `21-usbstreamer-playback.conf`
   (commit `b8584f8` on #40): 16/min -> about 1/min ERR at quantum 1024
   on the Pi 4 (VL805 USB). Main has 4.
3. D-065 / F-292 (#40): `node.always-process = true` on the filter-chain
   convolver, so it does not suspend during mode transitions. Main's
   convolver conf does not set it.

### Analysis (architect, AE, security; 2026-10-24)

Item 1. Neither record's theory holds (architect). NoNewPrivileges
only stops privilege gain across execve; it blocks neither
sched_setscheduler nor systemd's CPUSchedulingPolicy. GM runs FIFO/80
with NNP=true and a SystemCallFilter (security's counterexample), so
main's comment ("all must be cleared for fifo to take effect") is
wrong, and so is #40's "NNP blocks mod.rt from demoting". The
daemon-reload effect is most likely the user manager still running
the old unit; a cold boot avoids it. `chrt -p $(pidof pipewire)` shows
only the main thread, while mod.rt acts on the data-loop thread. AE:
an RT failure under load gives xruns, each a click into the amps and
ch 5-8; at the D-009 caps unlikely to damage drivers, but repeated at
in-ear level on IEM/HP, and it can look like an F-349 event.
Security: main's relaxed PipeWire unit is acceptable for the US-163
no-audio bootstrap.

Item 2. The evidence is real but VL805-specific; the Pi 5 has
RP1/DWC3 USB, and the Pi 4 cannot be re-measured (architect). Clicks
are a quality issue at our levels, not a safety one (AE).

Item 3. Probably redundant (architect): both convolver nodes already
set `session.suspend-timeout-seconds = 0`, the out node is permanently
linked to the USBStreamer driver (pause-on-idle false), and F-292 was
fixed by removing `90-no-auto-link.conf`; #40 never tested the flag
alone. No gate impact: Closed stays exact silence and pre-flight #10
is unchanged. For F-349 at most positive: a running convolver flushes
a latched NaN after about the filter length (T47 case 3b) (AE).

### Acceptance criteria

1. Item 1: US-163 AC13 tests main's current fix as is, on
   `mugge-pi5-deploy`, after a cold boot with no `daemon-reload`, and
   records `ps -L -o tid,cls,rtprio,ni,comm -p $(pidof pipewire)` and
   the journal mod.rt lines. AC13 passes only if the data-loop thread is
   FIFO/88. If it is not, this defect is high and there is no amps-on
   load session on the Pi 5 until it passes (AE).
2. Item 1, separate reviewed PR (not US-163: `pipewire.nix` is shared
   and US-163 AC1a needs the Pi 4 drvPath unchanged): port #40's Fix C
   (`module.rt.args` `nice.level = 0`, `rt.prio = 88`) and Fix B (PAM
   nice -19). Restore the unit hardening (NNP, SystemCallFilter and the
   rest) only if a measurement with it on shows FIFO/88 holds. AC13 is
   re-verified after the port; security and the architect review it.
3. Item 2 (low): US-164 measures ERR/min at `period-num` 4 and 5 on the
   Pi 5, at q1024 and q256, and records the sink delay at q256 for both,
   so the D-011 Live figure is measured, not assumed (AE, architect). If
   5 is better or neutral and adds no Live-mode PA-path latency, it is
   ported to the shared conf.
4. Item 3 (low): rejected for now. Ported only if the US-163 bring-up
   (AC14, or T52 idle plus a mode transition) shows
   `pi4audio-convolver` going suspended or losing ports; then in its
   own PR with AE's sign-off, under these conditions (AE):
   a. F-349 AC2 (explicit, confirmed reset before every open) stays
      mandatory; always-process is never credited as a mitigation.
   b. Informative dev test: NaN injected with the gate Closed and
      always-process on, finite input for longer than the filter

   c. GM changes links only with the gate Closed (F-359).
   d. The USBStreamer sink does not suspend either: WP
      `session.suspend-timeout` checked, together with F-318.
   e. The idle CPU and thermal cost of the always-running 8 ch / 16k
      convolver is measured on the fanless Pi 5 in US-164 (O-39 (b)).
5. Architect, informational: once the PW 1.6.2 source is readable, a
   static check of whether the convolver clears its history on suspend
   and resume. Nothing may rely on it; F-349 AC2 stays mandatory.
