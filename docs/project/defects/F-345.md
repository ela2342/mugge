## F-345: Web UI thermal limiter restores Mult while the D-063 gate is Closed

**Severity:** high (audio-engineer). **Re-rate to Critical** if the interim rule (status.md rule 11) is not owner-adopted before the next amps-on session (AE): it needs no operator action, reopens to the full profile gain (on the CHN-50P 0.94 dB under the G9 ceiling), and triggers exactly when the speaker is thermally stressed and the operator has closed the gate.
**Status:** open — fix in US-159 (gate is the sole Mult writer; reduce-only limiter); needs a worker (O-8). Interim operating rule sent by AE to team-lead for the owner.
**Found in:** `src/web-ui/app/thermal_limiter.py:356-437`: every tick `_enforce_tick` computes `target_mult = base_mult * reduction_factor` and `_apply_mult` writes it with `pw_helpers.set_mult` (pw-cli). There is no gate-state check. The limiter runs in production: `main.py:215-218` creates and starts it, and it is configured when a speaker profile is activated (QE).
**Affects:** D-063 gate, thermal protection, gate indicator
**Related:** F-344 (Config tab bypass), F-320 (gate state not authoritative), F-037, US-159, US-157, L-US120 (mock early return hiding real code)
**Found by:** audio-engineer (2026-10-24); production path and test gap confirmed by quality-engineer

### Description

If the limiter is engaged (factor < 1) when the gate closes, recovery,
an override, or an override expiry moves the factor back toward 1, and the
limiter writes `base_mult * factor` to the node. The channel goes live
while GM and the indicator read CLOSED.

Test gap (QE): every `ThermalGainLimiter` unit test builds the limiter with
`is_mock=True` (`test_thermal_limiter.py` l.113/210/251/381/499), and
`_apply_mult` returns early in mock mode. So the real `set_mult` path has
no test coverage.

Also (architect): `thermal_limiter.py:427-435` caches the convolver node ID
for the session; after a PipeWire restart the ID is stale and may be reused
by another object, so the limiter writes to the wrong target or fails.
US-159 D1/D2 make this moot; file a separate interim defect only if the
web-ui limiter ships again before US-159.

### Acceptance criteria

1. The limiter never writes Mult; it sends a factor to GM, which composes
   the value and can only reduce (US-159 D1, D2, L1, L2).
2. While Closed, GM re-zeroes any Mult != 0.0 and goes to CloseFailed
   (US-159 D3; AE, architect).
3. Real-stack test (US-159 T13): engage the limiter, close the gate, then
   drive recovery, override set and override expiry. All 8 Mults stay 0.0,
   observed via `pw-cli enum-params` or pw-dump (not GM `get_state`, not
   the limiter's cache). Mutation: restoring the direct `set_mult` makes it
   fail. REQUIRE_STACK, no skip.
4. The limiter's real write path has test coverage, not only `is_mock=True`.
5. safety.md §10 has a gap row for this bypass until the fix lands (AE).
   Present in #45 `d605b5c1` (safety.md l.890, AD); close when #45 merges.
