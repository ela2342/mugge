## F-297: scripts/split-monoliths.py would overwrite newer per-item tracking files

**Severity:** medium (tracking data loss)
**Status:** open
**Found in:** `scripts/split-monoliths.py`, header of `stories-index.md` / `defects-index.md` / `decisions-index.md`
**Affects:** project tracking (docs/project/)
**Found by:** project-manager (tracking re-sync, 2026-10-24)

### Description

The three index files used to say "Auto-generated by
`scripts/split-monoliths.py`". That script regenerates `stories/`,
`defects/` and `decisions/` from the monoliths `user-stories.md`,
`defects.md` and `decisions.md`, overwriting existing files. Since the
split, every new or updated item has been edited in the per-item files
only. The monoliths have no entries for US-131+, F-262+ and many others,
and older entries there are stale (e.g. US-112, US-113). Running the
script would silently revert or lose tracking data.

### Mitigation (2026-10-24)

Index headers changed to state that per-item files are the source of
truth and the script must not be run.

### Fix (to decide)

Either delete the script and archive the monoliths, or replace it with an
index-only generator that reads the per-item files. Architect to decide.
