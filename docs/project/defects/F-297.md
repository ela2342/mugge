## F-297: scripts/split-monoliths.py would overwrite newer per-item tracking files

**Severity:** medium (tracking data loss)
**Status:** open — architect ruling 2026-10-24 (fix defined below)
**Found in:** `scripts/split-monoliths.py`, header of `stories-index.md` / `defects-index.md` / `decisions-index.md`
**Affects:** project tracking (docs/project/)
**Found by:** project-manager (tracking re-sync, 2026-10-24)

### Description

The three index files used to say "Auto-generated by
`scripts/split-monoliths.py`". That script regenerates `stories/`,
`defects/` and `decisions/` from the monoliths `user-stories.md`,
`defects.md` and `decisions.md`, overwriting existing files. Since the
split, every new or updated item has been edited in the per-item files
only. The monoliths have no entries for US-131+, F-262+ and many others,
and older entries there are stale (e.g. US-112, US-113). Running the
script would silently revert or lose tracking data.

### Mitigation (2026-10-24)

Index headers changed to state that per-item files are the source of
truth and the script must not be run.

### Evidence: data loss already happened (D-032)

The split kept only the last heading per ID. `decisions/D-032.md` held only
"D-032 Amendment"; the original decision ("Web UI requires HTTPS for
AudioWorklet secure context") survived only in `decisions.md:524`, and the
regenerated index row was empty (advocatus-diaboli, technical-writer, PR #41
review). Restored on 2026-10-24 from the monolith. Other multi-heading IDs
(D-043, D-049, D-057) checked intact. Also found: F-265 used an H1 title and
got an empty index row (fixed); the hand-added F-231 row was dropped
(restored as a per-item file).

### Fix (architect ruling, 2026-10-24)

1. Delete `scripts/split-monoliths.py` (it generates in the wrong direction
   now that per-item files are the source of truth).
2. Move `user-stories.md`, `defects.md`, `decisions.md` to
   `docs/project/archive/` with a "FROZEN, superseded by per-item files as of
   <date>" header.
3. Commit an index-only generator that builds the three indexes from the
   per-item files (currently a PM scratch script reusing the split script's
   builders; AD-41-3: it must be named and committed), and name it in the
   index headers.
4. Add a check to test-unit or CI that fails when an index is stale.
5. The CLAUDE.md / index-header references are updated accordingly
   (technical-writer).
