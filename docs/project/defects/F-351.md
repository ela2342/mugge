## F-351: Gain readers parse pw-dump or pw-cli text, so NaN and -Inf gains read as 0 and pass

**Severity:** to be rated by audio-engineer (architect: confirmed statically, not measured on the Pi)
**Status:** open — confirmed by the architect (static, 2026-10-24); needs a worker (O-8). Shares the reader with US-159 G11 (f), keeps its own ACs (architect)
**Found in:** PW 1.6.2 `spa_json_format_float` (`json-core.h:451`); GM `main.rs:974-1010`, `gain_integrity.rs:91, :220`, `registry.rs:484`; web UI `pw_helpers.py` (`find_convolver_node`, `_extract_gain_params`, `read_mult` l.252), `audio_mute.py:68-86`, `thermal_limiter.py:423`, `config_routes`, `graph_routes`
**Affects:** GM gain integrity check; web UI mute, thermal limiter, Config tab and graph views; test oracles that assert zero via pw-dump (US-159 T8, T9, T10, T16, T22, T47)
**Related:** F-349 (AC5, AC10), F-348, F-343 (AC21), US-159 (G11 (f), G13, sole-writer rule), F-345
**Found by:** technical-writer, from the architect's pw-dump finding; confirmed by the architect (2026-10-24)

### Description

pw-dump prints NaN, -Inf and subnormal floats as `0.000000`; +Inf prints
as FLT_MAX (architect). Readers that act on it:

1. GM gain integrity runs pw-dump every 30 s (`main.rs:974-1010`) and
   parses the JSON (`gain_integrity.rs:220`, `parse_pw_dump_gains`). NaN,
   -Inf and subnormal pass as 0.0; +Inf is caught by the > 1.0 test. Even
   with a raw read, NaN would pass, because `NaN > 1.0` is false. GM has no
   native Props read (`registry.rs:484`), so the watchdog's pre-mute values
   are hardcoded, not read.
2. The web UI reads gains from pw-dump (`pw_helpers.find_convolver_node`,
   `_extract_gain_params`) for mute discovery and stored pre-mute values
   (`audio_mute.py:68-86`), the Config tab (a NaN gain shows as 0), the
   thermal limiter (`thermal_limiter.py:423`: a NaN read as 0 looks
   silent, so the limiter never acts) and graph_routes.
3. The web UI fallback `read_mult` (pw-cli) uses `Float\s+([\d.eE+-]+)`
   (`pw_helpers.py:252`), which does not match nan or inf and returns None;
   `audio_mute.py:86` defaults None to 0.0. Unknown is treated as zero:
   fail-open.

Static reading only; not measured on the Pi.

### Acceptance criteria

1. (Architect) GM has one native Props reader returning raw f32 (pod
   Float, no text). US-159 G11 (f) and gain integrity both use it; the
   pw-dump gain parse is removed.
2. (Architect) Gain integrity flags any non-finite value by bit pattern
   (F-349 AC5) and any value with `!(m <= 1.0)`. The MissingNodes early
   return (`gain_integrity.rs:91`) is no longer debug-only (F-348, US-159
   G13).
3. (Architect) The web UI makes no safety decision from a Mult it parsed
   itself: mute, the thermal limiter and the gate indicator take gain state
   from GM over RPC (US-159 sole-writer rule). A Config tab display read,
   if kept, shows "invalid" for non-finite or unparseable values, never 0.
4. (Architect) No reader maps unknown or None to 0.0 (`audio_mute.py:86`
   today).
5. (Architect, QE's call) Oracles that assert zero read raw bits through
   the AC1 reader (GM RPC or test helper); interim, strict pw-cli passing
   only on exactly `Float 0.000000`. Oracles that assert a specific
   non-zero value within a tolerance still catch NaN and can stay.
6. Each check's test injects NaN, +Inf, -Inf and a quiet-NaN payload
   variant (F-349 AC5).
