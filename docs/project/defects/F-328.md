## F-328: ada8200-in capture node no longer deployed — Live-mode ADA8200 input path undefined

**Severity:** high (Live-mode readiness; split from F-295 per architect ruling 2026-10-24)
**Status:** open — architect question must be answered before any Live-mode work
**Found in:** `configs/pipewire/20-usbstreamer.conf` (no longer deployed by `nix/nixos/audio/pipewire.nix`, commit `991ff456`)
**Affects:** Live mode (vocal mic ch 1, spare mic/line ch 2), graph clocking
**Related:** F-295 (split from it), F-323 (no Live mic capture), US-158 (Live-mode mic), F-319 (level-bridge hw-in targets the removed node)
**Found by:** reconstructed from `991ff456` (PM); split and question by architect (2026-10-24)

### Description

PipeWire promoted the `ada8200-in` capture adapter to `driver=true` at
runtime despite its config, adding a dormant driver node. The fix in
`991ff456` stopped deploying `20-usbstreamer.conf`. That is a
graph-clocking problem, separate from the JACK RT-priority fix that keeps
the F-295 ID (different file, mechanism and failure class).

### Open question (architect, blocking Live-mode work)

If the `ada8200-in` node is no longer deployed, how does Live mode get the
ADA8200 inputs (vocal mic ch 1, spare ch 2)? Either another node provides
them, or the Live-mode input path is currently missing (see F-323).

### Acceptance criteria

1. The question above is answered with evidence (code reading plus a CM
   OBSERVE pw-dump on the Pi).
2. The ADA8200 capture path exists without adding a second driver node
   (single graph clock: USBStreamer).
3. Code comments that cite F-295 for the ada8200-in change cite F-328.
