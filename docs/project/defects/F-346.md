## F-346: `POST /reload-pw` hot-swaps convolver coefficients with no gate check, probably on one channel only, and reports success silently

**Severity:** high (audio-engineer; architect concurs). Confirmed in code, not tested on the Pi. **Re-rate to Critical** if the room-correction pipeline is run with the amps on before the fix (AE).
- It is the normal deploy-then-reload workflow, not only an attack.
- A filter without the D-031 HPF going live on the CHN-50P is the Xmax case: there are only about 2 dB between the G9 ceiling (-19 dB) and the Dirac Xmax point (-17 dB).
- It defeats G8a/G8b, which validate when the node appears or at `open()`, while a later reload swaps in content that was never validated.
- The partial reload (below) can leave mains and subs on mismatched crossovers.

**Status:** open — architect, AE and AD assessed (code and patch read, not run). Fix: US-159 G8c (architect ruling R-a to R-e with amendments, R-f, R-h, R-g1 to R-g4; AE conditions RF1-RF4) plus patch changes (AC10-AC12, AC14, AC15). Interim: status.md rule 9 (proposed, O-32).
**Found in:**
- `src/web-ui/app/filter_routes.py:576` (`reload_pw_endpoint`; docstring l.580-588) calls `room_correction.deploy.reload_convolver` (`src/room-correction/room_correction/deploy.py:392-437`).
- The `nix/patches/pipewire-convolver-reload.patch` is applied in both PW builds: the Pi image overlay (`nix/nixos/configuration.nix:196`) and the flake's `pipewire-patched` (`flake.nix:198`, dev/local-demo). An unpatched PW has no `Reload` control.

**Affects:** D-063 gate, US-159 G8a/G8b, driver protection (D-031), crossover consistency, F-321 (the venue coefficient load path)

### Description

AD's first premise, a destroy and re-create of the convolver node, came from
the endpoint docstring. That docstring describes a removed design: "pw-cli
destroy", "~1-2 s gap while GM re-links". AD retracted the premise. There is
no destroy fallback.

What the code does, per the architect (read, not run):

1. **Instant swap, no gate check.** `reload_convolver` sets `"Reload" 1.0`
   via pw-cli. The patch swaps the coefficients in place mid-stream, with no
   crossfade. The endpoint checks only `confirmed: true`. It has no gate
   check, no G8b validation and no auth (F-037). With the gate Open, whatever
   WAV is on disk plays at once at venue gain. An instant swap on an open path
   also produces a click.
2. **Probably only one of 8 convolvers is reloaded** (architect: probably
   High; high confidence from PW naming semantics, not verified on hardware).
   The control is sent unprefixed. PW filter-chain resolves an unprefixed name
   to the first node, which is why gains are always written as
   `gain_left_hp:Mult`. In `30-filter-chain-convolver.conf` the first node is
   `conv_left_hp`, so the left main gets the new FIR while the right main and
   both subs keep the old ones. If the old files were Dirac, the stale
   channels can also lose D-031 protection.
3. **Silent success.** `{"reloaded": true}` is returned without reloading
   anything when:
   - pw-cli returns 0 for an unknown or unmatched param name;
   - the patch's own failure path (`read_closest` or `convolver_new` fails)
     only logs "keeping old coefficients";
   - the post-check compares node IDs, which proves nothing because the patch
     never changes the ID.
4. **Main-loop stall.** The patch reads the WAV and builds the 16k-tap FFT
   convolver inside `control_changed` on the PW daemon main loop. Registry and
   param events are delayed while it runs, which lengthens the watchdog and
   the US-159 D3 detection latency (L4). With all 8 channels reloaded, the
   stall is 8 times as long.
5. **Unpatched PipeWire** (architect, moderate confidence): there is no
   `Reload` control port, filter-chain skips unknown control names without
   an error, `pw-cli s` exits 0, and `deploy.py` sees the same node ID and
   returns True. Same silent path as item 3. Both Nix builds apply the
   patch; this applies to any non-Nix PW. QE can confirm it on local-demo
   once disk space allows.
6. **No crossfade, no state carry-over** (AD; architect agrees): the new
   convolver starts with zeroed overlap and tail, so each swap is a hard
   discontinuity, and the 8 swaps land in different graph cycles. The gain
   nodes sit after the convolvers, so a confirmed Mult = 0 (G11) masks both
   effects completely. This makes "reload only while Closed" a correctness
   requirement, not just policy.
7. **Unlocked fallback swap** (AD; architect agrees): if `pl->data_loop` is
   NULL the patch swaps without the data-loop lock, a potential
   use-after-free on the RT thread. Whether module-filter-chain passes
   DataLoop is unverified.
8. **Re-arm depends on port storage** (AD; architect adds the inverse
   case): (a) if the clear does not take, an unrelated control change (for
   example GM's Mult writes at gate open) re-runs the reload, if filter-graph
   notifies that node at all; (b) if the clear takes in the patch's storage
   but filter-graph's cached value stays 1.0, every reload after the first
   is a silent no-op.
9. **G8a goes stale.** GM hashes coefficient content when the node appears.
   An in-place reload never makes the node reappear, so GM's hash no longer
   matches what PW plays.

### Acceptance criteria

1. Coefficient reload is a GM-owned RPC. The web-ui endpoint calls GM and
   never pw-cli (architect R-a, US-159 G8c).
2. Reload is refused unless the gate is Closed (R-b; the same rule as G7
   `set_venue`; AE agrees, owner exception O-33).
3. GM hashes and G8b-validates the new files before triggering. If
   validation fails or is pending, it refuses and the old coefficients stay
   (R-c).
4. GM triggers all 8 convolvers with node-prefixed names
   (`conv_<ch>:Reload`) and confirms success per channel. "Confirmed" means
   all 8. Anything else is ReloadFailed: the gate stays Closed and opening is
   refused until a successful reload (R-d). No success is reported on any of
   the silent paths above.
5. GM updates its G8a hash only after a confirmed reload (R-e).
6. The docstring matches the implementation.
7. Dropped 2026-10-24 (AE): the historical reload count in the old
   Pi's journal is unknowable (the old Pis are unreachable); the fix
   and its tests do not depend on it. Kept: QE result: no test,
   deploy or otherwise, asserts or references the prefixed `conv_<ch>:Reload`
   names; code and tests send only the bare `"Reload"` (`deploy.py:419-421`,
   `test_convolver_reload.py` l.88/114/157/195).
8. Real-stack tests (US-159 T22, T23). Points 7 and 8 of the description
   need a CHANGE-tier test with the amps off, or local-demo; QE owns this as
   part of T23: after a reload, one Mult write adds 0 "reloading" lines and a
   second reload adds exactly 8.
9. safety.md carries the interim rule (status.md rule 9) until the fix lands
   (follow-up safety.md PR, F-343).
10. (Patch, architect) The unlocked else branch refuses with an error log;
    never an unlocked swap (AD AC: refuse or assert when there is no data

11. (Patch, architect) Each convolver exposes a read-only notify control
