## F-325: Hardware watchdog not configured — no backstop for RT lockups

**Severity:** medium. Fix and test before the next gig (audio-engineer, security-specialist).
**Status:** open
**Found in:** `nix/` (no `systemd.watchdog.runtimeTime` or equivalent; only the kernel BCM2835 driver is present)
**Affects:** F-291 / F-317 (RT throttle disabled), D-013, gig availability
**Related:** F-317; owner decision O-24; CLAUDE.md TODO "Watchdog reliability" (BCM2835 watchdog failed on Test 3 and Test 5, 2 of 11 lockups)
**Found by:** security-specialist and audio-engineer (retroactive review of `991ff456`, 2026-10-24); promoted from a CLAUDE.md TODO

### Description

`rt-tuning.nix` (F-291) disables the RT throttle and relies on the
watchdog as the backstop. Nothing configures the watchdog, and when it was
tested earlier it failed on 2 of 11 lockups. As things stand, F-291 has no
backstop at all. A runaway FIFO thread starves SCHED_OTHER, which takes
down SSH and the web UI MUTE path. The physical amp switch remains the
only real panic control.

### Acceptance criteria

1. Hardware watchdog configured in NixOS (e.g. `systemd.watchdog.runtimeTime`).
2. Lockup test on the Pi (CM CHANGE session, amps OFF) shows a reboot
   within the configured time, repeated enough to address the earlier 2/11
   failures.
3. Owner warned before any test that resets the USBStreamer.
4. safety.md states that a watchdog reboot resets the USBStreamer and
   causes a transient (technical-writer).

### Audio-engineer position (2026-10-24; not a veto item)

A hardware watchdog is not a speaker-safety backstop. A hung Pi just
silences the USBStreamer, while a watchdog reboot resets USB, which is the
documented transient risk, with the amps on and no warning. Configuring it
is still worth it for availability, since the D-063 gate is closed on boot,
but the owner must take that tradeoff knowingly (O-24).
