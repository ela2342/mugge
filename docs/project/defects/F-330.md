## F-330: CI paths filter is an allowlist — unknown paths skip the tests

**Severity:** medium (process; quality-engineer, advocatus-diaboli)
**Status:** open
**Found in:** `.github/workflows/ci.yml` (paths filter; skip treated as pass at ci.yml:192)
**Affects:** Rule 13 (T1-T3 required), F-313 (root `tests/` suites), PRs #41-#43
**Related:** F-329, F-313, F-333; owner ruling O-22 (2026-10-24: a paths-filter skip is NOT green; T1-T3 must actually run on each PR head)
**Found by:** quality-engineer, advocatus-diaboli (Rule 13 review of PRs #41-#43, 2026-10-24)

### Description

The paths filter lists code paths that trigger `test-and-build`. A change to
any path not on the list skips T1-T3, and the skip is reported as a pass.
Root `tests/**` is not covered, which F-313's ports will need. On PRs
#41-#43, T1-T3 did not run.

### Acceptance criteria

1. The filter is inverted to a denylist of known non-code paths (e.g.
   `docs/**`, `*.md` outside test/config dirs); every other path runs the
   tests.
2. `tests/**` and any `configs/**` read by tests run the tests.
3. Verified with one docs-only PR (skips) and one PR touching an unlisted
   path (runs).
