## F-353: Project docs and benchmarks assume a Pi 4B; the new target is a Pi 5

**Severity:** medium (PM; documentation, and performance numbers that may not transfer)
**Status:** open — follow-up to the owner's new target (2026-10-24); doc owners and the architect to scope
**Found in:** CLAUDE.md (Project Summary, Pi Hardware State, Hardware Access Protocol `ela@192.168.178.185`), `.claude/team/config.md` (deployment target), BM-2 and other benchmarks, the CPU budget, the NixOS flake target
**Affects:** documentation, CPU and latency budgets (D-040 BM-2 numbers, quantum choices, 16k-tap budget), deployment target declaration
**Related:** O-2 (moot), D-040, D-011, US-128
**Found by:** team-lead, from the owner's answer (2026-10-24)

### Description

The owner named a new deployment target: a Pi 5 at `ela@192.168.178.88`,
to be bootstrapped to NixOS with nixos-anywhere. The project docs say Pi
4B throughout, and the old Pis are unreachable. The BM-2 results and the
CPU budget were measured on a Pi 4B (Cortex-A72) and do not carry over to
a Pi 5 (Cortex-A76) without a re-run.

### Acceptance criteria

1. CLAUDE.md and `.claude/team/config.md` name the Pi 5 target and
   address, and mark the Pi 4B Pis as historical (CM or TW, as each
   file's owner decides).
2. Hardware-specific docs (setup manual, rt-audio-stack, safety.md where
   relevant) say which Pi they apply to.
3. BM-2 and the CPU budget are marked "Pi 4B" and re-run on the Pi 5 after
   the bootstrap (architect to plan).
4. The PREEMPT_RT kernel and V3D notes are re-checked for the Pi 5.
