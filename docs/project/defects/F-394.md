## F-394: DJ-mode E2E group skips on mode-switch failure, and the level-bridge signal test fails whenever it runs

**Severity:** High (quality-engineer; audio-engineer confirms: safety-relevant)
**Status:** open. Fix PR #68 merged in `55d90806`; the PR #59 quarantine (strict xfail on `test_level_bridge_sw_has_signal`) is removed. AC (iv) is open and AC (vi) awaits the audio-engineer/quality-engineer ruling. Nothing may present mute as verified until AC (vi) passes
**Found in:** CI E2E runs, `src/web-ui/tests/service-integration/test_audio_flow.py::TestLevelBridge::test_level_bridge_sw_has_signal` and the mute E2E tests (2026-10-25)
**Affects:** CI evidence for the DJ-mode signal path and for mute; T3 on PRs that do not touch the audio path
**Related:** F-262 (D-249 paragraph corrected, AC v), F-270 (mis-cited xfail, AC v), F-410 (unmute behind a closed gate, PM backlog), D-249

### Description

CI has never shown signal on the level-bridge-sw tap in DJ mode, and
has never shown that mute silences the output.
`test_level_bridge_sw_has_signal`: 0 pass / 3 fail (runs 40231575303,
40240718064, 40242141720) / 8 skip.

Mechanism: the `ensure_dj_mode` fixture
(`src/web-ui/tests/fixtures/backend.py`) calls `pytest.skip` when the
switch to DJ mode fails. When the switch succeeds (the GM reports
settled), the test reads one level snapshot (`count=1`), and the tap is
silent.

The mute E2E tests are vacuous: `test_mute_silences_level_bridge` only
checks that level data arrives before the mute, never that there is
signal. In CI 40240718064 the sw tap was silent and the mute test still
passed.

Lead (quality-engineer, 2026-10-26; a lead, not a conclusion, to be
ruled in or out under AC (ii)/(iii)): `scripts/local-demo.sh`
(l.114-115, 138-141) resolves WP_STORE from the unpinned registry
nixpkgs (`nix eval --raw nixpkgs#wireplumber.outPath`), not from
flake.lock, and puts that WirePlumber into XDG_DATA_DIRS,
WIREPLUMBER_MODULE_DIR and PATH. The test-e2e app in `flake.nix`
(l.745-765 on ba5cc200) pins PW_STORE (l.759) but does not set
WP_STORE; no app in flake.nix sets it. The E2E environment is therefore not hermetic: the WirePlumber version and
config search path can drift between CI runs, a plausible contributor
to the nondeterministic DJ switch. Fix candidate: export a WP_STORE
pinned from the flake, like PW_STORE.

Hard condition (quality-engineer, audio-engineer): "Nothing may present
mute as verified until AC (vi) passes."

### Fix status (PR #68, merged in `55d90806`)

Claimed by PR #68:
- (i) `ensure_dj_mode` FAILs instead of skipping. It is function-scoped
  and its teardown switches back to standby and checks the result (QE Q3
  `19429bd0`).
- (ii) Root cause, two parts: GM push events (`{"type": "event", ...}`)
  arrive on the RPC connection and were taken as the `set_mode` reply
  (fixed in `51fae218`: `_rpc_call` skips events); and `local-demo.sh
  env` derived the PipeWire runtime dir from its own PID, so the pw-*
  tools in pytest saw no PipeWire (fixed in `0cb35f0c`: `env` reads the
  manifest). The DJ group has passed since CI run 40356547804.
- (iii) The sw tap was silent because CI had no stimulus (the mp3 is not
  on the runner). Test runs now use the `--tone` stimulus (QE Q1
  `0919d10d`). The negative control, CI run 40398705324 with the tone
  off, goes red.
- (v) The F-270 xfail on `test_unmute_restores_levels` is removed, not
  re-pointed, because the test now passes.
- (viii) The quarantine marker is removed.

Claimed, awaiting the audio-engineer/quality-engineer ruling:
- (vi) The mute tests assert the pre-mute tone and go red without a
  stimulus. AE Q2 `e37c80fa` supersedes the "same tap" wording in
  (vi)(2): mute and unmute are asserted on level-bridge-hw-out,
  downstream of the gain nodes; level-bridge-sw only checks that the
  stimulus is present. The hard condition is unchanged.

Open:
- (iv) N >= 5 consecutive green CI runs at one head, `-rs` output saved
  (QE ruling `9402c6eb`).

The "Rules while open" above stay in force until (iv) and (vi) pass.
