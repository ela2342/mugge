## F-312: No central stack-availability guard — CI can go green with the real stack down

**Severity:** high (CI gate integrity)
**Status:** open
**Found in:** `src/web-ui/tests/fixtures/backend.py:120` and ~17 local-demo probe fixtures in `e2e/` and `service-integration/`; `test-e2e.sh` and other real-stack runners
**Affects:** ci-gate, T2, testing-process.md Sec 9.2
**Found by:** quality-engineer (skip audit C1, 2026-10-24); design ruling by architect

### Description

"Local-demo not reachable" leads to a skip in about 17 module fixtures.
That is fine locally. But if local-demo fails to start in CI, or a
backing service is down while the web UI is up, or the stack crashes
mid-run, the whole E2E/service-integration tier skips and ci-gate goes
green. Some runner entry points have no guard at all.

### Fix (architect ruling)

- `test-e2e.sh` and the other real-stack runners export `PI4AUDIO_REQUIRE_STACK=1`.
- A single helper in `tests/fixtures/` fails when the variable is set and
  skips when it isn't. `backend.py:120` and all probe fixtures use it.
- Opt-in skips (`--destructive`, `--owner-confirmed`, tier gating) stay as
  skips.
- The helper has its own test.
- QE is a mandatory reviewer.
