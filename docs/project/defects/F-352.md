## F-352: Config API accepts a NaN or subnormal Mult and writes it to PipeWire

**Severity:** critical if PW parses `nan`, else high (audio-engineer, 2026-10-24)
**Status:** open — the `nan` parse step is unverified (architect to check statically; QE could test on dev, not the Pi); needs a worker (O-8). Interim: status.md rule 7 [safety.md Rule 8], network isolation
**Found in:** `src/web-ui/app/config_routes.py:92-106, 196-201` (`GainRequest` validator, hard cap), `pw_helpers.py:286` (`set_mult` via pw-cli)
**Affects:** all 8 gains, past the D-063 gate; every gain reader (F-351)
**Related:** F-344 (same endpoint; AC6 already tests NaN), F-037 (no auth), F-349, F-351, US-159 (G3, sole writer)
**Found by:** audio-engineer, while rating F-351 (2026-10-24)

### Description

`POST /api/v1/config/gain` checks Mult only by comparison, and NaN fails
every comparison (AE):

1. The validator rejects `mult < 0.0` and `mult > 1.0`; both are False
   for NaN.
2. The hard cap `min(nan, 1.0)` returns nan in Python.
3. Starlette's `json.loads` accepts the bare token `NaN`, and pydantic
   floats allow NaN by default.
4. `set_mult` then sends `"gain_x:Mult" nan` to pw-cli
   (`pw_helpers.py:286`).
5. A subnormal such as `1e-40` also passes validation. +-Inf is rejected
   by the range checks.

A browser cannot send it (`JSON.stringify(NaN)` is `null`, rejected), but
a hand-made request can, and with no auth (F-037) so can any host on the
network, on any of the 8 channels, past the gate. Every reader then reports
0 (F-351), and the output is undefined, worst case full scale (F-349).

Unverified: whether PW's SPA JSON parser accepts `nan` as a float.
Rating (AE): Critical if it does; High if not, because a subnormal Mult
still disables the hard-zero path.

### Acceptance criteria

1. (AE) Every web UI and GM Mult input rejects non-finite values
   (`math.isfinite`, pydantic `allow_inf_nan=False`) and rejects
   0 < |m| < FLT_MIN.
2. (AE) `set_mult` and every pw-cli writer refuse non-finite values at the
   boundary, as defence in depth.
3. (AE) After US-159, GM as sole writer applies the F-349 AC5 bit test to
   every write.
4. (AE) Test: POST with NaN, Infinity and 1e-40 is refused and nothing is
   written (pw-cli read-back). Extends F-344 AC6.
5. (Architect) Static check whether PW parses the bare word `nan` as a
   float; this sets the severity.
