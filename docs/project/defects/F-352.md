## F-352: Config gain API passes a NaN Mult to pw-cli, which PW turns into an indeterminate gain of up to +20 dB, past the gate

**Severity:** critical (audio-engineer, architect; 2026-10-24)
**Status:** open — static analysis only (architect; nothing run on the Pi). Worker to be assigned (O-8 resolved). Interim: status.md rules 7 and 11 [safety.md Rules 8, 11]; rule 7 tightening proposed (security, O-32). Owner notified (O-38), including the upstream PW report
**Found in:** `src/web-ui/app/config_routes.py:92-106` (`GainRequest` validator, hard cap), `pw_helpers.py:286` (`set_mult` via pw-cli); PW 1.6.2 `filter-graph.c:671`, `plugin_builtin.c:1517`
**Affects:** all 8 gains, past the D-063 gate and `MULT_HARD_CAP`; every gain reader (F-351)
**Related:** F-354 (same endpoint, name injection), F-355 (thermal limiter sends `nan` through the same writer), F-344 (same endpoint; AC6 already tests NaN), F-037 (no auth), F-349, F-351, US-159 (G3, sole writer), D-009
**Found by:** audio-engineer (NaN input), architect (PW parse path), 2026-10-24

### Description

`POST /api/v1/config/gain` checks Mult only by comparison, and NaN fails
every comparison (AE):

1. The validator rejects `mult < 0.0` and `mult > 1.0`; both are False
   for NaN.
2. The hard cap `min(nan, 1.0)` returns nan in Python.
3. Starlette's `json.loads` accepts the bare token `NaN`, and pydantic
   floats allow NaN by default.
4. `set_mult` then sends `"gain_x:Mult" nan` to pw-cli
   (`pw_helpers.py:286`).
5. Only NaN gets through (security-specialist): +Inf is clamped to 1.0
   by `min()`, and -Inf is rejected. A subnormal such as `1e-40` also
   passes; it disables the hard-zero path (F-349).

What PW does with it (architect, static): the SPA JSON parser does not
parse `nan`, so pw-cli builds a String pod. An upstream bug then applies
a garbage value: at `filter-graph.c:671` the test
`spa_json_parse_float(...) >= 0` is always true, so PW applies an
uninitialised float, clamped to the port range [-10, 10]
(`plugin_builtin.c:1517`). The result is an indeterminate Mult of up to
+20 dB on the channel. PW accepts Mult up to 10.0: the 1.0 cap of D-009
exists only in our code. The rating is Critical unconditionally (AE).

A browser cannot send it (`JSON.stringify(NaN)` is `null`, rejected), but
a hand-made request can, and with no auth (F-037) so can any host on the
network, on any of the 8 channels, past the gate. Every reader then
reports a wrong value (F-351).

Without an attacker (AE): any of our code that computes a non-finite
value and passes it to `set_mult` hits the same path. The architect's
audit found one such caller, the thermal limiter (F-355); the other
`set_mult` callers are clean.

A native NaN Float pod (not text) is clamped to -10.0, so PW never
stores a NaN Mult through Props (architect). A Mult of -10.0 is still a
+20 dB, phase-inverted gain, so the F-349 AC5 bit test on every GM write
stays mandatory.

QE: the existing dev test of this endpoint expects an arbitrary value
to be accepted with no error, so it encodes the bug and must change
with the fix.

### Acceptance criteria

1. (AE, architect) The API rejects any Mult that is not finite
   (`math.isfinite`, pydantic `allow_inf_nan=False`) or not in [0, 1.0],
   and any 0 < |m| < FLT_MIN. Reject with 4xx; never clamp.
2. (AE, architect, security) `set_mult`, `_set_mult_sync` and every
   other pw-cli Mult writer re-validate: `math.isfinite` and
   0 <= v <= cap, otherwise refuse. -0.0 is normalised to +0.0 before
   formatting, not rejected, so a close or mute path that computes -0.0
   still writes its zero (architect). The value is formatted explicitly
   (never Python's `str()` of a float).
3. (Architect, security; fail-safe action is AE's ruling) An internal
   caller whose value is refused never writes it; it latches a visible
   fault and logs loudly.
4. (AE) After US-159, GM as sole writer applies the F-349 AC5 bit test
   to every write.
5. (AE, QE) Test: POST with NaN, Infinity, -Infinity and 1e-40 is
   refused with a 4xx and nothing is written (pw-cli read-back). Extends
   F-344 AC6. The existing dev test that accepts an arbitrary value is
   changed.
6. (AE) Unit test: `set_mult(nan)` and `set_mult(inf)` are refused
   without calling pw-cli; `set_mult(-0.0)` writes +0.0.
7. Done 2026-10-24 (architect, static): PW does not parse bare `nan`;
   the upstream `>= 0` bug makes the result indeterminate. The audit of
   the other `set_mult` callers is done (only F-355 found). Reporting
   the PW bug upstream is the owner's decision (O-38).
