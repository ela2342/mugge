### Description

The GM looks for venue files in `PI4AUDIO_VENUES_DIR`, or in
`./configs/venues` if that is unset. No unit on the Pi set the
variable, and the fallback dir did not exist, so no venue could be
armed. This failed safe: without a venue the gate cannot open. But it
blocked the DJ path completely.

While planning the fix, worker-1 found a second problem (plan
`67cce1d1`, Q1). The GM had a built-in first-boot default: it armed
`PI4AUDIO_DEFAULT_VENUE` if set, otherwise the hard-coded
`foh-passthrough`, and persisted that name. That default could not
fire only because the dir was missing. Packaging the venues alone
would have made it live, and `foh-passthrough` has no driver
protection (D-031).

### Fix (architect `827c2d69` §3, `bd68d14a`, `4c7eceaa`; audio-engineer `013d2fa8`, `16ab21eb`)

- The venues are packaged into the Nix store as a read-only
  derivation from the flake source (`flake.nix`, `venues`).
- `PI4AUDIO_VENUES_DIR` points at that store path for both the GM
  (`nix/nixos/services/graph-manager.nix`) and the web UI
  (`nix/nixos/services/web-ui.nix`), so both read one dir.
- `nix/checks/board-guard.nix` asserts that the GM unit carries the
  variable, that the dir exists and is not empty, and that the
  packaged venue file equals the flake-source file.
- No built-in default venue (Q1 = A, commit `90bb72de`). The GM arms a
  default only if `PI4AUDIO_DEFAULT_VENUE` is set, and no unit sets
  it. Audio-engineer (`16ab21eb`), verbatim: "a venue is armed only by
  an explicit set_venue, or by restoring the venue a previous explicit
  set_venue persisted; never by a built-in or env default unless the
  AE later opts in."
- F-467: the GM no longer reports a venue as active when its profile
  fails to load (commit `afaba039`).
- Docs in the same PR (commit `1eb84dac`): the `foh-passthrough.yml`
  header, US-113, D-062, US-127, a dated note in F-037, and a status
  line.
