## F-348: Generated filter-chain configs remove the D-063 boot gate, and GM cannot close N-way gains

**Severity:** high (audio-engineer; architect proposed High). Static evidence only, not reproduced at runtime. **Re-rate to Critical** if the OBSERVE check (AC7) finds a generated conf active on the Pi, or a live convolver node with fewer than 8 channels, names other than the fixed 8, or non-zero boot gains: "gate closed at boot" would then be false today (AE). Two live convolver nodes (both fragments loaded) are also Critical: GM may be bound to the wrong one (architect).
**Status:** open — found independently by audio-engineer and architect (code read; one merged entry); needs a worker (O-8). Fix: US-159 G12/G13 and G8c R-g4 (architect ruling). Interim: status.md rule 10 (proposed, O-32). The AC7 OBSERVE check is on hold until the owner answers O-2 (CM).

**Affects:** D-063 boot gate, GM close_gate, watchdog mute, standby close, gain integrity, HP/IEM path (ch 5-8)
**Related:** F-347 (Config tab fixed list), F-339 (close returns Ok without zeroing), F-342 (3-way), F-346 (PW restart is the interim reload route), D-063, US-159 (D1/D3, G8c R-g4, G11-G13)
**Found by:** audio-engineer and architect, independently (2026-10-24)

### Description

1. **Boot gate lost.** Any web-UI profile activation, 2-way included, writes a
   generated conf. After the next PipeWire restart the outputs come up at
   profile gain while GM shows CLOSED. No operator action is needed beyond the
   restart. Whether PW lets the user fragment shadow the system one or loads
   both (two filter-chains) is unverified; both are unsafe (architect).
2. **N-way gains can't be closed.** GM's fixed list never matches the
   pass-through names, so close_gate writes params that don't exist, the real
   gains stay live, and close still returns Ok (F-339). The watchdog mute, the
   standby close and the open-gate table miss them the same way.
3. **No > 0 dB detection on N-way.** Gain integrity stops at MissingNodes
   before the Mult > 1.0 check, and MissingNodes is a debug log only.
4. **HP/IEM path lost.** The generated conf has only the speaker channels, so
   the gated ch 5-8 path is gone, even on 2-way (architect, verified in code;
   not checked on the Pi).

Why High, not Critical (AE): pre-flight #10 (all `gain_*` == 0.0, exactly 8),
run before the amps go on, catches every case, and the F-346 interim rule
already runs #10 after the restart.

Unverified (AE): whether a generated conf is already on the Pi. Nothing under
`nix/` references `~/.config/pipewire` (PM grep), so NixOS probably doesn't
manage that path and the write probably succeeds.

### Acceptance criteria

1. The generator emits Mult 0.0 for every gain node; venue gains are applied
   only by GM on open (US-159 G12).
2. The generator emits the fixed 8 names (no pass-through suffixes) and the
   full 8-channel D-063 layout; the profile's channel map decides only the
   content of each channel. Generator and GM share one name source (G12, G8c
   R-g4).
3. Profile activation never writes a PW conf. It goes through the single
   validated deploy path, or a GM runtime apply; the active conf stays the
   Nix-managed D-063 one. Generated confs never use the Nix conf's filename.
   The deploy path refuses non-D-063 confs (all Mult 0.0, the expected gain
   set, the channel count) (architect).
4. GM checks the discovered gain set against the expected 8. close_gate,
   watchdog mute and standby close zero every `gain_*:Mult` present,
   including unknown names; on a mismatch close returns a failed or partial
   result naming the missing and extra nodes, never Ok, and raises an alarm;
   open is refused (G13, G8c R-g4).
5. Gain integrity: MissingNodes is a loud fail-closed state, not a debug log,
   and the > 1.0 check still runs over the gains present (G13).
6. Tests US-159 T34-T37, with mutation evidence.
