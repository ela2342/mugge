## F-344: Config tab gain Apply (`POST /api/v1/config/gain`) writes Mult directly, bypassing the D-063 gate

**Severity:** high (quality-engineer; audio-engineer confirmed the safety side: the UI soft cap is -20 dB but the API reaches 0 dB, with no feedback while Closed, and F-037 makes it reachable from the network)
**Status:** open — fix in US-159 (gate is the sole Mult writer); needs a worker (O-8)
**Found in:** `src/web-ui/app/config_routes.py:176-215` (`set_gain`): for each requested channel it calls `pw_helpers.set_mult` (`pw_helpers.py:297`, pw-cli) directly. No gate-state check, no call to GM, no ramp. The only checks are in `GainRequest` (l.92-106): name prefix `gain_`, Mult >= 0.0, clamp to 1.0 (D-009 cap).
**Affects:** D-063 gate, gate indicator, speaker and hearing safety
**Related:** F-352 (the same endpoint accepts NaN and subnormal Mult; AE), F-354 (gain-name injection, same endpoint), F-345 (thermal limiter bypass), F-320 (gate state not authoritative; same class as F-320-F, `audio_mute.py`), F-037 (no web UI auth: the same write is reachable from any host on the network; security-specialist verified in code, already in the F-037 evidence; no severity change, F-037 is Critical and safety.md Rules 8/11 cover the interim), F-338, US-159
**Found by:** quality-engineer (2026-10-24)

### Description

With the gate Closed, pressing Apply on the Config tab (or any POST to
`/api/v1/config/gain`) sets the Mults to the requested values at once.
The channel is live while GM, and therefore the indicator, still reads
CLOSED. A later Close Gate does zero them, but nothing tells the operator
that the gate was bypassed. With F-037, any host on the network can do
the same.

Not yet checked (PM; QE's reading agrees, unverified until a test proves it): `GainRequest` does not
reject NaN or infinity (`mult < 0.0` and `mult > 1.0` are both false for
NaN, `min(nan, 1.0)` in `set_gain` returns nan, and pydantic v2 `float`
allows inf/nan by default). What PipeWire does with a NaN Mult is unknown,
possibly worse than 1.0 (QE). Architect to confirm whether pydantic lets them through; US-159 G3
(finite, 0 <= Mult <= 1.0) would cover it once all writes go through GM.

### Acceptance criteria

1. With the gate Closed, `POST /api/v1/config/gain` is either rejected
   with a visible reason or routed through GM (the G2 ramp and G3
   validation apply). It never calls `set_mult` directly.
2. All 8 Mults stay 0.0 while Closed, observed independently via
   `pw-cli enum-params`, not via `GET /api/v1/config` (QE).
3. Mutation evidence: reintroducing the direct `set_mult` call makes the
   test fail.
4. The test runs under REQUIRE_STACK (F-312) and must not skip.
5. The Config tab shows the refusal, or the gate-routed result, to the
   operator (UX).
6. (QE) POST /config/gain with NaN, +inf, -inf and the JSON strings
   "NaN"/"Infinity" returns 4xx and the Mults stay unchanged (pw-cli
   read-back). Mutation: dropping the finite check makes it fail (US-159
   T20, G3).
