## F-338: Web UI CLOSE GATE is disabled while the gate reads CLOSED — gains cannot be zeroed from the UI in the F-320 states

**Severity:** high (ux-specialist; confirmed by audio-engineer: blocks the interim safety procedure in the F-320 states; MUTE and REST close are workarounds). Makes interim rules 5-7 impossible to perform from the UI.
**Status:** open — standalone fix ahead of US-159 (AE + architect); needs a worker (O-8)
**Found in:** `src/web-ui/static/js/venue.js:59-61` (`closeBtn.disabled = !gateOpen`). GM `close_gate` (`src/graph-manager/src/main.rs:824-840`) zeroes unconditionally; only the UI blocks it.
**Affects:** status.md interim rules 5-7 (safety.md §10 rules 5-7), F-320 D/E/F, US-159 U items
**Related:** F-320, F-339, US-159 (U7), US-160
**Found by:** ux-specialist (2026-10-24); verified by audio-engineer

### Description

The CLOSE GATE button is enabled only when the UI believes the gate is
open. In the F-320 states (after an unlatch, a GM restart, or UNMUTE) the
indicator can read CLOSED while gains are above 0. The interim rules tell
the operator to press Close Gate in exactly those states, and the button
is disabled.

### Interim procedure (audio-engineer)

Amps off, then panic MUTE, then REST `POST /api/v1/venue/gate/close`,
then safety.md pre-flight #10 (all 8 Mult read 0.0 from PipeWire).

### Fix

CLOSE GATE is always enabled: closing is always safe. AE and architect
agree it ships ahead of US-159 as its own small fix, on two conditions:
the button calls `close_gate` (`POST /api/v1/venue/gate/close`), not
MUTE, and a test asserts the button is enabled while the gate reads
CLOSED. UX tier A: the worker sends the approach to UX before writing
code. Can be bundled with US-160 (interim UNMUTE). US-159 U7/T9 keeps the
long-term coverage.

### Acceptance criteria

1. CLOSE GATE is enabled in every gate state, including CLOSED, and
   calls `close_gate`, not MUTE.
2. Pressing it with the indicator CLOSED and a Mult above 0 (set via
   pw-cli) leaves all 8 Mult == 0 per pw-cli.
3. Browser E2E covers 1 and 2 (no mock of the gate state), including an
   assertion that the button is enabled while the gate reads CLOSED.
4. safety.md §10 rules 5-7, the gaps table and the status.md "press Close
   Gate" workaround note are updated when this lands (UX, #45 follow-up).
