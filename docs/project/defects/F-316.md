## F-316: Lab-only static route (US-156) hardcoded into the production image

**Severity:** low (security-specialist; not blocking)
**Status:** open
**Found in:** `nix/nixos/network.nix` (commit `991ff456`)
**Affects:** US-156, US-000a (firewall baseline), US-132a
**Found by:** security-specialist (retroactive review of `991ff456`, 2026-10-24)

### Description

The route 192.168.105.0/24 via 192.168.178.26 is active at every venue. It
opens no new inbound services, and the firewall is unchanged. But many
German venues run FritzBox networks, which default to 192.168.178.0/24, so
there .26 is an arbitrary venue device that would receive traffic for
192.168.105.0/24 (in practice only replies). On networks where the gateway
is unreachable, adding the route fails. Whether this fails or delays
`network-addresses-end0` at boot is unverified.

### Fix

Move it into a dev/lab-only module or flake option, or make it
conditional. Pi check (CM OBSERVE session) on boot behaviour when .26 is
unreachable. See US-156 AC2-AC4.
