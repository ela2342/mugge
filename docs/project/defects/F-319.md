## F-319: Dead capture consumers after F-295 — level-bridge hw-in and pcm-bridge capture-usb (suspected)

**Severity:** unknown (suspected, unverified)
**Status:** open — needs verification (CM OBSERVE session)
**Found in:** `nix/nixos/production.nix:66` (level-bridge `hw-in`, target `ada8200-in`); `nix/nixos/production.nix:91-99` (pcm-bridge `capture-usb`, target `alsa_input.usb-MiniDSP_USBStreamer-00.pro-input-0`); GM Live routing in `routing.rs`
**Affects:** F-295, US-158, Live mode, F-015 (if a capture stream exists), safety.md pre-flight #8
**Found by:** product-owner (code read, 2026-10-24)

### Description

F-295 removed the `ada8200-in` capture adapter from the production image,
but level-bridge `hw-in` is still enabled with that target, and GM's Live
routing still references the node. It may be failing, crash-looping, or
spamming logs on the Pi. Not verified.

Scope extended 2026-10-24 (audio-engineer, via QE): the production
pcm-bridge `capture-usb` is a second suspected dead consumer. Its target
node is probably suppressed by `deny-usbstreamer-alsa.lua` and F-295.

### Acceptance

One CM OBSERVE session: a worker reads the pw-dump node list and records
whether `ada8200-in` or any USBStreamer input node exists, plus the
level-bridge hw-in and pcm-bridge capture-usb unit states and journals,
and the links on any such node (a node alone does not prove an active
stream; AD). If a USBStreamer input node exists and is linked or running,
production has an active USBStreamer
capture stream: that is an F-015 risk and safety.md pre-flight #8 fails.
Escalate to the audio-engineer immediately in that case.

### Next step

Fix belongs with US-158 (see its AC5).
