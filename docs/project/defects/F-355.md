## F-355: Thermal limiter latches a NaN level and sends `nan` to set_mult every 0.5 s, a persistent random gain that overrides gate close and MUTE

**Severity:** critical (audio-engineer, 2026-10-24); mitigated today by interim rules 10(a) and 11
**Status:** open — static analysis only (architect). Worker to be assigned. Interim: status.md rules 10(a) and 11 (no web UI profile activation, so the limiter is unconfigured; limiter not used). Rule 10(a) must not be lifted until this is fixed and tested (AE)
**Found in:** level-bridge `server.rs:226` (prints `NaN`), `src/web-ui/app/thermal_monitor.py:116` (smoothed power), `thermal_limiter.py` (`compute_reduction`, `_enforce_tick`), configured at `speaker_routes.py:954, 978`
**Affects:** all gains the limiter controls; gate close, MUTE, the operator's panic paths
**Related:** F-352 (PW turns each `nan` into an indeterminate Mult), F-349 (the NaN source), F-344, F-345, F-348 (rule 10(a)), O-31, US-159 (sole writer, reduce-only limiter)
**Found by:** architect, from AE's audit request (2026-10-24)

### Description

No attacker is needed (architect):

1. NaN audio reaches the `levels_sw` tap; level-bridge prints `NaN`
   (`server.rs:226`), and `json.loads` accepts it.
2. The smoothed power in `thermal_monitor.py:116` becomes NaN and stays
   NaN for good.
3. `compute_reduction` returns NaN, and `_enforce_tick` sends `"nan"` to
   `set_mult` every 0.5 s, with no audit log.
4. PW turns each send into an indeterminate Mult in [-10, 10], up to
   +20 dB (F-352).

The stream outlives the NaN source, overrides a gate close within
0.5 s, overwrites MUTE, and logs nothing. Only amps off or stopping the
web UI end it. It turns a transient NaN event (F-349) into a permanent,
silent random-gain stream (AE).

It is reachable only after a web UI profile activation, which configures
the limiter (`speaker_routes.py:954, 978`), so interim rule 10(a) blocks
it today.

### Acceptance criteria

(a)-(e) are the architect's; AE agrees, with refinements.

1. (a) Every caller rejects non-finite values before `set_mult`
   (F-352 AC2, AC3).
2. (b) The monitor ignores non-finite rms readings. (AE) Smoothed state
   is re-initialised only after an operator acknowledgement and a
   sustained run of finite readings, never automatically mid-stream.
3. (c) The limiter fails safe. (AE) On non-finite input,
   `compute_reduction` does not just return the maximum reduction: a
   non-finite level is an F-349 event, so it signals GM to close the
   gate, alarms, and resets the convolvers. The limiter itself goes to
   the O-31 "THERMAL PROTECTION LOST" behaviour: hold the last finite
   factor, refuse raises, alarm, then a -6 dB ramp after 60 s. Never
   NaN, never a raise.
4. (d) level-bridge emits finite values or `null`, never `NaN`.
5. (e) A NaN-injection test. (AE) Plus an end-to-end variant: NaN
   injected at the level-bridge input (Rust) gives no non-finite
   `set_mult`, a latched fault, and a gate-close request.
6. (f) (AE) Config loading checks that every physics and gain field
   (`pe_max_watts`, impedance, ADA8200 Vrms, `base_mult` /
   `pw_gain_mult`) is finite and in range, and rejects the profile
   otherwise (`yaml.safe_load` accepts `.nan` and `.inf`).
7. (g) (AE, verification before the fix PR) Is the `levels_sw` tap
   before or after the gain? If before, the limiter can write random
   gains while the gate is Closed, so outputs are live while the UI
   shows CLOSED. Critical either way; it sets the test matrix.
8. (AE) The structural fix is US-159's sole writer plus a reduce-only
   limiter; these ACs still apply inside it.
