## F-357: A skipped test-and-build job lets a PR show CI green, so main has had no real T1 since 2026-04-20

**Severity:** medium (quality-engineer, re-rated after D-067, 2026-10-24: past docs-only skips are now legitimate; a code, Nix, CI or config PR going green on a skip would be high impact but is low likelihood, with no evidence it has happened). Back to high, or critical if code shipped untested, if (a) the paths filter (`ci.yml:69-81`, F-330) classifies any non-docs path as docs-only (candidates: `.claude/settings.json` hooks, config files, `flake.lock`), or (b) any PR since 2026-04-20 that touched code, Nix, CI or config merged with `test-and-build` skipped. worker-2 can check both from the F-335 diagnosis
**Status:** open — found in worker-2's F-335 diagnosis; worker-2 states in the F-335 PR which check is required. Not in F-335's scope
**Found in:** `.github/workflows/ci.yml` (`test-and-build` skipped on docs-only changes, `ci-gate`), branch protection on main
**Affects:** Rule 13 (CI green), O-22, every docs-only merge since 2026-04-20
**Related:** F-330 (paths filter allowlist; skip treated as pass at ci.yml:192), F-329 (no durable CI evidence), F-335, F-333; O-22, D-067
**Found by:** quality-engineer, from worker-2's F-335 diagnosis (2026-10-24)

### Description

Every CI run reported green since 2026-04-20 was docs-only, with
`test-and-build` SKIPPED. So main has had no real T1 run since then, and
F-335 could stay hidden. One of two things lets this happen: either a
skipped required job satisfies the branch-protection check (O-22 broken
at the CI level), or the job is not a required check at all.

F-330 is about which paths trigger the tests. This defect is about what
counts as green: even with a correct filter, a skip must not pass.

Rescoped 2026-10-24 (D-067, owner: "documentation-only PRs are
exempt"): a skip is acceptable for docs-only PRs. The defect now
covers PRs that touch code, Nix, CI or config files: for them T1-T3
must actually run and pass at the head (security, QE). What counts
as docs-only is pending the owner (D-067 questions 1-3).

### Acceptance criteria

1. The required check(s) on main are recorded (worker-2, in the F-335
   PR).
2. A non-docs-only PR head whose `test-and-build` is skipped does not
   show the required check as passed (O-22, D-067).
3. Test: a PR touching code, Nix, CI or config files shows the
   required check as failed or pending, not passed, until T1-T3 have
   actually run on its head. A docs-only PR (D-067 definition) may
   pass with the skip.
4. Separate from F-335 and F-330, each fixed in its own PR.
5. (QE) Once the owner answers D-067 questions 1-3, the CI
   classification of docs-only matches D-067's definition, and a test
   PR touching a borderline path proves it. F-330 owns the filter;
   F-357 owns what counts as green.
6. (AD M2; static read, QE to rate) `ci-gate` fails open when the
   `changes` job fails: `test-and-build` needs `changes` (ci.yml:124)
   and is then skipped, while `ci-gate` needs only `nixos-eval` and
   `test-and-build` (ci.yml:171-200) and accepts the skip. `ci-gate`
   must fail when `changes` does not succeed; a test proves it.
