## F-366: Pi 5 RT kernel config fails on NVMe TCP TLS

**Severity:** not rated; blocked the US-163 deploy step (not the bootstrap)
**Status:** resolved in US-163: committed `798f2dc7` on story/US-163 (parent `fb7d557e`), built in CM-MAC-BUILD-2 and deployed to `.89`
**Found in:** `nix/nixos/kernel-rt.nix:150` (forces TLS=n), `:320` (Pi 5 `keepNvme = true` skips the whole nvmeStrip)
**Affects:** `mugge-pi5-deploy` RT kernel build
**Related:** US-163, D-069
**Found by:** worker-1 (US-163 deploy build, 2026-10-24)

### Description

`NVME_*_TCP_TLS` selects `TLS`, which `kernel-rt.nix:150` forces to
`n`. On the Pi 4 the NVMe options are stripped, but the Pi 5 sets
`keepNvme = true`, which skipped the whole strip, so the kernel
config check failed.

### Fix (architect and audio-engineer approved)

Always strip the NVMe fabrics options (FC, TCP, TARGET); strip the
local NVMe options only when `keepNvme` is false. A board-guard
assert checks the evaluated config values on all boards. Rejected:
dropping `keepNvme`; `TLS=m`.

The commit touches only `nix/checks/board-guard.nix` and
`nix/nixos/kernel-rt.nix`; its diff sha256 equals the approved
`7d3630b4...b463` (CM verified). board-guard passes and its mutation
tests fail as intended; the Pi 4 kernel drv is unchanged.
