## F-372: S-001 path check uses a string prefix and an unsanitised profile name

**Severity:** medium (security-specialist); amps-on/gig blocker class, next to F-037
**Status:** open. AMPS-ON PRECONDITION LIST (Pi 5), item 11. No owner escalation (home lab rule)
**Found in:** `src/web-ui/app/filter_routes.py:545` (prefix check); `:244` (`output_dir`) and `:226` (`session_dir`) join `req.profile` unsanitised
**Affects:** filter deploy endpoint (unauthenticated on the LAN, F-037); `/etc/pi4audio/coeffs`
**Related:** S-001, F-362, F-037, D-009, US-110
**Found by:** security-specialist (2026-10-25, US-163 review)

### Description

The S-001 fix checks
`os.path.abspath(req.output_dir).startswith(os.path.abspath(DEFAULT_OUTPUT_DIR))`.
That is a string prefix test, so a sibling directory such as
`<RC>/output-x` or `<RC>/output2` passes. `req.profile` also goes
unsanitised into `os.path.join` for `output_dir` (`:244`) and
`session_dir` (`:226`); this is partly limited because the profile
must load first.

Impact is integrity: an unauthenticated LAN client could deploy
`combined_*.wav` files from outside the output tree to
`/etc/pi4audio/coeffs`. D-009 verification still caps the gain.

The tests that would catch a regression here do not run (F-362).

### Acceptance criteria

1. The path check uses `os.path.realpath` plus
   `os.path.commonpath` (or `Path.is_relative_to`), so siblings and
   symlinks out of the tree are refused.
2. The profile name is checked against an allowlist pattern before
   any path is built from it.
3. Tests for sibling directories, `..`, symlinks and bad profile
   names exist and actually run in CI (depends on F-362).
