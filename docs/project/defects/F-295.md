## F-295: Mixxx audio clicks — JACK client threads not RT

**Severity:** low (audio-engineer ruling 2026-10-24; was reconstructed as medium). The Live-mode mic loss is tracked separately: F-323 / US-158 (and F-328).
**Status:** fixed (commit `991ff456`, 2026-04-19, PR status unknown) — Pi verification not recorded
**Found in:** `configs/pipewire/80-jack-no-autoconnect.conf`, `nix/nixos/audio/pipewire.nix`
**Affects:** DJ mode (Mixxx), Live mode mic input
**Found by:** unknown (no original record)

### Description

1. JACK client audio callback threads (Mixxx) ran at SCHED_OTHER and were
   preempted, causing clicks.
2. *(Split to F-328.)* `20-usbstreamer.conf` (ada8200-in capture adapter)
   was promoted to `driver=true` at runtime despite config.

### Fix

1. `rt.prio = 70` in `80-jack-no-autoconnect.conf` (below GM 80, PW 88).
2. `20-usbstreamer.conf` no longer deployed by NixOS.

### Open points

- **Live mode mic input is now not configured.** The code comment says
  "Live mode will re-enable this via GraphManager when mic input is
  needed". No implementation exists (AE). Tracked as F-323, fix story US-158.

### Audio-engineer retroactive review (2026-10-24)

- `rt.prio = 70` for JACK clients: LOW, approved. This is standard
  practice, and the priority order 88 > 80 > 70 is correct.
- Removing `ada8200-in`: no safety impact (UMIK-1 is a separate device).
  It does leave Live mode with no vocal-mic capture path, which is HIGH
  for readiness and filed as F-323. safety.md pre-flight check #8 needs
  updating (technical-writer).

### Possible interaction with F-291 (architect, 2026-10-24)

The `rt.prio = 70` change may be what pushed RT load over the 95% throttle
(F-291 / F-317). Tracked on F-317.
