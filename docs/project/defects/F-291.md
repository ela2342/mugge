### Description

PipeWire hit the default kernel RT throttle (`sched_rt_runtime_us` = 95%)
under sustained load, causing periodic scheduling delays and xruns. In
addition, hardening directives in the base PipeWire user unit
(`SystemCallFilter`, `SystemCallArchitectures`, `LockPersonality`,
`MemoryDenyWriteExecute`) each force `NoNewPrivileges`, which prevented
`CPUSchedulingPolicy=fifo` from taking effect.

### Fix

- `kernel.sched_rt_runtime_us = -1` (throttle disabled on PREEMPT_RT) and
  CPU governor `performance` — new module `nix/nixos/rt-tuning.nix`.
- PipeWire unit hardening directives cleared so FIFO/88 applies.
- Code comment states Security Specialist approved. **Not confirmed:** security-specialist has no record of this approval (2026-10-24). Do not treat it as approved.

### Security retroactive review (security-specialist, 2026-10-24)

- **Unit hardening relaxed: LOW, acceptable in substance.** PipeWire listens
  on a local socket only, and `ela` already has passwordless sudo, so seccomp on
  PipeWire adds little within the threat model. Caveat: the stated reason
  ("each directive forces NNP, so fifo fails") is inconsistent with
  `graph-manager.nix`, where GM gets FIFO/80 with NoNewPrivileges=true AND a
  SystemCallFilter. Requested (non-blocking): show which directive actually
  blocked RT and keep the others.
- **sched_rt_runtime_us=-1: MEDIUM (availability)** — filed as F-317.

### Audio-engineer retroactive review (2026-10-24)

**MEDIUM, accepted with conditions.**

- Correction: there was never a prior security approval; the code comment
  was self-attested.
- Audio-safety cost: if a FIFO thread runs away, SCHED_OTHER is starved,
  and the software panic MUTE path (web UI → GM RPC) and SSH go with it.
- Since F-295, Mixxx's engine is also FIFO/70. GM at 80 still preempts it.
- The physical amp switch stays the real panic control.

Conditions:
- (a) Evidence that throttling caused the xruns ("RT throttling
  activated" in the kernel log before the change). Also consider whether
  980000-990000 would have been enough.
- (b) A configured and tested watchdog before the next gig (F-325).
