## F-341: safety.md pre-flight `nc -q1` commands unverified on NixOS

**Severity:** medium (pre-flight checks #3 and #6 may not run as written; audio-engineer to rate)
**Status:** open — needs a CM OBSERVE check (pending owner, O-2)
**Found in:** `docs/operations/safety.md:246`, `:249` (pre-flight #3 signal-gen reachable, #6 signal-gen -20 dBFS cap): `echo '{"cmd":"status"}' | nc -q1 127.0.0.1 4001`. Also on `docs/safety-d063-gate` (new commands, AE approval note at `1616dd61`).
**Affects:** safety.md pre-flight checklist, interim operating rules
**Related:** O-2, F-298, US-159
**Found by:** technical-writer (2026-10-24); audio-engineer non-blocking follow-up on `docs/safety-d063-gate`

### Description

No netcat package is declared in `nix/`, and `-q` is a Debian netcat
option (OpenBSD and GNU netcat do not take it, or treat it differently).
If `nc` is absent or does not accept `-q1`, the pre-flight checks for the
signal generator fail or hang, and the -20 dBFS cap cannot be verified as
written.

### Acceptance criteria

1. A CM OBSERVE session records whether `nc` exists on the Pi image, which
   implementation it is, and whether `-q1` works.
2. If not: either add the right netcat to the NixOS image, or rewrite the
   commands with a tool that is present (e.g. a small client shipped with
   signal-gen), on main and on `docs/safety-d063-gate`.
3. Every safety.md command is run once on the Pi and its expected output
   recorded.
