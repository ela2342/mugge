## F-361: Link audit protects only ports named playback_AUX0..7

**Severity:** medium while latent (audio-engineer, architect); high if the USBStreamer comes up with a non-AUX port name or a non-pro-audio profile
**Status:** open. Fix after US-160, before US-159, and before any amps-on use (AMPS-ON PRECONDITION LIST (Pi 5), item 7)
**Found in:** `src/graph-manager/src/link_audit.rs:52` (port-name match); `src/graph-manager/src/routing.rs:316`, `:353` (unresolved ports)
**Affects:** US-159 B2 (non-GM link enforcement), every gate state; amps, HP/IEM ch 5-8
**Related:** F-318, US-159 (B2, G16), US-160, US-163 (AC12: anything other than pro-audio with AUX0..7 FAILS)
**Found by:** audio-engineer and architect (2026-10-25, US-163 review)

### Description

The link audit decides which links to protect by port name: only
ports named `playback_AUX0` to `playback_AUX7` on the USBStreamer
playback node count. If the device comes up under another profile or
with other port names, a link into the USBStreamer is not audited at
all. When the expected ports do not resolve, routing gives no visible
fault.

US-163 AC12 confirmed pro-audio with `playback_AUX0..7` on the Pi 5,
so the defect is latent there today.

### Acceptance criteria

1. The audit matches by node and direction (every input port of the
   USBStreamer playback node), not by port name.
2. Ports that do not resolve are a visible fault (`routing.rs:316`,
   `:353`), never silently skipped.
3. OpenGate is refused with reason code `output_ports_unresolved`
   while the output ports do not resolve.
4. If the ports vanish while the gate is Open: a reduce-only close,
   a read-back, and the gate stays Closed.
5. Done before any amps-on use of the Pi 5.
