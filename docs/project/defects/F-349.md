## F-349: Non-finite audio drives full-scale output; latches in the convolver while Closed and fires at gate open

**Severity:** critical (audio-engineer, 2026-10-24; likelihood low)
**Status:** open — raised by the architect, rated by AE; needs a worker (O-8). Fix as a US-159 AC or a sibling story (PM and architect to decide). Interim: status.md rule 12 (proposed, O-32). Owner notified of a new Critical (O-35).
**Found in:** design review (US-159 G8c R-i, AE N1); PW 1.6.2 source (architect, static): `audio-dsp-c.c:44-58, :185`, `fmt-ops-c.c`, `audioconvert/meson.build:10-25`, `plugin_builtin.c:1434`, `spa_json_format_float`
**Affects:** all 8 outputs, in every gate state, HP/IEM included; D-063 "gate Closed = silence"; the US-159 fade-in; pre-flight #10
**Related:** D-063, US-159 (G3, G4, G8b, G8c R-i N1, G11, T47), US-157, F-343, F-351, F-346 (AC10, AC15), F-298, F-315
**Found by:** architect, from audio-engineer's N1 (2026-10-24)

### Description

One non-finite sample (NaN or Inf, from an application stream such as a
Reaper plugin or a Mixxx LV2 effect, or produced inside the convolver)
latches in the FFT convolver history until the node is reset (AE). PW
1.6.2, statically read (architect):

1. Steady Closed is true silence: the `linear` builtin with `Add` == 0
   and `Mult` == 0.0f exactly calls `dsp_clear` (memset to zero), with no
   multiply. filter-graph is not built with fast-math.
2. The NaN stays in the history. At gate open the first non-zero ramp step
   releases it: an instantaneous step that bypasses the 2 s fade-in, on any
   channel. A NaN while Open does the same at once; intermittent bursts give
   full-scale switching, broadband at full scale (AE). This latched path
   is the realistic one (AE).
3. What NaN or Inf becomes at the sink is undefined: the aarch64
   F32-to-S32 converter (`conv_f32d_to_s32_c` in `fmt-ops-c.c`, C only) is
   compiled with `-Ofast` (`audioconvert/meson.build:10-25`), so the
   mapping is compiler-dependent and build-specific (architect). AE rates
   the worst case, +-full scale, until an aarch64 measurement exists; the
   measurement can lower the rating, not hold it back. x86 dev builds use
   the SSE2/AVX2 converters, so they say nothing about the Pi (QE).
4. PW's `clamp` builtin maps NaN to a rail (`clamp_run` uses SPA_CLAMPF),
   so it is not a sanitizer.
5. pw-dump prints NaN, subnormal values and -Inf as `0.000000`
   (`spa_json_format_float`), so a gain check that parses pw-dump text
   cannot see a non-finite or subnormal Mult (architect).

Static reading only; not reproduced.

Impact (AE): a full-scale step through 4x450 W is maximum sub excursion
and a full-scale transient in the IEMs and headphones (hearing-injury
risk). If any stage after the DAC is DC-coupled (ADA8200 and amp output
coupling unverified), it is sustained DC into the voice coils. Worse than
the reboot transient, and nothing visible detects it beforehand: the
meters after the gain read zero while Closed. Likelihood is low because it
needs a source of non-finite samples.

Through the Props path PW never stores a NaN Mult: text `nan` gives an
indeterminate value in [-10, 10] (F-352), and a native NaN Float pod
is clamped to -10.0 (architect, 2026-10-24). The NaN risk stays on the
signal path.

### Acceptance criteria

1. (AE, REQUIRED) A finite-check stage after the gain, as the last stage
   before the sink. Our own code or a new builtin, never PW `clamp`.
   Non-finite input becomes an exact 0, with a latched alarm, a gate close
   and a reset of that convolver.
2. (AE, REQUIRED) Every convolver's state is reset immediately before
   every gate open; open is refused unless the reset is confirmed on all
   8. Optionally, the pre-gain convolver output is checked finite over one
   quantum, failing closed. Next to US-159 G4 and G11.
3. (AE, OPTIONAL, defence in depth) A hard output gate (link cut), only
   once USBStreamer idle suspend is disabled and verified on the real
   stack (a stopped stream is the reboot transient). Close: Mult 0,
   confirm, cut. Open: restore with Mult 0, then the slewed ramp.
4. (AE, confirmed; architect) A static check that the last step of every
   close and every ramp-down writes the literal 0.0f Mult, never a
   computed value such as start*(1-k/N), which can be subnormal or -0.0,
   and that `Add` is exactly 0.0 (G13, pre-flight #10). This keeps the
   memset path.
5. (AE, architect) One rule for every non-finite check in the safety path:
   test the f32 bit pattern, `(bits & 0x7f800000) == 0x7f800000`, never
   isfinite or isnan, which `-ffast-math` or `-ffinite-math-only` can fold
   to "always finite". It covers (a) the AC1 sanitizer; (b) the US-159
   G8b check on coefficient WAVs, over the f32 sample data as stored
   (integer-PCM WAVs cannot hold non-finite values); (c) GM's G11 raw-float
   read-back; (d) the AC9 signal-gen check. It applies in Python or numpy
   too, so a port to Rust or C cannot regress. Each check's test injects
   NaN, +Inf, -Inf and a quiet-NaN payload variant. The sanitizer is also
   compiled without fast-math, and its test runs on aarch64 with the
   production build; an x86 run does not prove it. Worker check of the
   Nix PW build flags (AE).
6. (Architect) The NaN and Inf mapping is measured on aarch64 (T47). A
   disassembly of `conv_f32d_to_s32_c` in the built
   `libspa-audioconvert.so` (`fmaxnm`/`fminnm` against `fmax`/`fmin`) is a
   complementary static oracle and does not replace the run (QE).
7. (QE) Real-stack test US-159 T47, plan only until a worker exists (O-8)
   and disk allows. Case (5), a NaN Mult written while Closed, is a
   finding candidate for AE: NaN skips the `== 0.0f` clear path.
8. (AE) History reset: an impulse, then an all-zero tail after the reset.
9. (AE, confirmed) signal-gen checks its output with the same bit-pattern
   method; on a failure it mutes and alarms.
10. (Architect, AE) GM's confirmed close (US-159 G11 (f)) reads the 8
    Mult and Add values as raw f32 from the Props pod over its own PW
    connection, never from a text dump: Mult bits 0x00000000 or 0x80000000
    and Add exactly 0.0f, anything else is CloseFailed. Pre-flight #10
    reads the gains with pw-cli, not pw-dump (#45, F-343 AC21); its
    residual (pw-cli resolution 5e-7, smaller values read as 0) is accepted
    because the automated check covers it (AE). Other pw-dump readers in
    the gain path: F-351.
11. (QE) Because `-Ofast` makes the result build-specific, T47 evidence
    records the PipeWire store path and version, and T47 is re-run on any
    PipeWire version, patch or toolchain change (regression trigger for
    the US-157 / CI-trigger list).
